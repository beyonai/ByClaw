# D0.5.1 报错国际化审计

基线：`D0.5.1`（初始审计点 `313debad558b576266583df11721bcaa602a4c1d`，提交前同步到 `8dcf041327d00e8b352a4ffa85c7b8d33a566abb`）。本次检查面向会直接进入 ByClaw Web 页面、后端 HTTP 响应或超级助手聊天流的错误信息；日志、测试样例、协议错误码和第三方打包代码不作为界面文案处理。

| 区域 | 发现的英文报错入口 | 处理 |
| --- | --- | --- |
| Web 前端 | 登录、数字员工、模型详情、沙箱管理、Token 配额、卡片链接、文件预览、知识库转存结果和 WebSocket 连接等直接写死或透出的英文提示 | 改为现有中英文语言包键或补充对应键 |
| Web 请求层 | 后端或上游返回英文 `msg`，被错误弹窗和业务组件直接展示 | 新增 `localizeErrorMessage`，按当前语言保留同语言业务错误，对另一种语言的原始错误使用本地化兜底 |
| Java 后端 | 50 个直接失败提示、119 个 HTTP 状态原因、27 个领域错误，以及通用异常/鉴权异常 | 加入中英文资源键；同步补齐新提交的文件转存参数/路径错误；全局异常与 `ResponseUtil` 对未翻译的技术异常使用本地化兜底 |
| 超级助手 | `run.failed` SSE 曾向聊天页面透出内部英文异常；HTTP 鉴权和请求错误也会返回原始英文 | SSE 使用 Session locale，HTTP 使用 `Accept-Language`；内部错误仍保留在日志/事件中供排查 |

Java 后端的三个 `messages*.properties` 现各新增同一组 200 个 `i18n.*` 键及 7 个文件转存错误键；所有代码中引用的新键均能在三个文件中找到。前端新增的 WebSocket 等键同时写入 `zh-CN` 和 `en-US`。对已按当前语言写出的业务错误，展示层保留原文；对纯英文技术错误在中文界面、中文错误在英文界面使用通用提示。后端对“中文前缀：英文异常”也使用兜底，避免把连接异常直接返回给用户。

静态扫描还会找到英文日志、内部抛错、测试数据和 `byclaw-exe` 插件的机器接口响应。这些字符串不直接进入本次检查的 Web 用户界面；插件协议若要按语言返回错误，需要先为调用方约定 locale/Accept-Language 的传递规则，再逐个接口处理，不能只替换错误字符串。由第三方服务自由返回的混合语言文本也无法仅靠静态键扫描穷尽，新的兜底覆盖常见的纯英文及后端“中文前缀：英文异常”形式。

验证：Java 原有定向测试 89 个通过，同步最新分支后的文件转存与响应测试 12 个通过；Web 原有定向测试覆盖请求层、沙箱、WebSocket 和文件预览，新增转存/语言包/兜底测试 10 个通过；超级助手 HTTP/SSE 测试 28 个通过，服务层 TypeScript 类型检查通过。完整 Web 构建因该独立工作区沿用的依赖目录缺少 `D0.5.1` 的若干预览依赖而未完成。超级助手全量项目构建仍有既有的 `AskAgentDispatchDeps.waitIndex` 类型错误，与本次改动无关。
