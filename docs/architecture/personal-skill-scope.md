# 资源中心个人技能范围

资源中心“我的技能 → 个人”按当前登录用户查询，不以当前或默认数字员工为列表范围。

- 已登记技能：`listResourceUseAuth` 使用 `ownerType=personal`、`permission=CREATED_BY_ME`，操作权限来自技能自身。
- 未登记目录技能：`qryWorkspacePersonalSkillList` 使用 `personalWorkspace=true`；服务端查询当前用户存储空间的个人技能目录，以及本人创建且未注销的数字员工技能目录，按实际路径去重，排除已安装和已登记技能。此口径不包括仅被授权使用的他人员工。
- 目录没有独立创建人字段，历史目录按上述所属空间归集；无法把目录内文件的实际作者与工作空间创建人逐项等同。
- 个人目录的详情、导出、冲突检查、资源化和删除均传递 `personalWorkspace=true`。服务端忽略客户端用户编码、默认员工 ID，并重新验证路径属于当前用户允许的来源，拒绝其他员工目录和路径穿越。
- 个人目录资源化只创建/更新个人技能及资源文件，不自动安装到任何员工，不重建默认员工技能关系。上架企业继续使用独立的复制接口及技能权限校验。
- 右侧边栏保留员工范围，继续按当前员工查询技能、检查员工管理权限及处理安装/卸载。
- 主动安装资源时的明确安装目标与技能归属分开处理，不用于扩大个人技能列表或决定上架权限。

验证用例覆盖列表不携带默认员工、个人目录来源与路径校验、服务端忽略伪造身份、资源化不绑定员工、个人目录导出和上架请求。
