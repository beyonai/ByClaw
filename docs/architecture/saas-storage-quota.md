# SaaS 用户存储配额

## 数据事实源

用户配额、已用空间、写入预占、增值授权、增值包取消/降级、回收站任务和管理操作均持久化在 OpenGauss 的 `byai` schema 中。Redis 只用于扫描和回收任务的分布式锁，不承载最终额度状态。

`po_user_storage_quota` 是用户当前状态表，默认容量为 2 GiB。用户写入前通过条件更新增加 `reserved_bytes`，只有 `used_bytes + reserved_bytes + writeBytes <= total_quota_bytes` 时才允许继续写入；物理写入成功后以单条条件更新把预占原子转入 `used_bytes`，失败时才释放预占。这样连续写入会看到上一笔已经提交的使用量，不依赖扫描任务才能阻止超额。

文件或目录删除前由服务端读取可信文件大小，物理删除成功后再原子扣减 `used_bytes` 并重算状态；物理删除失败不扣账。定时扫描仍以存储真实大小校准覆盖写、沙箱直接写入或异常中断产生的偏差；扫描失败只记录错误，不覆盖最近一次有效使用量。

增值包定义保存在 `po_storage_package`，每次生效权益都以一条不可变容量快照写入 `po_user_storage_grant`。同一增值包可以重复授予，不同等级也可以同时生效；总增值额度等于全部 `ACTIVE` 权益快照之和。物理表 `po_user_storage_downgrade` 为兼容既有取消/降级数据继续沿用，业务语义已扩展为统一“增值变更记录”：通过 `request_type` 区分 `ADD_PACKAGE` 与 `CANCEL_PACKAGE`，并保存一个新增套餐或一组待取消的具体 `grant_ids`、名称快照、变更容量、前后额度、预计超额、发起来源、审核信息、宽限截止时间和关联回收记录。

增值包配置页的“生效用户数”只统计 `grant_status = ACTIVE` 的去重用户。仅当当前仍有生效权益时，服务端才禁止修改或删除该增值包；历史授权已经撤销或失效后，不再锁定定义。管理页与后端使用同一计数条件，避免出现“生效权益列表为空但配置仍不可操作”的状态分裂。

`po_storage_quota_setting` 保存管理员可调整的默认容量、告警阈值和回收站保留天数。管理员设置只影响新用户、后续扫描和新建回收站任务，不会自动缩减已有用户的当前基础配额。

## 网盘完整业务生命周期

### 1. 初始化与就绪

用户创建或首次登录时幂等补齐配额记录，并创建 `byclaw-{userCode}` 隔离桶/目录。状态从 `INIT` 进入 `READY`；物理初始化失败不会回滚账号，而是记录 `FAILED` 和错误原因，由补偿流程重试。LocalFile 模式下桶映射为文件系统子目录，生产可把根路径直接配置为 NFS 挂载点。

### 2. 日常使用与记账

网盘批量上传、会话附件和 UserFS 使用同一套“预留 → 落盘 → 提交/释放”账本。FileBrowser 会在写入首个文件前按整个批次原子预留容量，避免批量上传只成功一部分；物理写入成功后逐文件提交，异常时仅释放尚未结算的预留。

用户删除文件或目录时执行“删除前可信计量 → 存储删除 → 原子扣减用量”；删除后若用量降至阈值以下，状态随之恢复为 `NORMAL`。定时真实扫描是最终对账补偿层，不替代同步记账。

### 3. 阈值告警与配额触顶

使用量从阈值以下跨入告警区间时发送一次站内信；回落后清除告警闩锁，下次重新跨入时可再次通知。达到 100% 后状态为 `EXCEEDED`：前端禁用上传并对批次总大小做体验层预检，后端数据库条件更新以 HTTP `507 Insufficient Storage` 作为不可绕过的最终强制点。读取、下载和删除仍被保留，用户可选择扩容或释放空间。

### 4. 增值授权与取消生命周期

配额触顶后存在三类扩容入口：

- **用户申请新增（本次已交付）**：用户从当前启用的增值包中选择一项并提交申请。相同套餐可以重复申请叠加，不同等级也可以组合生效。`REQUESTED` 状态只表示等待管理员审核，不会冻结现有上传能力；管理员通过后新增一条独立权益快照，驳回或用户撤回则不改变额度。
- **管理员直接授予（本次已交付）**：管理员选择通用增值包，服务端直接写入容量快照，标记首次授权或聚合后续授权，重算总额度和状态，并向目标用户发送国际化站内信。已有权益用户可继续续授或升级，不受“首个增值包”限制。
- **用户购买（商业化目标）**：当前尚未接入订单、支付、订阅和自动续费。后续应由交易/订阅中心发布幂等权益事件，再复用现有授权与配额重算能力，不能由支付回调直接修改配额表。

新增申请的闭环为“用户选择已启用套餐 → 提交申请 → 管理员确认或驳回 → 新权益快照/保持原状 → 配额重算 → 国际化站内信”。申请、审核通过、驳回和撤回均写入统一增值记录；同一用户同一时刻只允许一个未结束的增值变更请求，避免并发审核造成目标额度预览失真。

当前版本的退出动作统一定义为“取消增值包”，不是“退款”：

1. 用户在当前生效权益中选择一项或多项具体授权；同等级叠加和不同等级组合都能精确选择。系统按选中 `grant_ids` 预览取消后的目标配额和预计超额量，提交后状态进入 `REQUESTED`。只有待审核的取消申请会暂停网盘与会话附件新增写入；用户可在管理员处理前撤回，状态进入 `CANCELLED` 并即时恢复写入。
2. 管理员可确认或驳回用户申请。驳回进入 `REJECTED`，选中权益全部保持生效并发送站内信；确认后仅撤销本次选中的授权并重算总额度，未选中的叠加权益保持不变。管理员也可从“生效增值包”直接发起取消，复用同一影响预览和降级状态机。
3. 取消后若用量不超过目标额度，状态进入 `COMPLETED`，用户继续正常使用；若超过目标额度，状态进入 `GRACE`，在清理宽限期内只读、可下载、可删除但禁止新增写入。
4. 宽限期内用户可删除部分文件直至不再超额，系统自动完成降级；也可选择立即把在线资源转入临时回收站。宽限期届满仍超额时，由定时任务执行同样的归档流程，该取消变更记录进入 `ARCHIVED`。
5. 新增与取消的申请、撤回、驳回、确认，以及取消进入宽限期和归档的结果，均通过国际化站内信触达用户；前端在操作后重新读取配额并刷新 FileBrowser，避免显示旧权益或旧文件树。

用户端和管理员端均以“增值记录”承载 `ADD_PACKAGE`、`CANCEL_PACKAGE` 两类历史。列表使用服务端分页并复用 FE 公共分页组件，支持变更类型、状态和用户编码查询，默认按 `requested_time DESC, downgrade_id DESC` 稳定排序。旧 `/cancellations/*` 路径保留兼容，新增统一 `/changes/*` 路径作为主接口。

当前没有支付，所以取消流程不包含“确认外部退款完成”。未来接入支付后，退款只能作为“取消增值包”的一个交易侧子流程：交易中心完成退款并发布结果，权益中心再执行取消；支付渠道不得直接修改配额或文件状态。

### 5. 清空与临时回收站生命周期

临时回收站有两个已交付入口：一是管理员“初始化还原”；二是取消增值包后进入 `GRACE` 的用户选择“立即转入临时回收站”，或宽限期届满后由任务自动归档。在线 `by` 前缀先归档到不挂载的 `${userBucket}-recycle` 存储，再清空在线空间并重算账本。归档失败时保留在线数据，避免出现“账本已重置但文件丢失”。

每条回收任务有独立创建时间和 `retention_until`，状态流转如下：

1. `ARCHIVING`：复制在线资源并计算归档容量。
2. `AVAILABLE`：归档可管理；管理员可浏览目录并预览支持的文件，也可发起恢复。
3. `RESTORING` → `RESTORED`：容量校验通过后恢复到在线路径，归档退出可操作状态。
4. `PURGING` → `PURGED`：超过该记录自己的保留期后彻底删除归档资源。
5. 任一步骤失败时记录错误和审计，可基于 `request_id` 幂等重试。

管理员预览复用现有 FileBrowser 展示和文件预览能力，但数据源限定在目标回收记录的归档根路径：只允许平台管理员访问，只接受 `AVAILABLE` 记录，校验记录归属和规范化路径，拒绝 `..`、反斜杠、NUL 及越界对象。页面不提供上传、重命名、移动或删除动作；普通用户访问预览接口返回 403。

管理员回收记录列表使用服务端分页并复用 FE 公共分页组件，默认按 `started_time DESC, recycle_id DESC` 稳定排序；支持状态、创建时间段和过期时间段组合查询。用户配额主列表只在存在有效 `AVAILABLE` 记录时显示角标及数量，“仅看有效回收”使用相同有效性条件；恢复完成后列表、角标和筛选结果同步刷新。

### 6. 对账、异常与闭环

扫描任务周期性统计用户真实存储大小，并使用乐观版本更新账本。它用于纠正覆盖写、存储外部写入、进程中断等同步链路无法完全避免的偏差。扫描失败仅更新错误字段；后续成功扫描可恢复一致状态。授权、撤销、回收、恢复、到期清理和管理操作均写审计记录，形成可追踪闭环。

### 7. 账户注销与租户退订（后续治理）

账户注销或企业租户退订不能等同于立即删除目录。建议状态流为“冻结新增写入 → 提供数据导出宽限期 → 按租户/合规策略归档 → 到期物理清理 → 保留不可变销毁审计”；存在法律保全时暂停到期清理。该生命周期尚未在当前版本交付，后续需补齐导出 SLA、保留期策略、legal hold 和销毁证明。

| 生命周期 | 当前已交付 | 后续规划 |
| --- | --- | --- |
| 初始化 | 基础配额、隔离目录、失败状态 | 自动补偿看板与租户级策略 |
| 日常使用 | 网盘/会话统一预留、上传、删除扣账、扫描对账 | 冷热分层与存储成本计量 |
| 触顶处理 | 507 强制拦截、用户申请新增、管理员审核/直接授予、取消影响预览、取消审核/撤回、超额清理宽限、清空回收 | 用户自助购买、订单支付、自动续费 |
| 增值权益 | 同/异等级叠加、具体权益多选取消、统一增值记录与分页/状态查询、管理员确认/驳回/直接取消、全环节站内信、生效用户计数与修改/删除保护 | SKU、订阅、支付接入后的退款子流程、欠费宽限、按比例计费 |
| 临时回收 | 独立保留期、用户立即归档、宽限到期自动归档、管理员只读预览、恢复、到期清理、审计 | 更细粒度用户自助恢复策略、合规保留规则 |

## 接口

- 用户：`GET /byaiService/storage/quota`、`/storage/grants`、`/storage/packages`、`POST /storage/changes/add/apply`、`/changes/cancel/preview`、`/changes/cancel/apply`、`/changes/withdraw`、`/changes/page`、`/changes/archive`
- 管理员：`/byaiService/storage/admin/packages`、`/settings`、`/users/page`、`/grants/page`、`/users/grant`、`/users/revoke`、`/grants/cancel/preview`、`/grants/cancel`、`/changes/page`、`/changes/approve`、`/changes/reject`、`/users/reset`、`/users/recycles`、`/users/restore`
- 回收只读预览：`POST /byaiService/storage/admin/users/recycles/preview/list`、`GET /byaiService/storage/admin/users/recycles/preview/download`
- 文件：`/byaiService/fileBrowser/upload`、`/delete` 及会话附件上传接口

配额拒绝写入返回 HTTP `507 Insufficient Storage`；普通用户访问管理员配额或回收预览接口返回 HTTP `403 Forbidden`，响应体继续使用统一的 `ResponseUtil` 结构。

基础能力迁移版本为 `V0.2.1`；统一增值记录、多权益取消和叠加申请字段增量位于 `deploy/migrations/versions/V0.2.2/`。两版结构均已合并到 `deploy/middleware/initdb/02_ddl.sql`。
