用户个人私有 Env 配置运行期注入方案

在 ByClaw 后端维护用户私有配置，由 baiying-enhance 在 skill 触发工具、工具真实执行、或 exec 环境解析阶段按需读取并注入，避免密钥进入 prompt、skill 文档、模型上下文和持久化消息。

方案结论

存储在 BE 新增用户私有 env 配置域模型，按当前登录用户隔离，密文落库。
运行期读取 baiying-enhance 只在工具调用或 exec 环境解析时读取，短 TTL 缓存。
不进 Prompt 不通过 skill 文本、AGENTS.md、before_prompt_build 暴露密钥。
最小改造 优先增强 baiying_call executor，不修改 OpenClaw 核心生命周期。
推荐路径： BE 只提供个人参数配置的管理接口，负责密文落库并刷新 Redis 明文运行期缓存；baiying-enhance 在 baiying_call executor 和 resolve_exec_env hook 中直接读取 Redis key byai:user:private_params:{userCode}，把参数仅用于运行期内存替换或 exec 子进程环境。
不建议： 不要在 before_tool_call hook 里把 secret 写进 params。OpenClaw 的 before-tool hook 设计允许改写 params，这些 params 可能被日志、回放、消息持久化或模型可见链路间接接触，不适合作为密钥承载通道。

接口契约

接口只服务配置管理。运行期读取不走 BE API，baiying-enhance 直接读 Redis。

接口 用途 返回敏感值
GET /byaiService/userPrivateParam/list 按当前登录用户分页查询个人参数列表；支持 keyword 按参数名/说明模糊查询、status 启停过滤、updateTimeSort 更新时间排序，并刷新 Redis 缓存。 否，只返回 hasValue、valueLast4、description、status、updateTime。

POST /byaiService/userPrivateParam/delete 软删除当前用户参数，并刷新 Redis。 否。
POST /byaiService/userPrivateParam/enable 启用或停用当前用户参数，并刷新 Redis。 否。

运行期读取边界： baiying-enhance 不调用 BE 接口获取明文。它只通过现有 Redis JSON store 读取 SHARE_BFM_USER_{userId} 解析 userCode，再读取 byai:user:private_params:{userCode}。

运行期注入设计

baiying_call executor 注入

  1. BaiyingExecutor.execute() 读取 auth context，拿到 session、userId、headers。
  2. 优先通过 authContext.userId 读取 Redis SHARE_BFM_USER_{userId}，解析 userCode；失败时再使用 USER_CODE、BAIYING_USER_CODE。
  3. 通过现有 getSharedRedisJsonStore() 读取 byai:user:private_params:{userCode}，只接收字符串参数值。
  4. 把 Redis 中的 params 传给运行期占位符替换函数。
  5. 只替换资源配置里的显式占位符，例如 ${privateEnv.API_TOKEN}，不把整包 env 透传给工具。
  6. 调用结束后不写回 capability、payload、消息、日志或 session 文件；日志和错误详情按 private param value 脱敏。

推荐占位符

位置 例子 说明
HTTP header Authorization: Bearer ${privateEnv.API_TOKEN} 最常见，替换后直接发请求。
URL https://api.example.com/${privateEnv.TENANT_ID}/query 仅允许替换完整 segment 或 query value，避免构造任意 host。
MCP header x-api-key: ${privateEnv.MCP_KEY} 在 executeMcp() 发 tools/call 前替换。
exec env API_TOKEN 通过 resolve_exec_env 返回给 exec 工具，不写入 tool params。
关于 skill 生命周期： OpenClaw 当前没有独立 skill 调用 hook。skill 是模型可读的指令和文件，不能承载私有 env。若 skill 内脚本需要 env，应在脚本执行的 exec 生命周期使用 resolve_exec_env 注入；若 skill 触发 baiying_call，则在 baiying_call executor 内注入。

  Exec->>Exec: resolveCapability + extractBackendParameters
  Exec->>Reader: loadPrivateParamsRuntime(authContext)
  Reader->>Redis: GET SHARE_BFM_USER_{userId}
  Redis-->>Reader: userCode
  Reader->>Redis: GET byai:user:private_params:{userCode}
  Redis-->>Reader: {version, params}
  Reader-->>Exec: Record<string,string>
  Exec->>Exec: 显式占位符替换，仅内存态
  Exec->>Target: 发起真实工具或 MCP 请求
  Target-->>Exec: result
  Exec-->>Tool: ExecutorResponse
  Tool-->>OC: tool result

安全边界

风险 控制措施
密钥进入 prompt 或 skill 文档 禁止在 before_prompt_build、AGENTS.md、SKILL.md 中渲染 env。只输出 key 名或缺失提示。
密钥进入 tool params 被持久化 不在 before_tool_call 返回的 params 中写 secret。executor 内部替换后直接发请求。
越权管理他人参数 BE 使用 CurrentUserHolder 绑定当前用户，忽略请求体 userId。Redis key 使用 userCode，由 BE 写入和 baiying-enhance 解析。
日志泄漏 baiying-enhance 的 request debug 日志需要对 header 和 payload 做 secret redaction，至少对命中占位符的 key 做脱敏。
Redis 缓存残留旧值 BE 在保存、删除、启停、列表查询后刷新 Redis；无有效参数时删除 byai:user:private_params:{userCode}。
占位符滥用 只解析 ${privateEnv.KEY}，不解析任意表达式，不支持嵌套和默认命令执行。

落地计划

  1. BE 数据层： 新增表、entity、mapper、DTO、VO。完成 key 校验、密文保存、后四位展示字段。
  2. BE 应用层： 新增 list/save/delete/enable 管理接口。列表接口只返回脱敏值；保存、删除、启停、列表查询后刷新 Redis。
  3. BE 启动同步： 新增 InitUserPrivateParamRedisRunner，服务启动后异步全量重建用户个人参数运行期数据，避免 DB 与 Redis 不一致。
  4. baiying-enhance Redis 读取： 新增 personal params 读取模块，复用 createRedisJsonStore/getSharedRedisJsonStore，读取 SHARE_BFM_USER_{userId} 和 byai:user:private_params:{userCode}。
  5. baiying_call 注入： 在 BaiyingExecutor.execute() resolveCapability 后、分派 executeTool/executeMcp 前解析 env，并传给各 resource executor。
  6. 模板替换： 在 tool/mcp/agent 资源配置中支持 ${privateEnv.KEY}，只替换白名单字段。
  7. 可选 hook： 注册 resolve_exec_env，仅当 event.toolName === "exec" 时返回当前用户 Redis params。暂不使用 before_tool_call 传 secret。
  8. 前端页面： 增加个人参数配置管理页，支持新增、编辑、启停、删除、脱敏展示、变量名校验、分页、参数名/说明模糊查询、状态过滤和更新时间排序。
