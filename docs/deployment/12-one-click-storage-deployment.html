ByClaw 一键部署存储模式切换手册

通过 .env 驱动存储方案，在纯 Docker 场景下一键切换 legacy MinIO、 NFS 全文件型、NFS + MinIO 混合三种部署模式。deploy.sh 只区分 init 和 update 两个部署阶段。

推荐新部署在 .env 设置 BYCLAW_DEPLOY_STORAGE=nfs： OpenClaw 容器 /by 和 BE 文件 CRUD 都使用 /mnt/byclaw-file， MinIO 不再作为运行态文件系统。

1. 三种存储模式

模式 .env 设置 OpenClaw /by BE 上传/CRUD MinIO
nfs BYCLAW_DEPLOY_STORAGE=nfs NFS NFS 默认跳过
nfs-hybrid BYCLAW_DEPLOY_STORAGE=nfs-hybrid NFS MinIO 启动
minio BYCLAW_DEPLOY_STORAGE=minio legacy MinIO/rclone MinIO 启动

4. .env 参数说明

变量取值说明
BYCLAW_DEPLOY_STORAGE nfs / nfs-hybrid / minio 唯一的存储 profile 开关，写入 .env 后由 deploy.sh init/update 读取。
BYCLAW_DEPLOY_INIT_NFS true / false 仅 sh deploy.sh init 阶段生效。为 true 时通过 SSH 初始化 NFS Server 和客户端挂载。
BYCLAW_DEPLOY_START_MINIO true / false nfs 模式默认跳过 MinIO；设为 true 可同时启动。
BYCLAW_SANDBOX_FILE_VOLUME_ROOT /mnt/byclaw-file NFS 在 Docker 宿主机、openSandbox、BE 容器中的统一路径。
FILE_STORAGE_LOCAL_PATH /mnt/byclaw-file FILE_STORAGE_TYPE=file 时，BE CRUD 写入的文件根。
FILE_STORAGE_TYPE file / minio 通常由 profile 自动设置。nfs 使用 file，minio 和 nfs-hybrid 使用 minio。
不再推荐通过命令参数切换存储方案。标准入口是：首次部署执行 sh deploy.sh init， 仅初始化 NFS 执行 sh deploy.sh nfs-init， 增量更新执行 sh deploy.sh update，所有细节都写在 .env。

5. NFS 前置准备

5.1 A 服务器导出目录

sudo apt-get update
sudo apt-get install -y nfs-kernel-server
sudo mkdir -p /exports/byclaw
sudo chown -R root:root /exports/byclaw
sudo chmod -R 755 /exports/byclaw

echo '/exports/byclaw  *(rw,sync,no_subtree_check,no_root_squash)' | sudo tee -a /etc/exports
sudo exportfs -rav
sudo systemctl enable --now nfs-server

5.2 Docker 宿主机挂载

sudo apt-get update
sudo apt-get install -y nfs-common
sudo mkdir -p /mnt/byclaw-file
sudo mount -t nfs4 A_SERVER:/exports/byclaw /mnt/byclaw-file \
  -o rw,hard,noatime,nconnect=4,_netdev

findmnt /mnt/byclaw-file
touch /mnt/byclaw-file/.probe-$(hostname)

6. SSH 初始化 NFS

如果部署机可以 SSH 到 NFS Server 和 Docker/openSandbox 宿主机，可以让脚本自动完成 NFS Server 导出、 客户端挂载、/etc/fstab 固化和读写探针。 

BYCLAW_DEPLOY_INIT_NFS=true
BYCLAW_NFS_SERVER_HOST=10.0.0.10
BYCLAW_NFS_SERVER_PORT=22
BYCLAW_NFS_SERVER_USER=root
BYCLAW_NFS_SERVER_PASSWORD=
BYCLAW_NFS_EXPORT_PATH=/exports/byclaw
BYCLAW_NFS_EXPORT_CLIENTS=*

BYCLAW_NFS_CLIENT_HOSTS=10.0.0.20,10.0.0.21
BYCLAW_NFS_CLIENT_PORT=22
BYCLAW_NFS_CLIENT_USER=root
BYCLAW_NFS_CLIENT_PASSWORD=
BYCLAW_NFS_MOUNT_OPTIONS=rw,hard,noatime,nconnect=4,_netdev
密码为空时脚本使用 SSH key 登录；配置密码时，Shell 版本需要本机安装 sshpass。 远端用户建议使用 root，或配置免密 sudo。 
# 推荐：写入 .env 后在首次部署阶段自动初始化
BYCLAW_DEPLOY_STORAGE=nfs
BYCLAW_DEPLOY_INIT_NFS=true

sh deploy.sh nfs-init

# 也可以只执行 NFS 初始化脚本，适合先单独验证挂载
cd deploy
sh init-nfs.sh

# PowerShell 首次部署
.\deploy.ps1 init

7. 详细操作指南

7.1 首次部署

git clone https://github.com/beyonai/ByClaw.git
cd ByClaw
cp .env.example .env

# 修改 .env 中数据库、Redis、端口、镜像、账号、存储方案等基础配置
vim .env

sh deploy.sh init

7.2 增量更新

# 代码或镜像版本更新后，复用 .env，重新生成配置并重建容器
sh deploy.sh update

7.3 .env 中切换模式

# NFS 全文件型模式：OpenClaw /by 和 BE 文件 CRUD 都走 /mnt/byclaw-file
BYCLAW_DEPLOY_STORAGE=nfs
BYCLAW_DEPLOY_START_MINIO=false

# legacy MinIO 模式：保持旧 MinIO/rclone 运行态方案
BYCLAW_DEPLOY_STORAGE=minio

# 混合模式：OpenClaw /by 走 NFS，上传/下载 API 继续走 MinIO
BYCLAW_DEPLOY_STORAGE=nfs-hybrid

7.4 NFS 模式仍启动 MinIO

# .env
BYCLAW_DEPLOY_STORAGE=nfs
BYCLAW_DEPLOY_START_MINIO=true

sh deploy.sh update

7.5 Windows PowerShell

cp .env.example .env
# 修改 .env 后执行：
.\deploy.ps1 init

# 增量更新：
.\deploy.ps1 update

9. 用户空间隔离策略

MinIO 模式下，新增或注册用户会初始化用户 bucket。NFS/file 模式下，同一条用户创建链路会创建 /mnt/byclaw-file/byclaw-${USER_CODE}/by，保持“一用户一隔离根”。 

# userCode=user001
/mnt/byclaw-file/byclaw-user001/by

# OpenClaw 容器内
/by
历史用户不会在 BE 启动时批量创建目录。迁移旧数据时，需要按用户创建目录并同步 MinIO 数据。

10. 排障

现象原因处理
BE 创建用户失败或无法创建目录 BE 容器未挂载 /mnt/byclaw-file，或 NFS 权限不足 检查 BE compose volume 和 touch /mnt/byclaw-file/.probe
OpenClaw /by 仍是 rclone .env 未设置 BYCLAW_DEPLOY_STORAGE=nfs，或 openSandbox TOML 未重生成 确认 .env 后执行 sh deploy.sh update
NFS 模式仍启动了 MinIO 设置了 MIDDLEWARE_MODULES 或 BYCLAW_DEPLOY_START_MINIO=true 清空变量后重启，或接受 MinIO 同时运行
文件列表看不到 OpenClaw 产物 FILE_STORAGE_TYPE 仍是 minio 全文件型模式设置 BYCLAW_DEPLOY_STORAGE=nfs，并迁移历史对象
