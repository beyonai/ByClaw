02 · Background

需求背景与 SaaS 化必要性

网盘存储从“内部资源”演进为 SaaS 产品能力后，必须同时解决资源公平、成本边界、商业转化和数据生命周期治理。只有页面展示用量、没有统一账本和服务端控制，无法形成真正可售卖的增值服务。

租户公平与隔离

防止单一用户持续占满共享 NFS，保障不同租户之间的可用性与资源公平，降低“邻居噪声”风险。

成本可测与可控

将物理存储成本映射为用户额度、使用量和预留量，形成容量规划、成本归集和毛利核算的数据基础。

增值服务可销售

把增量空间从人工运维动作抽象为标准增值包，为后续 SKU、订单、订阅、支付与续费接入保留稳定权益模型。

生命周期可治理

超额后不直接删除用户数据，通过临时回收站、差异化到期时间、恢复与审计降低误操作和合规风险。

4.3 配额账本与并发一致性

po_user_storage_quota 是用户当前配额事实源，基础额度、增值额度、已用量、预留量和状态集中维护。读取“剩余空间”时必须扣除正在进行但尚未落盘结算的预留量：

剩余额度
=
总额度 − 已用量
−
预留量

写入前使用数据库条件更新增加 reserved_bytes，条件为 used + reserved + writeBytes ≤ total。成功写入后将对应预留原子转入已用量；异常时释放尚未结算部分。并发请求无法通过“同时读取到相同剩余额度”绕过限制。

删除采用反向事务语义：先在受信任存储侧递归测量文件/目录实际大小并去重重叠选择，物理删除成功后再通过条件更新原子扣减 used_bytes；Provider 删除失败必须抛错且不改账。定时扫描仍保留为外部 NFS 变更和历史偏差的最终校准，而不是正常删除的延迟记账手段。

4.4 两条上传链路的统一控制

层次网盘文件上传会话附件上传共同约束

4.5 增值包与管理员运营台

  • 套餐定义存入 po_storage_package，授权时将容量作为不可变快照写入 po_user_storage_grant，避免以后改套餐定义反向改变历史权益。
  • “授予首个增值包”改为通用“授予增值包”；首次达到基础上限保留提示标记。用户可以从启用套餐中申请新增，相同套餐重复申请和不同等级组合都会形成独立 ACTIVE 权益并累加容量。
  • 用户取消时按具体 grant_id 选择一项或多项权益；同等级叠加与不同等级组合均可精确多选，预览按选中容量计算目标配额，审批通过后只撤销所选权益。
  • “增值包管理”包含配置、生效增值包和增值记录三个页签：配置页支持新增、查询、修改、删除；生效页只展示 grant_status = ACTIVE 的用户权益；记录页统一展示 ADD/CANCEL 申请和管理员直接操作。
  • 配置页的“生效用户数”与生效页使用完全相同的 ACTIVE 条件。仅当该计数大于 0 时，前端禁用且后端拒绝修改/删除；历史授权撤销或失效后恢复可操作，避免状态语义分裂。
  • 弹窗移除固定内容高度和固定纵向滚动，列宽压缩到常用视口可容纳范围；内容少时自然收缩，内容多或窄屏时才由表格/弹窗按需滚动。
  • 用户编码、状态、套餐等级、回收站创建时间和过期时间均支持组合查询；使用量、状态和两个时间字段支持服务端排序。
  • 主列表、生效权益、回收记录和统一增值记录分页均复用 FE 既有组件；增值记录支持变更类型、状态、用户编码查询，默认按申请时间和记录 ID 倒序。

4.6 超额临时回收站与只读预览

用户确认清空后，当前管理流程由管理员执行初始化还原，将在线 by 目录归档到不挂载的回收路径。每个用户/任务独立记录 started_time 和 retention_until，因此创建时间与到期时间不会被错误地套用同一个全局值。保留期内可只读预览或恢复，逾期由任务彻底清理，所有动作落操作审计并以 request_id 保证幂等。

  • 管理员在“临时回收站”中点击预览，直接复用现有 FileBrowserPanel 的目录导航、文件类型识别和 Markdown/文本等预览能力，不允许上传、删除或改名。
  • 后端先验证管理员权限、回收记录归属及 AVAILABLE 状态，再把所有相对路径约束在该任务的归档根路径内；拒绝 ..、反斜线和 NUL 等路径逃逸输入。
  • 管理布局不存在普通用户页面的全局预览驱动，因此组件自动使用局部预览弹窗；该兼容修复保证管理端真正展示文件内容，而不是只打开列表。
  • 回收记录由服务端分页，默认按创建时间与记录 ID 倒序稳定排列；状态、创建时间段和过期时间段均由后端过滤，弹窗复用 FE 公共分页组件。
  • 主列表仅在存在有效 AVAILABLE 记录时显示“临时回收站”角标及数量；“仅看有效回收”复用同一有效性条件，恢复完成后角标和筛选结果同步刷新。

4.7 LocalFile 与纯 NFS 适配

部署映射 本次环境设置 FILE_STORAGE_TYPE=file 并使用 LocalFile 路径验证。纯 NFS 环境只需把该根路径配置为 NFS 挂载目录；用户“桶”映射为隔离子目录，配额账本、回收和恢复逻辑保持不变，不依赖对象存储 API。

4.8 站内信、国际化与权限边界

  • 用户申请新增/取消、主动撤回，以及管理员确认/驳回、取消进入宽限或归档时均创建目标用户站内信。通知携带稳定业务类型和资源 ID；中文/英文由前端本地化映射，避免持久化语言耦合。
  • 补齐普通用户通知分页路由，并强制以当前登录用户覆盖查询目标 ID，防止构造参数读取其他用户通知。
  • 配额管理接口使用管理员授权；普通用户调用返回 403。上传限制由后端执行，禁用按钮不能被视为权限控制。
  • SM4 登录兼容改为轻量 Bouncy Castle API，解决 JDK 21 运行时签名 Provider 限制，不降低密码传输和认证要求。

05 · Complete Business Lifecycle

网盘、配额、增值权益与资源完整生命周期

网盘并非只有“达到上限后清空”一条路径。完整模型从用户开通、日常使用和计量开始，在告警/触顶处形成扩容、主动释放和临时回收三条分支，最终还要覆盖权益续期/到期、恢复/彻底清理以及异常对账。下图把各条生命周期放在同一业务视图中。

当前能力与目标能力边界 当前版本已经交付用户申请新增并叠加、管理员确认/驳回、管理员直接授予、用户多选具体权益取消/撤回、管理员确认/驳回/直接取消、统一增值记录、超额清理宽限、用户立即归档、宽限到期自动归档，以及管理员恢复/只读预览。当前尚未接入订单和支付，因此现阶段不存在“退款审核”；退款只可作为未来取消增值包流程中的交易子流程。

5.1 从开通到日常使用：所有分支共同的主干

开通与初始化生命周期

用户建立 → 存储桶/目录初始化 → 基础配额建立 → 首次扫描 → READY

  • 登录成功后以幂等方式确保用户存储目录和基础配额存在。
  • 已有用户由回填任务补齐账本；初始化失败保持可重试，不发放虚假可用额度。
  • 扫描把历史物理文件用量校准进账本，防止“新账本、旧文件”造成少计。

日常使用与删除生命周期

选择文件 → 原子预留 → NFS 写入 → 提交用量 → 下载/预览 → 删除 → 扣减用量

  • 网盘与会话附件共用同一配额账本，写入失败释放预留。
  • 文件/目录删除前递归测量可信物理大小、去重重叠路径，删除成功后才原子扣量。
  • 删除失败不扣账；周期扫描用于修复外部 NFS 操作或历史数据形成的偏差。

状态与告警生命周期

NORMAL → WARNING → EXCEEDED → 扩容或释放 → NORMAL

  • 告警阈值按策略计算，状态和使用量由服务端统一重算。
  • 达到上限后保留读取、预览、下载和删除能力，禁止新增写入。
  • 额度增加或数据释放后即时重算；满足条件即恢复两条上传链路。

5.2 配额触顶后的三条完整业务分支

三条分支解决的是不同业务诉求：用户申请新增解决自助扩容并为商业转化预留入口，管理员直接授予解决运营处置，主动释放空间解决不付费用户的数据治理。三条链路最终都回到同一个配额账本和状态重算点。

5.2.1 分支 A：用户申请新增增值包

本次已交付并实测

适用于用户希望保留全部在线文件并主动扩容的场景。当前版本由用户选择现有启用套餐并提交申请，管理员确认或驳回；相同套餐可重复叠加，不同等级也可组合生效。订单支付是后续商业化接入项。

权益后续生命周期：ACTIVE → 续授/升级 → 用户申请取消或管理员直接取消 → 配额重算 → COMPLETED / GRACE → ARCHIVED。当前取消只改变对应权益，不涉及资金处理。未来接入支付后，可在交易侧完成退款，再以幂等事件触发同一取消状态机；若额度回落后实际用量仍超限，用户进入清理宽限，只读、可下载、可删除，但不会直接丢失文件。

5.2.2 分支 B：管理员直接授予增值包

本次已交付并实测

适用于客服补偿、试用运营、线下成交或紧急恢复业务。动作统一为“授予增值包”，首次触顶只作为提示，不限制已有权益用户再次授权。

管理员可在“生效增值包”中预览取消影响并直接取消某一授权，系统复用用户申请取消的同一降级状态机。取消后仍有足够容量则立即完成；否则进入清理宽限，由用户删除、立即归档或等待到期归档。

5.2.3 分支 C：用户主动释放空间

局部删除、用户归档与管理端回收已交付

适用于用户不购买增值包、希望通过整理数据恢复可写额度的场景。根据释放范围分为“局部删除”和“整盘清空进入临时回收站”两条子链路。

  • 并发安全：容量检查和预留在数据库条件更新中原子完成。
  • 故障安全：写入失败释放未结算预留；批量不足时首文件前拒绝。
  • 权限安全：管理接口受 RBAC 保护；通知查询绑定当前用户；回收预览限定 AVAILABLE 任务和归档根路径。

上线结论 功能安全边界和业务完整性达到灰度标准，但不建议绕过仓库回归基线和目标制品验证直接全量。三项准入条件全部完成后，可从“有条件 GO”转为“GO”。

9.2 支付接入后的付费与取消链路建议

取消是主流程，退款是条件子流程 当前版本取消增值包不涉及资金。未来支付接入后，用户仍提交“取消增值包”；取消编排服务先计算配额影响，再根据订单、退款窗口和使用政策决定是否调用交易中心。退款成功（或无需退款）后发布幂等取消事件，权益中心撤销权益，配额服务重算额度。支付渠道永远不能直接修改配额表或文件状态。
  1. 用户收到 80%/100% 配额提醒，点击进入套餐比较页。
  2. 选择存储 SKU，创建订单并完成支付；服务端验证签名、金额和订单状态。
  3. 支付成功事件以订单号作为幂等键发放存储权益，配额即时恢复。
  4. 用户发起“取消增值包”，系统展示目标额度与预计超额；若权益关联已支付订单，再由交易中心判断可退金额并执行退款，管理员只处理取消确认/驳回，不手工录入“外部退款完成”。
  5. 退款成功或无需退款后，幂等取消事件撤销对应权益快照；若用量超过降级后额度，复用本次已交付的清理宽限与临时回收治理，不直接丢数据。
  6. 订阅到期前提醒续费；欠费同样通过权益状态和降级状态机处理，保留读取/删除与数据恢复边界。
