ByClaw OpenSandbox K3s + Longhorn 一键部署手册

目标是把 OpenSandbox 从 Docker 单机 runtime 升级到 K3s 集群 runtime，并用 Longhorn RWX PVC 承载 /by 工作区。部署入口保持一条命令：scripts/deploy-k3s.sh <env> init 或直接在集群节点执行 deploy/k3s/deploy.sh init。

支持 指定 K3s server/agent 节点 支持 节点池分配 支持 Longhorn 一键安装 注意 生产 Secret 写入 envs/<name>/env.k3s，不要提交。

1. 交付文件

文件作用
scripts/deploy-k3s.sh远程部署包装器，上传当前 git HEAD 和 envs/<name>/env.k3s，再在远端执行 K3s 部署。
deploy/k3s/env.k3s.example部署参数模板，包含 server/agent、节点池、Longhorn、镜像、namespace、密钥占位符。
deploy/k3s/install-k3s.sh通过 SSH 安装 HA K3s：首个 server 执行 --cluster-init，其他 server/agent 加入，并统一打节点池标签。
deploy/k3s/install-longhorn.sh安装 Longhorn，设置默认数据路径、RWX、默认副本数。
deploy/k3s/render-manifests.sh根据 env.k3s 渲染 K8s YAML 到 deploy/k3s/generated/。
deploy/k3s/deploy.sh本地/远端统一入口：init、cluster-init、storage-init、render、update、stop。

2. 节点拓扑

K3s 控制面与工作节点分开配置。server 节点组成 embedded etcd HA；agent 节点用于承载沙箱和重负载任务。节点池通过 byclaw.io/node-pool 标签驱动调度。

3. env.k3s 配置

本地部署复制 deploy/k3s/env.k3s.example；远程部署推荐放到 envs/204/env.k3s，由 scripts/deploy-k3s.sh 同步到服务器。

cp deploy/k3s/env.k3s.example deploy/k3s/env.k3s
vi deploy/k3s/env.k3s

最小节点配置示例

4. 一键部署流程

cluster-init
仅安装 K3s server/agent，并打节点池标签。
storage-init
仅安装 Longhorn 并创建工作区 PVC。
init
完整路径：K3s（可选）→ Longhorn → 渲染 manifest → apply → 等待 rollout。

远程一键部署

前提：envs/<env>/.env 配好远端 HOST、HOST_USER、DEPLOY_DIR；envs/<env>/env.k3s 配 K3s 集群参数。

# 首次完整部署
sh scripts/deploy-k3s.sh 204 init

# 更新镜像、配置或 manifest
sh scripts/deploy-k3s.sh 204 update

# 只停止 workload，保留 namespace/PVC/Longhorn 数据
sh scripts/deploy-k3s.sh 204 stop

在 K3s server 本机部署

K3S_ENV_FILE=deploy/k3s/env.k3s sh deploy/k3s/deploy.sh init
K3S_ENV_FILE=deploy/k3s/env.k3s sh deploy/k3s/deploy.sh update
K3S_ENV_FILE=deploy/k3s/env.k3s sh deploy/k3s/deploy.sh render

注意 远程脚本使用 git archive HEAD 上传代码，新增脚本和手册需要先进入可审查的提交或明确同步方式，否则远端会拿不到。

5. Longhorn 分布式部署

install-k3s.sh 会在每台节点准备 /data/longhorn，并尝试安装 open-iscsi、nfs-common/nfs-utils 等 Longhorn RWX 依赖。install-longhorn.sh 使用官方 manifest 安装 Longhorn，并应用以下设置：

设置来源说明
default-data-pathLONGHORN_DATA_PATH默认 /data/longhorn，避免根盘被工作区数据打满。
allow-rwx-volume固定 true允许 byclaw-workspace 使用 RWX。
default-replica-countLONGHORN_REPLICA_COUNT三节点建议 3；容量紧张时可先用 2，但可用性下降。
# 仅初始化 Longhorn 和工作区 PVC
K3S_ENV_FILE=deploy/k3s/env.k3s sh deploy/k3s/deploy.sh storage-init

6. Manifest 生成机制

部署不再直接 apply 静态业务 YAML，而是先渲染到 deploy/k3s/generated/。这样 namespace、镜像、host、Secret、StorageClass、节点池都来自同一份 env.k3s。

生成目录内容
00-namespacesby-service、by-middleware、by-sandbox、monitoring
10-storageservice/sandbox 两个 namespace 下同名 RWX PVC
20-middlewareRedis、openGauss、Secret、PVC
30-sandboxOpenSandbox Server、RBAC、ConfigMap、BatchSandbox 模板、API Key Secret
40-serviceByClaw BE/FE，BE 注入 BYCLAW_SANDBOX_API_KEY 并挂载工作区 PVC
50-ingressByClaw 业务入口。沙箱 wildcard endpoint 默认交给 OpenSandbox 动态管理。

安全要求 deploy/k3s/generated/ 含 Secret stringData，已被 deploy/k3s/.gitignore 忽略，不要手动提交。

7. 验收命令

kubectl get nodes -L byclaw.io/node-pool,byclaw.io/k3s-role
kubectl get storageclass longhorn
kubectl -n longhorn-system get pods
kubectl -n by-sandbox get pvc
kubectl -n by-sandbox rollout status deploy/opensandbox-server
kubectl -n by-service rollout status deploy/byclaw-be

# 直连 OpenSandbox 创建 smoke sandbox
export BYCLAW_SANDBOX_BASE_URL=http://opensandbox-server.by-sandbox.svc.cluster.local:9005
export BYCLAW_SANDBOX_API_KEY=<api-key>
sh deploy/k3s/smoke/create-sandbox.sh

业务验收还需要从 ByClaw BE 发起一次真实 OpenClaw sandbox 创建，确认 /by 在 BE Pod 和 sandbox Pod 中能看到同一用户目录。

8. 回滚策略

场景动作
OpenSandbox K8s runtime 不稳定将 BE 的 BYCLAW_SANDBOX_BASE_URL 切回 Docker OpenSandbox 地址，执行 deploy.sh update 或旧部署脚本。
业务服务异常sh deploy/k3s/deploy.sh stop 缩容 K3s workload，PVC 和 Longhorn 数据保留。
Longhorn 数据迁移未完成不要删除旧 MinIO/NFS 数据源；先只切灰度用户或测试租户。

9. 常见问题

现象检查点
agent 加入失败确认 K3S_JOIN_URL 从 agent 可访问，token 一致，6443 未被防火墙拦截。
沙箱 Pod Pending检查 kubectl get nodes -L byclaw.io/node-pool，确认模板中的 OPENSANDBOX_NODE_POOL 有可调度节点。
Longhorn PVC Pending检查 Longhorn manager/driver/deployer Pod、节点磁盘路径 /data/longhorn、iSCSI/NFS 依赖。
BE 调 OpenSandbox 401确认 BYCLAW_SANDBOX_API_KEY 与 OPENSANDBOX_API_KEY 一致或符合服务端配置。
BE 和沙箱看到的文件不一致确认 BE Deployment 和 BatchSandbox 模板使用同一个 WORKSPACE_PVC_NAME，且 BE 挂载路径等于 FILE_STORAGE_LOCAL_PATH。
