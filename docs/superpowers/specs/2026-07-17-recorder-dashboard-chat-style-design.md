# Recorder Dashboard Chat 风格改版设计

## 目标

将 `/iframes/adapter-recorder` 从当前独立的深色青色工具界面，统一为与 Chat 页面一致的浅色工作区风格；在不改变 Recorder 状态机、接口和业务行为的前提下，让用户能在 sider 底部持续看到当前登录身份。

## 视觉与布局

- 页面画布使用 Chat 的浅灰背景和现有 Ant Design/beyond 设计变量。
- 主工作面使用白色背景、轻边框和克制阴影，避免深色大面积渐变和高亮边框。
- 主品牌强调色沿用 Chat 的蓝紫渐变（主按钮、当前步骤、焦点态）；成功、运行、错误继续使用语义色。
- 页面保持两列结构：左侧 sider 步骤导航，右侧当前操作区。
- sider 顶部显示工作台品牌和简短说明，中部显示步骤轨，底部固定用户身份条。
- 右侧操作区继续承载现有 `HealthStep`、`BindStep`、`CaptureStep`、`RankStep`、`PipelineStep`、`InitStep`、`VerifyStep`、错误和完成状态。
- 小屏下 sider 步骤轨切换为顶部横向轨道；用户身份条保持在导航区域末端并允许压缩为头像 + 名称。

## 用户信息

从现有 DVA `user.userInfo` 读取，不新增请求或接口。

- 紧凑态：头像、`userName`、下拉箭头。
- 展开态：`userName`、优先显示的组织名称（`usersOrganizations[0].orgName`）、`userCode`，必要时显示岗位名称。
- 头像优先使用 `avatar`，无头像时用用户名首字生成品牌色圆形占位。
- 未登录时保留当前 Auth/登录行为，不渲染伪造的用户信息。
- 用户条位于 sider 底部，使用 `position: sticky` 或 flex 末端布局，不遮挡步骤导航和操作内容。

## 组件边界

- `Workbench`：读取 `user.userInfo`，负责页面壳层和用户条数据映射；不改变 Recorder actions。
- 新增 `UserIdentityBar`：只负责用户身份展示和展开交互，接收已整理的用户数据。
- `index.module.less`：重做页面壳层、sider、工作区和 Ant Design 控件覆盖；保留现有工作状态类名和窄屏断点语义。
- 现有步骤组件只在需要适配颜色/间距时使用现有作用域样式，不做业务重构。

## 交互与可访问性

- 用户身份条作为可聚焦按钮，键盘可打开/关闭详情。
- 详情浮层从 sider 内部向主工作区方向展开，避免被视口边缘截断。
- 所有交互状态提供 `:focus-visible` 样式，颜色对比符合现有前端规范。
- `prefers-reduced-motion: reduce` 下关闭进入、悬停和展开动画。
- 用户名、组织和账号过长时使用省略号，并通过可访问名称保留完整文本。

## 性能与数据流

- 用户信息只从 Redux selector 读取，避免重复请求。
- 用户条拆成独立组件，避免整个工作台因展开状态变化而重渲染；展开状态在组件内部管理。
- 不引入新的 UI 库、图片资源或重量级依赖。
- 静态步骤和图标结构保持现有组件复用，避免增加首屏 bundle 体积。

## 测试与验收

- 为用户条添加组件测试：已登录显示用户名、组织和账号；无头像使用首字占位；未登录不显示敏感信息；展开/收起可通过键盘操作。
- 更新现有工作台样式测试，验证 Chat 风格根节点、sider 底部用户条和移动端类名存在。
- 运行 Recorder 目录 ESLint、Stylelint、Prettier 和相关 Jest 测试。
- 运行前端构建，确认所有 Recorder 步骤仍可编译。
- 手动验收桌面和窄屏：步骤导航完整、用户条不遮挡、状态/错误/完成态可读，当前用户信息与 Chat 页面一致。

## 非目标

- 不改变 Recorder 状态机、接口契约、请求参数、权限和保存行为。
- 不新增全局导航菜单入口。
- 不修改 Chat 页面本身或全局主题变量。
