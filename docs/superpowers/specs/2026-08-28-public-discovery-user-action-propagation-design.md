# Public Discovery User-Action Propagation Design

## Problem

`hot_discovery` returns a structured `requiresUserAction` object after its managed byCLI browser-recovery ladder is exhausted. The merge layer currently drops that object while preserving only `adapterStats` and free-form warnings. An agent reading the merged public-discovery snapshot therefore sees that browser adapters were skipped, but loses the authoritative machine-readable instruction to stop and report the blocked state. This contributed to an invalid fallback to direct HTTP clients and a generic headless browser.

## Scope

This change will:

- preserve a sanitized `requiresUserAction` from a valid hot-discovery result in the merged document;
- attach a fixed, machine-readable fallback policy that prohibits direct HTTP and generic-browser fallback;
- expose the same user-action object at the top level of `public-discover` output;
- retain successful SearXNG discovery candidates when hot-discovery requires user action;
- add regression tests for propagation, sanitization, and partial-channel success.

This change will not:

- add provenance receipts or executor authentication to `collect` or `report`;
- change the byCLI bridge recovery ladder;
- make `public-discover` fail when SearXNG succeeded;
- modify collection inventory or delivery semantics.

## Design

### Safe user-action normalization

The hot-discovery merge layer will accept `requiresUserAction` only from a structurally valid hot-discovery document. It will copy only these optional scalar fields:

- `kind`
- `source`
- `errorCode`
- `message`

String values will be bounded to prevent oversized or untrusted adapter output from flowing into the merged snapshot. Unknown keys and nested values will be discarded.

When a valid action remains after sanitization, the merge layer will add a fixed policy generated by repository code rather than copied from input:

```json
{
  "allowDirectHttp": false,
  "allowGenericBrowser": false,
  "nextAction": "stop-and-report"
}
```

This policy makes the permitted response machine-readable and prevents an upstream document from weakening the fallback rules.

### Merge behavior

`mergeDocuments` will include the normalized object as top-level `requiresUserAction`. It will also append an explicit warning that direct HTTP clients and generic browsers are prohibited fallbacks.

The action will not suppress SearXNG candidates. Existing totals, groups, adapter statistics, and channel diagnostics will remain unchanged.

Invalid hot-discovery documents will not contribute `requiresUserAction`, even if they contain an object with that name.

### Public-discover behavior

`runPublicDiscover` will continue writing the merged document to the merged snapshot. It will also expose `merged.requiresUserAction` as top-level `requiresUserAction` in its command result, so callers do not need to inspect warnings or parse the snapshot.

When no action exists, the property will be omitted rather than set to `null`, preserving a clear distinction between an actionable block and normal partial coverage.

## Error and Security Handling

- User-action fields are allowlisted and length-bounded.
- Unknown fields, arrays, objects, and non-finite numbers are discarded.
- The fallback policy is synthesized locally and cannot be overridden by hot-discovery input.
- A malformed hot-discovery document is isolated under the existing merge behavior and cannot inject a user action.
- SearXNG success remains usable even when hot-discovery is blocked.

## Tests

Tests will be added before production changes.

1. A merge test will prove that `requiresUserAction` is currently absent, then require sanitized propagation and the fixed fallback policy.
2. The merge test will include unknown and nested input fields and assert that they are removed.
3. A malformed hot-discovery document test will assert that its action is ignored.
4. A public-discovery test will simulate successful SearXNG plus blocked hot-discovery and assert that:
   - the command still succeeds;
   - the merged snapshot contains the action and fallback policy;
   - the top-level command result contains the same action;
   - SearXNG candidates remain available;
   - the explicit no-fallback warning is present.

Targeted hot-discovery and public-discovery tests will be run after each red-green cycle, followed by the full knowledge-collection test suite.
