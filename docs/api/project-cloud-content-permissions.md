# 项目云盘内容操作权限

项目云盘（`KG_CLOUD`）的上传、新建文件夹和上传前冲突检查沿用目录树、预览的项目访问权限。

文件和文件夹的重命名、删除仅允许条目创建人；项目创建人及 `adminvip` 可以操作全部条目。创建人按知识服务元数据 `userCode.value` 与当前账号匹配，不使用显示姓名，也不接受请求方传入的创建人字段。缺失创建人记录时，普通成员不能改名或删除。覆盖上传删除旧文件前同样校验归属。

目录接口返回 `canManageItem`，前端据此禁用无权操作条目的改名、删除入口。后端执行时重新校验，不能通过直接请求绕过。读取权限本身不变。

普通知识库继续要求资源管理权限。整库编辑、注销、授权、构建及独立的批量移动接口不因本次内容权限调整而放开。

## 文件改名

`POST /byaiService/datasetController/renameFile`

请求字段：`resourceId`、`filePath`（原文件完整路径）、`fileName`（新文件名）。不依赖目录返回的 `fileId`。服务端只构造同目录目标路径，禁止路径分隔符及点目录名称，默认不覆盖已有文件，复用知识服务的移动能力完成改名。

响应沿用 `KnowledgeItemsMoveResult` 的逐项结果及汇总；前端必须检查逐项失败或失败数量，失败时保留改名弹窗并展示错误。

已补充后端创建人、项目创建人、adminvip 权限矩阵、改名路径和前端操作回归用例；本次未执行测试和构建。
