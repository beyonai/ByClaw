# 项目云盘内容操作权限

项目云盘（`KG_CLOUD`）的读取、下载、搜索、文件构建、上传、新建文件夹和上传前冲突检查统一使用项目访问权限：项目创建人、成员及 `adminvip` 可访问。普通平台或组织管理员不自动获得云盘权限。

文件和文件夹的重命名、删除、移动、文件内容及元数据更新仅允许条目创建人；项目创建人及 `adminvip` 可以操作全部条目。创建人按知识服务元数据 `userCode.value` 与当前账号匹配，不使用显示姓名，也不接受请求方传入的创建人字段。缺失创建人记录时，普通成员不能改名或删除。单文件覆盖通过内容更新接口执行并校验归属，避免先删后建；QA 仍会在更新时注入操作者账号，创建人保留需由 QA 配合修正。新上传启用重名跳过保护，ZIP 不允许覆盖任何已有文件；需覆盖时使用显式单文件覆盖。ZIP 预检限制为最多 1000 个条目、100 MiB 解压数据。

目录接口返回 `canManageItem`，前端据此禁用无权操作条目的改名、删除、移动入口。后端执行时重新校验，不能通过直接请求绕过。`adminvip` 的读取和管理能力保持一致。

普通知识库继续要求资源管理权限。整库编辑、注销及授权不因本次内容权限调整而放开。实体发现按访问权限，实体补全因改写已有内容，按指定文件或目录下所有文件的归属校验。

## 文件构建

`POST /byaiService/datasetController/build` 对项目云盘复用读取权限：可访问云盘即允许构建其中任意文件，包括他人创建的文件，不校验条目创建人或 `canManageItem`。无法访问项目的用户仍被拒绝；普通知识库仍要求资源管理权限。构建结果查询继续使用读取权限。

## 文件改名

`POST /byaiService/datasetController/renameFile`

请求字段：`resourceId`、`filePath`（原文件完整路径）、`fileName`（新文件名）。不依赖目录返回的 `fileId`。服务端只构造同目录目标路径，禁止路径分隔符及点目录名称，默认不覆盖已有文件，复用知识服务的移动能力完成改名。

响应沿用 `KnowledgeItemsMoveResult` 的逐项结果及汇总；前端必须检查逐项失败或失败数量，失败时保留改名弹窗并展示错误。

已补充后端创建人、项目创建人、adminvip 权限矩阵、改名路径和前端操作回归用例；本次未执行测试和构建。

## 身份、查询及存储边界

创建账号只来自后端登录态，忽略客户端 `X-USER-CODE`。内部生成文档也补齐当前账号。创建字段 `userCode`、`createBy`、`createStaffName` 不允许通过元数据更新修改；QA 当前在改名、移动、内容更新时仍会注入操作者账号；本轮不修改 QA，创建人不可变及修改人另存尚需联调完成。

按编码查询必须解析并校验所有关联资源；同时提交资源 ID 与编码时，实际查询使用已鉴权资源的绑定编码。底层路径只从固定资源根节点解析资源 ID，不匹配任意子目录中的同名数字。

## 待 QA 同事配合的边界

本轮未修改 `byclaw-qa`，也未新增依赖 QA 传递新请求头的执行凭证。

- 业务入口已统一权限，但 QA 的 RESOURCE FS 回调仍受底层通用资源管理权限限制，普通项目成员上传、构建、改名等操作仍可能在落盘时被拒绝。底层不能直接放开所有项目成员写权限，否则会绕过业务层条目归属校验。需双方约定可验证的内部执行授权，再联调同步调用和异步任务。
- QA 目前在更新、改名、移动时把请求账号注入 `userCode`。需 QA 保留原创建账号、另存修改人，才能保证文件归属不会随管理员操作改变。后端已拒绝外部修改创建人元数据，但无法替代 QA 内部的归属保护。

本次仅进行前后端代码、测试用例和文档更新，未执行编译、构建、测试或线上请求。业务入口修复不代表整条 QA 存储链路已验证通过。
