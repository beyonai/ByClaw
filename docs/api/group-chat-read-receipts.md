# 群消息已读人数

直接复用现有群详情返回的成员 `lastReadMessageId`，不新增已读查询接口，不增加 AOP 查询路由或 tenant Node 查询方法，也不新增逐用户逐消息已读表。

## 计算

对当前消息 `M`，取当前群内有效 USER 成员并排除发送者：

- 成员 `lastReadMessageId >= M.messageId`：已读，等于也算已读。
- 字段为空或小于 `M.messageId`：未读。

前端保留群详情成员已有的字段和状态，按现有消息 ID 数值顺序比较。大整数 ID 始终使用字符串，不转为 JavaScript Number。人数与人员名单均从同一个成员数组计算，不对每条消息发起查询。

这是连续已读语义；后面的消息全部已读也意味着之前的消息全部已读，不能表达独立的跳读空洞，也没有逐消息阅读时间。成员加入/退出按当前成员名单重新计算历史消息，不还原发送时的接收人集合。

## 实时更新

公共库和 tenant Node 原本都已支持 `last_read_message_id` 单调更新，本次不重做该能力。只在现有更新后向群成员发送字段变化：

```json
{
  "type": "GROUP_CHAT_EVENT",
  "event": "READ_RECEIPTS_UPDATED",
  "sessionId": "70",
  "userId": "27",
  "lastReadMessageId": "9007199254740993"
}
```

公共库实际更新并提交后广播。标准租户仍使用原 Node 更新命令，Java 再复用现有群详情读取成员和已提交字段值，按租户作用域广播；Node 本身没有本次改动。复用 MultiDeviceBroadcastService 的跨实例分发，不替代个人未读事件。

前端在原有群详情状态中合并成员字段，忽略迟到的小值，并防止进行中的旧详情请求覆盖新事件；重连、恢复可见和可见期间每 30 秒通过原有群详情接口校准。
