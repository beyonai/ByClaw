# HACU 工作组云盘写入限额

2026-11-02：源码实现，测试源码已补，未执行测试、构建或部署。容量由 HACU 发布，资源范围、用量及最终写入由 ByClaw 管理；没有改 ByClaw 前端。

## 生效范围

`DatasetApplicationService` 的普通上传、直接上传、文件更新、跨库复制共用 `WorkgroupStorageAdmission`。文件浏览器转存及既有工具通过这些入口写入时也受约束。先完成现有资源鉴权，再根据目标资源的 KG_CLOUD 类型、项目及同企业历史 hs_as 会话关联确定工作组企业，不信任前端当前企业或调用来源 Header。

普通个人知识库、普通项目云盘不读取新策略或 QA 用量，不获取新配额锁。工作组不存在 HACU 策略且没有 COMMERCIAL_MANAGED 标记时沿用原保存流程；明确 UNLIMITED 也沿用原流程。没有托管标记的独立 ByClaw 不因新增策略读取连接故障中断保存，该行为不受旧人数配额的 REJECT 配置影响；存在但损坏的策略不能当作无套餐。已商业托管的工作组缺少策略、版本未对齐或 Redis 故障返回 503，避免已订购企业在缓存丢失时被误放行。

限制跟随资源，而非页面来源：从 ByClaw 页面向同一个 HACU 套餐企业工作组写文件也受约束。下载、删除、同库移动不经过容量准入；不增加字节的覆盖允许继续，结果未知占用待核对期间除外。直接上传原有先删后导入流程移入准入回调，额度拒绝时不会先删除旧文件。

## 发布契约

共享前缀默认 `byclaw:shared:quota:v1:`，新增 HASH `storage:{enterpriseId}`，字段仍为 `revision`、`payloadHash`、`payload`。SHA-256 针对 canonical JSON 的 UTF-8 字节，不修改旧四项额度 HASH 或其不可变历史正文。

```json
{"schemaVersion":1,"source":"HACU","scope":"HACU_WORKGROUP","enterpriseId":"42","revision":"7","mode":"LIMITED","storageBytes":"100000000000"}
```

`storageBytes` 是 0..Long.MAX_VALUE 的十进制字符串；UNLIMITED 不携带容量。HACU 从同企业、同 revision 权益快照派生，含增配；废弃墓碑发布零容量。沿用 `tenant_quota_publication` 的持久任务、单键版本 Lua、重试及成功任务周期修复，已有套餐也会补发。ByClaw 验证来源、范围、摘要、字段和主额度 HASH revision 一致。两个 HASH 非原子发布；间隙只拒绝受限 HACU 写入，不使用错误版本额度。解除限制须发布更高版本 UNLIMITED。

## 用量与写入

- 用量范围复用 [企业云盘汇总](enterprise-storage.md)，同企业所有保留云盘共同占一个额度，不按操作者入组列表计数。
- 企业锁为 `BYAI:BUSINESS:LOCK:quota-write-guard:HACU_STORAGE:<enterpriseId>`，复用现有可续租 RedisLockRegistry。等待后重读策略，再查询全部云盘，锁持有至同步写入完成。没有数据库行锁。
- 新文件按实际上传字节计算；覆盖读取旧文件精确 size，只计算 `max(新大小 - 旧大小, 0)`。正增量要求 `用量保守上界 + 增量 <= storageBytes`，超限返回 409，文案支持中英文；统计不可用返回 503，不填零。
- 同事接口按库把字节换算为 KB 后四舍五入两位。每个非空库以 `floor(spaceSize * 1024 + 5.12)` 作为上界；空库为零。因此可能每库提前最多约 10 字节拒绝，页面仍展示原始 KB。这不是精确字节账本；若要求边界完全精确，QA 需要增加原始字节字段。
- ZIP 默认解压时读取中央目录并累加实际解压字节，兼容前置数据和不同文件名编码，取展开大小与原包大小的较大值。无法读取的 ZIP 拒绝；明确 `extractZip=false` 则按普通文件计费。重复文件或 ZIP 部分失败可能少于预估占用，本次检查采用保守上界。
- 同步成功后重新统计是下一次准入的依据。依赖知识服务响应完成时 `file_size` 已更新；QA 写接口之外的直连写入、自动生成文件和绕过 ByClaw 的路径不在本次门禁内，发布前须核对实际写入拓扑。Redis 锁不是数据库或 QA fencing，不承诺 Redis 故障转移、丢锁等故障下绝对不超额。

## 结果未知的占用与恢复

发送前在 `byclaw:shared:quota:v1:storage-write:{enterpriseId}` 写 STRING `随机令牌:本次净增字节`，只允许不存在时写入且不设 TTL。明确完成的逐项结果、整请求业务拒绝或确定未受理的 HTTP 4xx 才以令牌比较删除。超时、进程退出、5xx、响应损坏或失锁保留标记，后续受限写入返回 503“上一笔写入结果待核对”，不能靠自动过期重试绕过额度。下载、删除不受此标记影响。

运维恢复须按企业执行：暂停该企业的所有写入口，确认 QA 原请求已结束且没有在途写入，核对实际文件和 status 用量，再读取并记录标记。使用与应用相同的比较删除 Lua，只删除刚核对的令牌值；值变化时停止核对。之后恢复写入，每次仍重新统计真实用量。不要批量删标记、直接 DEL 或设置 TTL。该版本未提供自动对账或管理页面；应用日志可按 enterpriseId 定位异常。Redis 自身数据丢失需要先核对在途写入再恢复服务。

## 发布与验证

先上线知识服务 status 接口；更新 HACU 并等待现有套餐主投影及云盘投影同 revision。切换全部 ByClaw 写实例前暂停云盘写入、等待在途请求完成，避免旧实例绕过守卫。之后核对普通 ByClaw 保存、多个 HACU 工作组共享容量、覆盖/转存/ZIP、超时占用恢复，再恢复写入。接口未上线时受限 HACU 正增量写入会返回不可用，不冒充已支持。
