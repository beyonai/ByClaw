# 按模型类型设置默认模型

模型管理的“设为默认”支持所有已保存的模型类型，包括 LLM、EMBEDDING、RERANK、TTS、IMAGE_GENERATION 及字典扩展类型，不要求应用范围包含“对话模型”。只有启用且尚未默认的模型显示该按钮；所有类型的默认模型均根据接口 `isDefault` 字段显示“默认”标识。

列表卡片的模型类型展示中英文名称，不展示编码：中文为“大语言模型、重排模型、向量模型、语音模型、文生图”。字典扩展类型展示配置名称，未配置名称时显示“未知类型”，空类型显示 `-`。显示名称不改变接口提交的模型类型编码。

`POST /byaiService/new/model/setDefaultModel` 使用 `modelId` 指定目标。`modelType` 可省略，省略时按数据库中的模型类型处理；传入时必须与目标类型一致（忽略首尾空格和大小写）。目标模型必须存在且为启用状态。

默认状态沿用 `byai_tag_relation` 的 `tag_id=1` 关系。设置时清除同类型其他模型的默认关系（包含停用模型），为目标保留或新增一条默认关系；目标重复关系也会被清理。其他类型的默认模型不受影响，并刷新受影响模型的 Redis 缓存。此功能无需数据库迁移。

模型类型为 `null`、空字符串或纯空白时，统一视为独立的“空类型”分组，拥有自己的默认名额，与 LLM 互不影响。卡片类型显示为 `-`，不显示为 LLM；前端设置默认时提交空字符串。显式提交空字符串只能匹配空类型，省略参数（或传 null）仍使用目标模型的实际类型。空类型默认模型不合成“默认对话模型”能力，也不触发 LLM 的默认自动补齐或保护规则。按类型获取默认模型时，空参数只查询空类型；无参获取方法仍明确查询 LLM。

“默认对话模型”应用范围仍仅由 LLM 默认关系合成。原有 LLM、EMBEDDING、IMAGE_GENERATION 的缺省自动补齐和默认模型停用/删除保护策略保持不变；其他类型开放手动设置默认，不自动补齐。
