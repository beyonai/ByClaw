# 场景 2：产品理念

**触发**："产品理念是什么""你们产品有什么特点"

---

## Step 1：接单介绍

确认收到请求，一句话介绍：百应本体平台有 5 个核心产品理念，你想深入了解哪一条？我逐一给你演示。

## Step 2：展示理念菜单 + 预告

```
百应本体平台有 5 个核心产品理念，你想深入了解哪一条？

1. 业务本体语义层 — "金融行业""客户名称"，说的就是业务语言，系统自动翻译
2. 零 ETL 联邦查询 — 跨数据源一次查询，数据不动，自动路由
3. 异构数据融合 — 结构化字段精确过滤 + 非结构化文档全文检索，一次返回
4. 性能与准确率双保障 — DSL 规则引擎快车道 + text2SQL 兜底
5. 操作安全人工确认 — 查询自动，操作确认

选一个告诉我数字或关键词就行～
```

> 用户选了具体某一条后，进入对应条目预告演示内容，征求确认后再执行。禁止一次性全部演示。

## Step 3：用户确认后演示

用户选了某一条并确认后，按下方对应步骤执行。

### 1. 业务本体语义层

**预告**：`我会查询"金融行业的客户数据"，让你看到返回的字段名是"客户名称""所属行业"这种人话，而不是底层编码。准备好了吗？`

**演示**：baiying_call 查询 `查询金融行业的客户数据`（[01-data-query](../demos/01-data-query.md) 第 1 步）

### 2. 零 ETL 联邦查询

**预告**：`我会按行业统计商机签约金额，跨数据源一次查询完成，数据原地不动。准备好了吗？`

**演示**：baiying_call 查询 `按行业统计商机签约金额`（[02-data-statistics](../demos/02-data-statistics.md) 第 3 步）

### 3. 异构数据融合

**预告**：`我会创建会议纪要对象并做融合查询——结构化标签精确过滤 + 文档全文同时返回。准备好了吗？`

**演示**：执行 [06-unstructured-ontology](../demos/06-unstructured-ontology.md) 创建 meeting_note 并挂载，baiying_call 查询 `查询黄药师参与的所有会议纪要`

### 4. 性能与准确率双保障

**预告**：`我会创建跨表视图并查询，看跨表关联秒级返回——DSL 规则引擎优先命中跳过推理。准备好了吗？`

**演示**：执行 [05-structured-ontology](../demos/05-structured-ontology.md) 创建 product_order_view 并挂载，baiying_call 查询视图数据

### 5. 操作安全人工确认

**预告**：`我会走一遍数据操作流程，走到预览确认表单停下来——数据还没写入，等你确认。准备好了吗？`

**演示**：执行 [04-data-operations](../demos/04-data-operations.md) 第 4-5 步——生成周报→抽取→预览确认表单

## Step 4：详细解释

演示完用户选的那一条后，基于返回结果数据做详细解释：

- **业务本体语义层**：返回字段名是"客户名称""所属行业"而非 `col_id_xxx`，查询条件"金融行业"也由本体层解析为精确过滤——本体层做了术语 ID→name 映射与条件解析。
- **零 ETL 联邦查询**：CRM 数据和商机数据可能在不同数据源，但一次查询完成——数据原地不动，自动跨源路由。
- **异构数据融合**：结构化标签（participants）精确过滤 + 非结构化文档全文同时返回。
- **性能与准确率双保障**：跨表查询秒级返回——DSL 规则引擎命中简单查询跳过推理，复杂查询降级 text2SQL 兜底。
- **操作安全人工确认**：确认前数据不写入。"查询自动，操作确认"。
