# 错误定位与有界恢复

只报告实际 HTTP 状态、业务 code/msg、异常类型和脱敏后的必要详情；以下分类不是承诺后端一定返回同名错误码。

## 按证据定位

| 观察 | 核实与下一步 |
|---|---|
| AUTH_ERROR / BEYOND_TOKEN not set | 客户端初始化缺凭据，尚未调用 API；恢复平台注入后再执行，离线任务可继续 |
| SERVICE_DISCOVERY_FAILED | 检查 redis 包、模式、节点、schema 与健康实例；按环境参考检查，不输出连接串 |
| redis/requests 原生连接或超时异常 | 未必被 SDK 包装；区分连接阶段与请求已发送后的不确定结果 |
| HTTP 401/403 或业务权限错误 | 核对当前身份、目标租户和管理权限；Token 已设置不代表有效，不换用其他用户凭据 |
| HTTP 404 | 核对可信 base_url、路径前缀和部署接口版本；不能直接断言只缺 /byaiService |
| INVALID_RESPONSE | 响应不是预期 JSON，可能是代理/登录页/服务故障；不要原样公开响应体或把它视为无数据 |
| HTTP 5xx、写请求超时 | 保存已知阶段和目标；先回读再决定是否重试，不将异常等同于无写入 |
| code 非 0 | 保留真实 code/msg；不要把所有业务失败都翻译成 RESOURCE_NOT_FOUND |
| code=0，但 failed>0 或 items 有失败 | 部分成功，列出成功对象和失败项；不要重做成功部分 |
| 返回字段缺失或类型变化 | 视为契约待核实，不用默认计数零掩盖错误 |

只读查询可在明确瞬时故障时做少量有截止时间的重试；鉴权失败、参数错误和不兼容 schema 不靠重试修复。输出 msg 前清除 Token、Cookie、代理凭据和含签名的 URL；诊断中保留错误类别和可公开的业务信息。

## 从最后可证明状态继续

| 中断点 | 先回读 | 恢复原则 |
|---|---|---|
| 沙箱内打包 | ZIP 是否完整、文件集合和 SHA-256 | 可重新生成沙箱内临时包，不触发发布 |
| 上传 | 完整技能列表、skillPath、resourceId、绑定 | 可能已落盘并注册，不能直接再次上传或资源化 |
| 资源化 | 成功 items、技能资源和员工绑定 | 使用已返回 ID，只处理确认未完成项 |
| 单个技能安装 | 技能资源、目标员工和实际绑定 | 已绑定不重复写入；技能使用权限按授权流程处理，员工管理权限按平台对应机制处理 |
| 授权/撤销 | query_skill_members 的目标成员 | 对比所需差异后继续，不清空无关成员 |
| 卸载/删除 | 当前绑定、保留来源、目标目录 | 未确认状态不能重复破坏性操作 |

恢复记录仅保存操作类型、目标身份、必要 ID/路径、ZIP 哈希、已完成阶段和脱敏响应。认证凭据不得写入恢复日志。

## “发布了，但没生效”

按层验证：沙箱内包是否正确 → 平台资源是否更新 → 目标员工是否绑定 → 用户是否有权使用 → 目标运行时是否收到绑定元数据 → 能否取得资源 → 运行时是否已加载 → 实际请求是否触发该 Skill。

ByClaw 有版本与同步机制，不承诺固定 1–5 分钟轮询时间。取得真实部署刷新配置或日志证据后再解释延迟。不要为了验证自动重启容器、清理缓存或删除重装；这些动作可能影响其他会话，且不能修复权限或触发描述问题。

日志只截取目标请求附近的脱敏片段。不要要求用户提供完整环境变量、整个配置文件或生产凭据。

## 广播同步与卸载未完成

按 [生命周期契约](lifecycle.md) 分别核对平台绑定/解绑、元数据接收与运行时加载/卸载。注册或绑定已成功时，不因某个运行时未生效重复发布；解绑已成功时，不因缺少卸载证据先删平台文件。查询平台支持的同步状态或脱敏日志，区分未收到元数据、文件获取失败、加载失败和卸载失败；没有证据的阶段标为待确认。具体恢复使用平台已有机制，不编造广播消息、ACK 字段或重试命令。
