# 卸载流程

解除单个技能与指定数字员工的绑定，再由平台广播驱动运行时卸载。输入为真实技能资源 ID 和目标员工 ID；卸载不等于删除会话源码或平台资源记录。

## 1. 核实当前关系与影响

使用 `get_skill_used_by(skill_id)` 等已提供查询核对目标绑定与影响，确认用户要求移除的对象及管理权限。目标已无绑定时报告实际状态，不重复写入。平台查询受限时不能推断无人使用。

展示将移除的技能和目标员工，复用同一对象及范围的明确授权；影响扩大时补齐授权。

## 2. 执行单个资源解绑

调用 `POST /digitalEmployeeController/uninstallRelResources`，请求体为 `digitalEmployeeId` 与 `relIds: [skill_id]`；具体调用见 [API 契约](api-contracts.md)。只提交目标技能，不以全量更新员工关系或删除目录替代解绑。

当前后端可能保留其他有效来源的关联。写后回读实际关系；若仍保留，报告“绑定仍保留”及原因或待核实状态，不报告“已解绑”或自行升级为强制删除。接口返回员工详情，不能套用未定义的预检令牌或移除计数字段。

## 3. 解绑广播与运行时卸载

按 [生命周期契约](lifecycle.md)，实际解绑发生后平台自动广播解绑元数据，各用户运行时执行相应卸载。平台解绑和运行时卸载分别验证；证据不足时报告“已解绑，运行时卸载待确认”。

注销同样从核实并解除相关绑定开始；平台资源记录或包的最终注销接口需另行核实，不将已完成单个员工解绑描述为资源已全局注销。

## 4. 回读与交付

报告技能、目标员工、实际解除或保留的关系，以及运行时卸载证据。结果不明先按 [错误与恢复](error-codes.md) 回读，不先删平台文件或开发产物。

## 删除操作边界

`delete_workspace_skill(skill_path, employee_id)` 删除工作区目录，必须使用真实路径；它不代表平台资源解绑或注销。删除平台资源需核实独立接口、所有受影响关系和用户授权，不能为让卸载看似完成直接删除运行时目录。

实际部署契约不符时，通过平台接口说明、工具元数据或只读查询核实，不猜测替代写入方式。
