# 安装流程

将已发布的单个技能绑定到指定数字员工。输入为真实技能资源 ID 和目标员工 ID；授权、平台绑定与运行时加载分别核实。

## 1. 核实技能、员工与权限

查询技能资源及 `get_skill_used_by(skill_id)`，确认目标员工是否已有绑定。已有绑定时核实当前状态，不重复上传或创建资源。分别核实操作者对目标员工的管理权限，以及本次操作所需的技能使用权限。技能使用权限不足时按用户目标进入 [授权流程](authorization.md)；员工管理权限不足时按平台对应权限机制处理，授予技能使用权限不能替代员工管理权限。不自动提交额外申请或提高权限。

发布接口可能已经绑定了目标员工，应复用查询到的关系。其他员工的安装使用现有技能资源 ID，不重新发布同一内容。

## 2. 执行单个资源安装

调用 `POST /digitalEmployeeController/installRelResources`，请求体为 `digitalEmployeeId` 与 `relIds: [skill_id]`。客户端初始化和受控 Session 调用见 [API 契约](api-contracts.md)。只提交目标技能，不通过全量员工更新覆盖无关关系。

接口返回员工详情，之后回读目标技能的使用员工列表，确认绑定确实存在。请求超时或结果不明时先查询，不盲目重发。

## 3. 绑定广播与运行时自动加载

按 [生命周期契约](lifecycle.md)，平台绑定发生后自动广播元数据，各用户运行时自动发现、获取文件并加载到各自目录。管理 Agent 不逐个拷贝文件，不将会话开发目录当成运行时安装目录。

分别核实平台绑定与可取得的运行时接收、获取、加载和调用证据。仅查到绑定时报告“已绑定，运行时加载待确认”；不推断所有用户均已生效。

业务调用按 [凭据与连接发现](credentials-and-connections.md) 解析目标员工当前 Agent 的模型与用户连接。不能用开发者凭据补齐目标用户缺失的权限。

## 4. 交付结果

报告技能资源 ID、目标员工、绑定查询结果、运行时生效证据与未测项。移除技能转到 [卸载流程](uninstallation.md)，失败按 [错误与恢复](error-codes.md) 继续。

实际部署契约不符时，通过平台接口说明、工具元数据或只读查询核实，不猜测替代写入方式。
