# 业务开发所需的凭据、认证与连接发现

创建、编辑、测试、发布等阶段都可能需要身份、模型、业务 API 或连接器。按**实际业务动作**确定依赖，不按“创建/测试”流程名称推断无需凭据。纯文档编辑、静态检查和使用合成数据的测试可以没有业务连接；调用模型、获取真实资源定义、业务联调或访问仓库则需先完成相关依赖解析。

本指南将来源分为三类。三类是用途与来源的划分，不是互斥存储：平台连接器凭据可能最终以环境变量或受管文件提供给沙箱；资源元数据也可能引用运行时身份。

## 每次新建前的业务资源盘点

创建前的现有能力查重同时覆盖相似技能和相关 TOOL、TOOLKIT、MCP 等资源，不以“需求是否明确”为触发条件。先按 [创建流程](creation.md#盘点的顺序与完成证据) 检索并核实候选动作，再决定复用或开发；下面的需求引导是在此基础上的按需步骤。资源盘点不等于遍历全部凭据，模型与连接器信息仍按选定业务依赖定向解析。

## 需求不明确时的资源匹配

创建或优化阶段，用户想法或可用资源不明确时，可以主动发现并推荐以下三类资源。按当前业务方向定向读取可见能力、元数据和连接状态，不为推荐方案收集秘密值；不要求每个技能同时使用三类资源。

| 来源类别 | 匹配内容 | 向用户展示 |
|---|---|---|
| 当前运行时的身份与模型能力 | 当前 Agent 可提供的生成、分析等能力，以及是否具备所需调用/解析方式 | 能完成的任务、已核实的能力与适配缺项；默认复用当前 Agent，不要求用户选择密钥 |
| 平台外部资源元数据 | 与业务目标相关的 API、MCP、资源定义或已声明的共享只读索引 | 资源名称/标识、用途、输入输出、权限与当前可调用状态 |
| 连接器与个人连接配置 | 业务所需服务的连接状态、可用操作和认证补齐入口 | 连接器名称、必要的脱敏账号范围、已连接/需授权/待验证状态；不展示 token、认证文件内容或秘密引用的实际值 |

将匹配结果按业务方案呈现：**方案 → 预期产物 → 已匹配资源 → 缺失能力或权限 → 需要用户决定的事项**。给出有依据的推荐项及必要替代项，允许用户补充其他想法。资源可发现、有权限、元数据完整、可调用分别核实；未知状态保持待验证，不因 env 非空或连接状态正常就承诺业务调用成功。

优先通过已提供的只读工具和平台查询取得候选。缺少目录能力或认证时，说明实际覆盖范围，并可先提供不依赖该资源的方案；不要通过自动登录、申请授权或真实业务写入来完成资源推荐。用户选定后再按下面的动态解析契约落实到生成技能，不能把创建时的资源句柄或身份固定进产物。

## 生成技能必须继承的动态解析契约

本指南同时约束本管理技能的创建过程及生成的业务技能。获取对象以**当前执行该技能的 Agent、用户、租户、会话和资源绑定**为准，不以开发者或首次测试环境为准。

- **默认模型：** 用户没有指定独立模型时，复用当前执行 Agent 的有效模型能力。创建阶段按该约定解析并验证；发布绑定到其他数字员工后，运行时按同一语义解析新的执行 Agent 模型与认证，而不是读取开发时保存的配置。
- **解析时机：** 在实际调用前取得有效配置，调用期间保持模型、endpoint 与认证来源一致。不同 Agent/用户/会话不能共用未隔离的解析结果；凭据轮换或配置更新后按运行时支持的方式重新解析，不在模块初始化或首次安装时永久缓存。
- **解析位置：** 使用当前运行时提供的 Agent 模型调用能力、配置/凭据解析能力，或经核实绑定到当前 Agent 的注入配置。解析上下文的来源可随 harness 改变，业务技能的“使用当前执行 Agent”约定保持一致。
- **平台资源与连接器：** 生成技能保留业务资源定位、认证类型和解析方式；在当前执行用户及其授权范围下查询元数据和解析凭据。资源无法访问时报告权限缺失，不回退到开发者连接。
- **交付内容：** 写入的是动态获取步骤或脚本逻辑、必要的能力依赖和失败处理。默认不固化开发阶段的模型名、endpoint、Token、用户 ID、会话认证文件路径或运行时绝对目录。用户明确指定专用模型/服务时可以保存其非敏感逻辑配置，但秘密仍动态解析。

例如用户在员工 A 下创建一个摘要技能：创建时用 A 的有效模型验证；绑定到员工 B 后调用时用 B 的有效模型及凭据；B 调整模型或更新认证后按运行时刷新契约获取新配置。无需重新发布技能来替换 A 的模型地址或密钥。

**模型调用的执行顺序：**

1. 获取当前执行 Agent 的权威身份/资源上下文，确认选用模型与模型配置来源。
2. 运行时已经提供“用当前 Agent 模型执行”的能力时直接复用；脚本必须直连时才解析该 Agent 的模型协议、名称、endpoint 和认证配置。
3. 注入的 MODEL_* 仅在确认属于当前 Agent 有效配置时使用。共享用户沙箱的启动默认模型可能与当前员工不同，不能在缺失绑定证据时静默回退到它。
4. 按模型实际协议执行；不能仅有 URL/key 就假定所有模型都是同一 OpenAI-compatible 接口。环境变量已设置但协议/归属未确认时仍视为配置未解析完成。
5. 当前 harness 没有可用解析能力时，精确报告“缺少当前 Agent 模型上下文/适配能力”，不使用开发者配置兜底。创建时记录此兼容性缺口，不能声称已保证跨运行时运行。

这里定义的是业务技能的语义契约，不虚构已经存在的统一工具名、环境变量或 `resolve_current_agent_model()` API。创建者应把它落实为目标运行时实际支持的调用/解析方式；以下可选字段与解析线索不保证所有部署都已提供，需通过当前运行时暴露的能力核实。

## 一、运行时自身持有的凭据与身份

### 获取步骤

1. 从当前会话/Agent 上下文取得实际选用的模型、用户、员工和会话身份。优先使用运行时已提供的模型调用或身份解析能力，避免重新构建已有认证逻辑。
2. 需要在脚本中直接调用时，核实当前运行时支持的凭据解析接口、配置字段或当前进程的定向环境变量。只在进程内解析必要值，不输出整个配置。
3. 核对模型 endpoint、模型名称、认证方式与当前配置匹配，区分运行时启动默认模型和当前 Agent 实际选用的模型。验证资源所属用户、租户和会话，不能把默认员工 ID 当作当前员工。
4. 缺失时先使用当前运行时支持的刷新/配置读取方式；只阻止依赖该信息的操作，说明具体缺项。不从其他用户目录或其他会话复制凭据。

### ByClaw 运行时可选字段

下面是启动上下文或特定适配器实际使用的字段线索，不保证每个沙箱都暴露同名环境变量。

| 类别 | 字段线索 | 使用注意 |
|---|---|---|
| 模型地址 | `MODEL_BASE_URL`、`model_base_url` | 来自模型配置 URL；模型密钥只发送到该配置对应的可信目标 |
| 模型标识 | `MODEL_NAME`、`model_name`、`MODEL_ID`、`MODEL_ALIAS`、`MODEL_PROVIDER_NAME` | 部分部署将 modelCode 注入 MODEL_ID，它不一定是平台数值 modelId；不要混用 |
| 模型认证 | `MODEL_API_KEY`、`model_api_key` | 启动上下文取自模型 authToken；不是 ByClaw、GitHub 或运行时 Web 登录凭据 |
| 用户身份 | `USER_CODE`；部分适配器提供 `USER_ID`、`USER_NAME` | userCode 与 userId 不同；字段未注入时查会话身份接口，不能猜测 |
| bootstrap 用户信息 | `userId`、`userCode`、`assistantId`、`enterpriseId`、`comAcctId`、`sessionDatasetId`、`defaultDigEmployeeId`、`paramMap` | 来自运行时启动时提供的用户载荷，不是一组保证存在的 env；paramMap 可能包含敏感内容，只取需要的字段 |
| 平台身份与连接 | `BEYOND_TOKEN`、`BYAI_SERVICE_BASE_URL` | 分别用于平台认证和服务地址；SDK 对地址的读取规则见 API 参考 |
| 会话认证线索 | `BAIYING_SESSION`；部分适配器提供 `SSO_TOKEN`、`WHALE_AGENT_AUTHORIZATION` | BAIYING_SESSION 取自登录上下文，不自动等于工作会话 ID，也不能据此推导开发目录 |
| Agent 服务认证 | `BAIYING_AGENT_AUTH` | 可能已包含 Bearer 前缀；只在目标服务契约要求时使用 |
| harness 访问认证 | 如 `gateway_token`、`OPENCLAW_GATEWAY_TOKEN` 或当前 harness 的 Web/session token | 仅用于对应运行时访问，不代替业务 API、模型或平台认证 |

OpenClaw 适配器存在会话认证文件与 Header 占位符解析；DeepSeek harness 的 Bash provider 可从当前用户登录/个人参数缓存刷新命令执行环境。优先通过各运行时暴露的能力获取，不将适配器内部存储路径或 Redis key 变成所有 Skill 的直接依赖。命令子进程与 Agent 宿主进程可能拿到不同时间点的配置，检查应针对真正发起请求的进程。

## 二、平台存储的外部资源元数据

### 先发现可引用的业务资源

平台列表入口及分页见 [资源发现 API 契约](api-contracts.md#平台资源发现与技能查重)。能力发现同时覆盖当前会话与平台：按业务意图使用平台已提供的目录、搜索或资源列表能力查找 API、MCP 等注册资源，再读取目标详情。已知资源 ID 时可直接查询；名称有多个候选时按业务用途、类型、所属范围与权限区分，不猜 ID。

当前会话工具清单不是平台完整目录，未加载的 API/MCP 也可以成为生成技能的依赖。区分“可发现”“有使用权限”“已取得调用元数据”“当前运行时可调用”四个状态；缺少权限或运行时适配时明确说明，并按用户目标处理，不将资源发现直接当作安装、授权或调用成功。

生成技能保存必要的资源 ID/逻辑定位与所需操作契约，在执行时按当前用户权限重新查询或解析元数据。API 核实方法、地址、请求/响应及认证；MCP 核实服务定位、传输方式、所需工具及输入 schema、认证与可用的客户端/平台调用能力。不固化开发会话临时工具名称、连接句柄或认证信息；平台资源引用不要求复制资源实现进技能包。

目录/搜索入口使用当前部署实际提供的能力；下面的详情 API 用于已定位资源，不虚构它们支持名称搜索或覆盖全部类型。无可用目录时，可使用用户指定的确切资源标识或平台明确提供的只读索引，不能从一个局部空列表推断平台无资源。

### 需要取得什么

先定位业务资源的真实 ID、类型与所属范围，再读取与当前动作有关的调用定义：目标地址、协议、HTTP 方法、路径、请求/响应 schema、Header、认证方式、凭据引用/占位符及必要的会话信息。返回可能包含实际敏感值，不能因为名为“元数据”就完整打印或复制到生成的技能中。

元数据回答“如何调用、采用哪种认证”；实际秘密可能在元数据中，也可能需要从第一类运行时身份或第三类连接器/env 解析。看到占位符不表示已获得有效凭据。

### 路径 A：平台 API 或已提供的资源查询工具

优先用当前运行时暴露的只读资源查询工具；需要直接调用时复用平台认证客户端。以下为已核实的后端接口，相对于带 `/byaiService` 的平台 base_url：

| 接口 | 查询方式与边界 |
|---|---|
| `POST /resource/queryResourceDetail` | JSON `resourceId`；取得目标资源详情，具体结构按资源类型解析 |
| `GET /tool/queryResourceDetail?resourceId=...` 或对应 POST | 同一资源详情能力的入口；不要因不同 URL 重复查询全部数据 |
| `POST /api/v1/resources/query` | 使用明确 queryType；是特定资源/模型的运行时查询，不是所有工具 API 的通用目录 |

运行时查询示例请求：`{"queryType":"BY_RESOURCE_ID","resourceId":"实际ID"}`。响应 data 内含 schemaVersion/queryType，以及实际 allowed、resourceType、data 等结果；先核对 allowed，再读取资源内容。`allowed=true` 且资源 data 为空仍不能视为定义完整。

当前运行时查询支持的资源映射为 DIG_EMPLOYEE、KG_DOC、OBJECT、VIEW、SCENE、ONTOLOGY_BASE；不要拿 TOOLKIT 等未支持类型反复请求该入口。`AUTHORIZED_RESOURCE_IDS` 返回的是该接口支持范围的授权资源，空列表不等于用户没有任何外部 API。`BY_MODEL_ID`/`BATCH_BY_MODEL_IDS` 使用平台 modelId，仅在当前业务确实需要相应模型时查询，不能批量收集模型凭据。

ByClawSkillAPI 当前没有上述专用方法；需要直接调用时按 [API 契约](api-contracts.md) 的受控 Session 模式复用 base_url、认证和响应处理，设置超时，不编造 `get_resource_metadata()` 等已实现方法。403/allowed=false 等权限拒绝不能通过换用文件或底层 Redis 绕过。

### 路径 B：平台明确提供的共享只读文件

从当前资源元数据、运行时配置或共享挂载清单取得**确切文件位置**，确认是当前用户/资源范围可用的共享只读内容，再定向读取目标资源文件。记录资源 ID、类型及可取得的版本/更新时间，保持共享文件只读，不将整个共享目录复制到会话产物中。

文件可提供链接元数据、OpenAPI 定义、认证配置或凭据引用；只提取当前业务需要的内容，在运行时解析敏感字段。如果文件身份不匹配、过期、字段不全或与实时查询冲突，使用平台支持的刷新/查询方式核实，不把旧快照当当前认证事实。

没有已声明的共享文件就用路径 A，不能猜测 `/by/.../resources` 是通用目录。某个能力名称含 local 或 snapshot 不证明存在可读取文件；缓存位置与刷新方式由平台/运行时负责，只使用其公开的读取能力。

### 解析与调用

ByClaw 资源适配器会处理 `param`、`headers`、`resourceService` 和 OpenAPI 内容，并形成 endpoint、method、schema 与认证 Header。部分 Header 的 `${fieldName}` 从当前用户认证上下文解析；它不是通用的 shell/env 插值规则，不要执行模板文本。

优先使用当前资源调用工具完成认证注入；自己实现脚本时遵循所选资源的真实契约，不把所有平台 Header 或所有环境凭据一并发送给外部 API。未解析的占位符、缺失的凭据引用和未知认证方式必须先补齐，不能原样发出请求。

## 三、平台连接器、个人参数与环境变量中的凭据

### 获取步骤

1. 明确业务目标和最小操作范围，例如查询某个 GitHub 仓库，而不是收集该用户全部连接凭据。
2. 查询当前用户连接器的账号、连接状态、credentialState、有效期与所需能力。若已有运行时连接器工具或 credential helper，直接使用其认证执行能力。
3. 脚本确实需要凭据时，通过当前部署支持的注入机制、连接器受管文件或定向 env key 解析。环境变量是消费入口，不证明底层来源一定是手填个人参数。
4. 已过期、需重新认证、被禁用或所需权限不足时，引导到平台对应连接器/个人设置补齐；只报告缺失变量名或状态，不要求把秘密粘贴到聊天。发现连接器状态不能自动等同于已取得秘密或具备所有仓库权限。

### 连接器状态 API

`GET /connector/connections` 返回当前用户连接信息，包含 `connectorId`（该 DTO 使用业务编码）、`status`、`accountName`、`credentialState`、`renewalMode`、`accessExpiresAt`、`refreshExpiresAt`、`lastVerifiedAt`。它是状态接口，**不返回 GitHub accessToken**。

已有 authorizationId 时可查询 `GET /connector/authorization/status`；开始、撤销授权和启停连接器是状态变更，不是环境探测附带动作。只在用户要求或业务已获准的授权范围内使用平台相应流程。

### GitHub 连接的使用线索

- 平台优先解析当前用户已启用、可用且未过期的 GitHub 连接器凭据；不可用时兼容回退到旧个人 GH_TOKEN。解析和解密由平台服务完成，Skill 不读取底层 secret store 或自行解密。
- 平台可将解析结果注入 GH_TOKEN；最终 profile 的 spec.env 决定是否注入，以及是否映射为 BY_GH_TOKEN。启动上下文中的字段不保证原样出现在沙箱。
- 某些部署提供 Git credential helper：先读 `BYCLAW_GITHUB_CREDENTIAL_FILE` 指定的受管文件，该 helper 的缺省路径是 `/by/.connector-auth/.github/credential.json`；然后按 `BY_GH_TOKEN → GH_TOKEN → GITHUB_TOKEN` 回退。此顺序仅适用于已提供该 helper 的部署，不能推广成所有连接器的统一规则。
- 有 helper 时优先让 Git 使用它，不运行会将 token 打印到终端的 credential get/fill 探测。受管凭据文件不得写入技能包；存在文件或非空 env 仍需核对实际业务权限与有效性。

其他连接器遵循各自 provider 的契约；不能套用 GitHub 的路径、key 名或回退顺序。

### 个人环境参数与刷新

启动工厂依次构造基础环境、spec 声明的系统配置、个人参数和专用身份/连接配置；个人参数可覆盖系统环境，GitHub/身份/模型等字段还会被专用逻辑赋值。最终注入仍受 profile 的 spec.env 控制，不指导用户“在任意 env 加一个 key 就一定生效”。

DeepSeek harness 的 Bash provider 还有执行时刷新：读取当前用户个人参数与登录身份，登录字段覆盖同名个人参数，刷新后的运行时环境在命令执行时应用。它可能不同于启动时快照。优先使用已有刷新能力并在实际调用进程中验证，不默认重启整个沙箱、不直接改 Redis 以补齐凭据。

## 创建与测试时怎样使用这三类信息

将实际需要的动态解析契约及**依赖契约**写入生成技能：资源 ID/定位方式、调用方式、认证类型、凭据来源或 env key、目标权限和缺失处理。不要把解析出的秘密传入技能正文、模板、ZIP 或测试报告。

| 业务例子 | 依赖发现 |
|---|---|
| 创建一个调用当前模型的分析技能 | 第一类：当前 Agent 模型、endpoint、运行时调用能力或脚本认证来源 |
| 创建一个调用平台登记业务 API 的技能 | 第二类：资源定义/只读元数据；按其认证引用补第一类或第三类 |
| 创建一个操作 GitHub 仓库的技能 | 第三类：当前连接器、helper/受管文件或实际 env 注入，以及仓库权限 |

纯静态验证可使用合成数据；真实模型/API/仓库联调须具备有效认证、正确目标和已获准的业务范围。凭据缺失时可以继续不依赖它的工作，但该业务调用标为未测/受阻，不能以 mock 通过声称真实连接验证成功。

跨用户发布时，生成技能须包含独立可用的动态解析逻辑或随附指引，不能只链接本管理技能在开发沙箱中的绝对路径。只打包代码、资源定位与必要解析指引；各用户运行时在调用时解析自身有效身份与连接，不复用开发者 Token、会话认证文件或固定个人账号。更新/撤销后的凭据生效依平台和运行时刷新机制核实。

## 诊断交付

诊断仅记录：所需业务动作、来源类别、资源/连接器标识、认证方式、SET/MISSING/需重认证等状态、已验证范围和未测原因。不输出秘密值、完整响应体、完整配置或认证 Header。秘密应由工具或脚本在执行进程内消费。

实际部署的字段、权限与工具能力若有差异，按当前受支持契约核实；不得从本文推断所有用户沙箱拥有全部凭据。
