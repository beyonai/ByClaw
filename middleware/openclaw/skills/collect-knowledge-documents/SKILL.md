# 收集知识资料

只使用 `by-knowledge-manager` 提供的知识库检索、读取和下载能力。不得访问互联网、连接器、任意网址、本地其他语料或其他外部资源。

执行前加载并遵循 [`../by-knowledge-manager/SKILL.md`](../by-knowledge-manager/SKILL.md)。把该 skill 作为命令语法、运行环境、知识库范围和故障处理规则的唯一来源；不要在这里复制或自行推断它的实现。

## 选择检索方法

资料收集通常同时覆盖路径前缀 `/KnowledgeEntity/` 和 `/OriginalDocument/`。`by-knowledge-manager` 不接受对象类型参数，因此在审查命中项时按 `filePath` 前缀保留这两类资料，排除任务范围外的路径；不得擅自扩大知识库资源 ID 或文件路径范围。

根据问题选择 `by-knowledge-manager` 的方法：

- **关键词检索**：已知实体名、文档名、类名或其他明确术语时，对每个少量准确关键词使用 `search-file` 查找候选文件。关键词应保留原始拼写，不要用宽泛近义词扩大范围。
- **语义检索**：需要按自然语言问题寻找相关证据时，使用 `search` 查找切片命中。
- **混合检索**：默认同时执行关键词检索和语义检索；按 `resourceId + filePath` 合并候选，并综合明确术语匹配、切片相关性和路径范围选择资料。不要把两路命中简单视为都必须读取。

检索只用于发现候选和证据片段。先审查命中的 `resourceId`、`filePath`、分数、切片内容及行号，再决定是否扩读或下载。

## 读取或下载候选

选定候选后，按以下情况调用 `by-knowledge-manager`：

- 命中包含可回答问题的文本与行号时，先使用 `read-file` 扩大命中行附近的阅读范围。
- 需要通读文本但命中没有可靠行号时，从文件开头分段使用 `read-file`，直到证据足够或确认无关。
- 需要完整文件、非文本内容或可链接的本地材料时，使用 `download`；读取实际下载结果，不要推测文档内容。

只读取或下载能够回答问题、核验关键事实或弥补当前证据缺口的候选，不因命中就全部获取。

## 追踪知识实体中的原始文档引用

知识实体中的引用可能写成：

```text
20007262/OriginalDocument/ByKC-deep-tech-analysis.md
```

其中第一段是知识库 `resourceId`，后半段是文件路径。引用同时包含这两部分时，不再检索：需要文本证据时直接使用 `read-file`，需要完整本地文件时使用 `download`。

如果引用只有名称、链接文字或实例 ID，缺少 `resourceId` 或完整文件路径，则只在当前允许的知识库资源 ID 中使用 `search-file` 二次查找，并且只接受 `/OriginalDocument/` 下与引用名称和上下文一致的候选；需要核验正文时再使用 `read-file`。没有可信结果时停止并记录证据缺口。

## 资料收集方法

1. **明确问题**：确定需要回答的事实、范围和证据标准，提取少量准确关键词。
2. **先检索**：先查看候选资料，不在检索阶段下载文件。
3. **最小化选择**：只下载能够回答问题或弥补证据缺口的候选，不因命中就全部下载。
4. **下载并阅读**：阅读实际内容，区分已有证据与尚未解决的问题。
5. **按需追踪引用**：只有引用可能补足当前缺口时才继续；不自动递归全部引用。
6. **及时停止**：证据足以回答、引用与问题无关、引用超出允许范围，或二次检索没有精确结果时停止。
7. **基于证据输出**：最终内容只使用已阅读文档支持的事实，链接到本地文件，并明确说明证据缺口。
