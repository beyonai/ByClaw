# 收集知识资料

只使用 `project-cloud-knowledge` 提供的知识库检索、读取和下载能力。不得访问互联网、连接器、任意网址、本地其他语料或其他外部资源。

执行前加载并遵循 `project-cloud-knowledge` skill。把该 skill 作为命令语法、运行环境、知识库范围和故障处理规则的唯一来源；不要在这里复制或自行推断它的实现。

## 选择检索方法

第一轮根据问题选择 `search`、`search-file` 或两者组合，并按照 `project-cloud-knowledge` 的检索子 Skill 用 `where` 将 `filePath` 限定在 `/KnowledgeEntity/`。

根据问题选择方法：

- 需要直接寻找正文证据时，使用 `search` 和完整自然语言问题取得相关切片。
- 已知实体名、文档名、类名或明确术语，需要先定位候选文件时，使用 `search-file`；保留原始拼写，不要用宽泛近义词扩大范围。
- 单一路径不足、需要同时发现候选和核验正文，或两路结果可以相互校验时，再组合使用两种方法。按 `resourceId + filePath` 合并结果，综合术语匹配、切片相关性和文件路径选择资料；不要把全部命中都视为必须读取。

先审查命中的 `resourceId`、`filePath`、分数、切片内容及行号。只有 `/KnowledgeEntity/` 下的结果不足以回答问题或暴露明确证据缺口时，才在相同知识库资源 ID 中移除该路径限制，重新使用 `search` 或 `search-file` 扩大到整库；不得因此擅自增加其他知识库资源 ID。

## 读取或下载候选

选定候选后，按以下情况调用 `project-cloud-knowledge`：

- 命中包含可回答问题的文本与行号时，先使用 `read-file` 扩大命中行附近的阅读范围。
- 需要通读文本但命中没有可靠行号时，从文件开头分段使用 `read-file`，直到证据足够或确认无关。
- 需要完整文件、非文本内容或可链接的本地材料时，使用 `download`；读取实际下载结果，不要推测文档内容。

只读取或下载能够回答问题、核验关键事实或弥补当前证据缺口的候选，不因命中就全部获取。

## 追踪 Markdown 引用

知识实体只通过 Markdown 链接引用其他文件，例如：

```markdown
[深度技术分析](../技术资料/ByKC-deep-tech-analysis.md)
```

引用目标、产生引用的知识实体、`search` 返回的切片以及 `download` 获取的文件都属于同一个知识库。始终复用知识实体命中项中的 `resourceId`，或下载该文件时使用的 `resourceId`；不要从 Markdown 链接中解析、查询或猜测另一个知识库 ID。

把以 `/` 开头的链接目标视为知识库绝对路径；把相对链接目标相对于当前知识实体的 `filePath` 所在目录解析并规范化。链接带有锚点时，文件路径不包含锚点，锚点只用于在正文中定位。不得把知识库链接当作本地工作区路径或外部网址访问。

解析出目标 `filePath` 后，需要文本证据时先在同一 `resourceId` 中使用 `read-file`，需要完整文件时使用 `download`。引用文件不保证存在；路径不存在时，使用链接文字、文件名和引用上下文在同一知识库中执行 `search-file`，必要时再用 `search` 核验正文。只接受与引用及上下文一致的候选；没有可信结果时停止并记录证据缺口。

## 资料收集方法

1. **明确问题**：确定需要回答的事实、范围和证据标准，提取少量准确关键词。
2. **先检索**：先查看候选资料，不在检索阶段下载文件。
3. **最小化选择**：只读取或下载能够回答问题或弥补证据缺口的候选，不因命中就全部获取。
4. **获取并阅读**：读取实际内容，区分已有证据与尚未解决的问题。
5. **按需追踪引用**：只有引用可能补足当前缺口时才继续；不自动递归全部引用。
6. **及时停止**：证据足以回答、引用与问题无关、引用超出允许范围，或二次检索没有精确结果时停止。
7. **基于证据输出**：最终内容只使用已阅读资料支持的事实，保留知识库资源 ID、文件路径和可用行号；存在下载文件时链接到本地文件，并明确说明证据缺口。
