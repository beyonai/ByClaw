# 文档智能打标技能（doc-tagger）

## 触发条件

当用户表达以下意图时触发：
- "帮我打标"
- "给这个文档打标"
- "录入文档"
- "文档打标"
- "融合更新写入知识库"
- 以及其他需要对文档进行结构化打标或融合写入的请求

---

## ⚠️ 执行规则（最高优先级）

1. **文档内容必须完整**：读取完整文档内容传给后端，禁止截断、省略、摘要，必须是原文全文
2. **录入范围必须确认**：用户提到多个文件时，不得默认全部录入，必须先向用户确认哪些文件需要打标录入，哪些不需要
3. **文档路径必须提供**：作为打标记录的一部分，路径不可为空
4. **动态获取对象列表**：每次执行时都重新获取最新的 OBJECT 资源，不使用缓存
5. **匹配合适即可**：不强制要求完全匹配，优先选择最相关的对象
6. **如无匹配对象**：告知用户当前没有合适的本体对象可用于该文档打标
7. **禁止推测结果**：调用对象录入前不得告知用户录入结果
8. **每个文件单独调用**：无论对象是否相同，每个文件必须单独发起一次 `baiying_call`，禁止将多个文件内容合并到同一次调用中；多个对象同理，每个对象也单独一次调用
9. **融合更新路径不可改变**：调用融合更新时，`original_source_path` 、 `current_source_path`和`source_path` 必须与用户提供的来源路径完全一致，禁止修改

---

## 第一步：获取本体对象列表

调用 `baiying_call` 获取当前数字员工的所有本体对象资源。

在 `TOOLS.md` 中找到所有 `type: OBJECT` 的资源，记录每个对象的：
- `name`（对象名称）
- `code`（对象编码）
- `id`（资源ID）
- 描述信息（了解该对象用于什么业务场景）

---

## 第二步：分析意图，选择调用方式

根据用户意图选择对应的调用方式：

- **普通打标**：用户提供单个文档，需要录入知识库对象字段 → 使用 [调用方式 A](#调用方式-a普通打标)
- **融合更新**：用户已提供融合后的文档内容，需要记录两个来源文件路径并写入知识库 → 使用 [调用方式 B](#调用方式-b融合更新)

> 注意：融合更新时，融合工作由调用方完成，此 skill 不做内容融合，只负责将融合好的内容连同来源路径一并写入知识库。

---

## 调用方式 A：普通打标

**query 格式（必须严格按此模板，所有占位符替换为实际值）：**

```
请对以下文档进行结构化打标录入。

source_path: {文档完整路径}
content:
{文档完整正文，原文全文，禁止截断或摘要}
```

**多文件/多对象处理规则**：每个文件必须单独发起一次 `baiying_call`，禁止将多个文件内容合并到同一次调用中。匹配到多个对象时，同一文件对每个对象也各发起一次调用。

---

## 调用方式 B：融合更新

调用前提：融合内容已由调用方准备好，此处只负责写入。

**query 格式（必须严格按此模板，所有占位符替换为实际值）：**

```
请执行融合更新，将文件融合后的文件打标更新。

original_source_path: {原融合文件完整路径}
current_source_path: {现整理文件完整路径}
source_path: {融合后文件完整路径}
content:
{融合后完整正文，原文全文，禁止截断或摘要}
```

**字段说明：**
- `original_source_path`、`current_source_path`：来源引用路径，仅记录，后端不修改原文件，必须与用户提供的路径完全一致
- `source_path`：融合后文件完整路径，以 `/` 开头
- `content`：融合后的完整正文，必须包含全部内容，禁止截断、摘要或省略

---

## 第三步：反馈结果

向用户反馈：
- 匹配到的本体对象
- 录入/写入结果（成功/失败）
- 失败原因说明
