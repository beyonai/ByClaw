# 文档智能打标技能（doc-tagger）

## 触发条件

当用户表达以下意图时触发：
- "帮我打标"
- "给这个文档打标"
- "录入文档"
- "文档打标"
- 以及其他需要对文档进行结构化打标的请求

## ⚠️ 执行规则（最高优先级）

1. **文档内容必须完整**：读取完整文档内容传给后端，禁止截断、省略、摘要，必须是原文全文
2. **录入范围必须确认**：用户提到多个文件时，不得默认全部录入，必须先向用户确认哪些文件需要打标录入，哪些不需要
3. **文档路径必须提供**：作为打标记录的一部分，路径不可为空
4. **动态获取对象列表**：每次执行时都重新获取最新的 OBJECT 资源，不使用缓存
5. **匹配合适即可**：不强制要求完全匹配，优先选择最相关的对象
6. **如无匹配对象**：告知用户当前没有合适的本体对象可用于该文档打标
7. **禁止推测结果**：调用对象录入前不得告知用户录入结果
8. **每个文件单独调用**：无论对象是否相同，每个文件必须单独发起一次 `baiying_call`，禁止将多个文件内容合并到同一次调用中；多个对象同理，每个对象也单独一次调用

## 技能逻辑

### 第一步：收集文档信息

需要从用户处获取：
1. **文档路径**：可以是本地文件路径或知识库中的文档标识
   - 如果用户提到多个文件，必须先确认哪些文件需要打标录入，不得默认全部处理
2. **文档内容**：读取完整文档内容，用于分析匹配，禁止截断或摘要

> 如果用户只提供文档路径，主动读取文档内容。

### 第二步：获取本体对象列表

调用 `baiying_call` 获取当前数字员工的所有本体对象资源。

在 `TOOLS.md` 中找到所有 `type: OBJECT` 的资源，记录每个对象的：
- `name`（对象名称）
- `code`（对象编码）
- `id`（资源ID）
- 描述信息（了解该对象用于什么业务场景）

### 第三步：分析文档内容，匹配合适的本体对象

将文档内容与各本体对象的业务描述进行匹配分析：
- 根据文档的主题、关键词判断属于哪个业务领域
- 根据文档中的实体（人物、项目、产品等）匹配对应对象
- 考虑对象之间的业务关联性

匹配合适的本体对象后，确定：
- **主要录入对象**：文档内容最相关的本体对象
- **可能关联对象**：文档中涉及的其它业务对象（如有）

### 第四步：调用对象进行打标录入

使用 `baiying_call` 工具，调用匹配到的本体对象：

```
resource_id: <对象ID>
resource_type: OBJECT
query: "请根据以下文档内容进行结构化打标录入：
文档路径：{文档路径}
文档内容：{完整文档原文，不得截断或省略任何内容}

请提取文档中的关键信息，完成字段录入。"
```

**多文件/多对象处理规则**：每个文件必须单独发起一次 `baiying_call`，禁止将多个文件内容合并到同一次调用中。匹配到多个对象时，同一文件对每个对象也各发起一次调用。调用顺序：按文件逐个处理，每个文件按对象优先级依次执行。

### 第五步：反馈录入结果

向用户反馈：
- 文档匹配到的本体对象
- 各对象的录入结果（成功/失败）
- 失败原因说明
