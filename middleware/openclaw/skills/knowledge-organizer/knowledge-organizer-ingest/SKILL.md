# 登记源文件

加载并遵循 `by-knowledge-manager` skill，使用它的上传能力执行本阶段。不得调用实体发现或补全。

## 确定目标

- 使用父 Skill 已确定的知识库 `resourceId`。
- 确定知识库目标目录；用户未指定且无法从上下文唯一确定时先询问，不要猜测。
- 确认每个本地文件对运行环境可读。保持原文件名和内容，不要为入库改写资料。
- 同一目标目录和冲突策略的文件可以批量上传；需要独立处理或失败隔离时逐个上传。

## 执行

- 按 `by-knowledge-manager` 的变更规则先检查同名冲突，再使用 `upload`。
- 用户未授权覆盖时，不要把同名文件改为 `update-file`。
- 上传成功会自动触发知识构建；异步构建受理不等于构建完成。
- 用户关心检索或后续实体处理是否就绪时，按 `by-knowledge-manager` 查询 `build-status`。

## 完成标准

只有 `upload` 返回成功时，才把对应文件视为已入库。逐项记录成功文件的知识库路径，以及失败或跳过的文件和原因。完成后停止；除非父 Skill 已获得完整链路授权，否则不得继续实体发现或补全。
