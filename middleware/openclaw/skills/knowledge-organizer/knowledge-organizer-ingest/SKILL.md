# 登记源文件

逐个独立处理文件，避免一个文件失败影响其他文件的结果。

## 选择对象

1. 阅读源文件，理解它表达的内容和业务对象。
2. 只读取初始化结果 `objects/ods/` 目录下的对象定义；不得使用 ADS 对象。
3. 只选择一个语义最匹配的 ODS 对象。优先采用用户明确指定的 ODS 对象。
   - 交互任务中，无法合理匹配或多个候选差异明显时，先询问用户。
   - 后台任务中，选择最有依据的匹配继续处理；没有可辩护的匹配时跳过该文件并记录原因，最后统一汇报，不要逐文件询问。
4. 原文件名有意义时保持不变；只有 `附件1` 这类通用名称才根据内容生成简短名称。不要改写文件内容。

## 执行

```bash
python3 <技能目录>/scripts/knowledge_organizer.py ingest \
  --task-dir "<任务目录>" \
  --source "<源文件绝对路径>" \
  --object-code "<所选对象编码>" \
  --storage-file-name "<有意义的文件名>"
```

支持 `.md`、`.txt`、`.json` 文件。

只有用户或上游流程提供了额外元数据时，才添加：

```bash
--ext-content-json '<元数据JSON>'
```

不要编造元数据。`--ext-content-json` 必须是 JSON 对象。

## 完成标准

只有对应命令执行成功时，才把文件视为登记成功。逐项记录成功文件及其所选 ODS 对象，再记录失败或跳过的文件和原因。
