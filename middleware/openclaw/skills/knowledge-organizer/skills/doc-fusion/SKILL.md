# 文档融合

## 子 agent 调用契约（knowledge-organizer）

由 `knowledge-organizer` 的对象级子 agent 调用时，一次只能处理一个 `{对象名称}`：

- 新增文档目录：`{任务目录}/新建对象/{对象名称}/`
- 现有候选目录：`{任务目录}/知识库候选/{对象名称}/`
- 融合输出目录：`{任务目录}/融合结果/{对象名称}/`

仅接收 `entity-resolution` 已确认同一实例的文档对。待用户确认候选和未匹配的新建文档不得传入、不得写入“融合结果”。子 agent 不得访问其他对象目录，完成后须返回每份融合文档的 `original_source_path`、`current_source_path`、`source_path` 与冲突信息。

## 文档结构

唯一固定的结构如下：

```
key: value
---
正文
--- related_docs ---
doc_id: 当前文件路径
related_docs:
- target_doc_id: 关联文档路径
  relation: 关系类型
  kb_resource_id: "知识库资源ID"
--- related_docs ---
```

除上述结构外，正文内容、YAML front matter 字段、标题格式均不固定，取决于提供材料。

## 融合规则

1. **对象实例判断**：结合文件名和文件内容，判断新增文档与现有文档是否描述同一对象实例
   - 提取文件中的核心概念、定义、主题
   - 比较现有文档与新增文档的核心内容是否相同或高度相关
   - 不以 `name` 字段作为唯一匹配条件
2. **有匹配时融合**：将新增文档的内容融合到现有文档，使用现有文档的文件名
3. **无匹配时新增**：将新增文档作为全新对象，保存到输出目录

## 融合质量要求

1. **内容充实性**：融合后的文档内容必须比融合前的任何一篇都更丰富，不能出现融合后内容比任一源文档更精简的情况
2. **行文流畅性**：避免直接出现"补充xxx内容"的表述，使文章阅读流畅自然
3. **文档完整性**：related_docs 中的 doc_id 必须与目标文档的文件名称和路径一致

## 执行步骤

### 第一步：扫描文档

1. 扫描现有文档目录，获取所有文档的完整内容
2. 扫描新增文档目录，获取所有文档的完整内容
3. 解析每个文档的结构，提取关键信息

### 第二步：文档分析

1. 读取新增文档，提取其描述的核心对象、概念、定义
2. 读取现有文档，提取其描述的核心对象、概念、定义
3. 通过内容比对，判断新增文档与现有文档是否描述同一对象实例
4. 标记所有需要进行融合的文档对
5. 识别全新对象（无匹配项的新增文档）

### 第三步：文档融合

对每个需要融合的文档对：

1. 分析两个文档各自的核心内容和侧重点
2. 将新增文档中的补充性内容自然融入现有文档
3. 合并 related_docs 列表（保留两个文档的关联关系）
4. 更新 doc_id 为融合后的目标路径
5. 确保融合后的文档满足质量要求

### 第四步：保存结果

1. **输出目录约束**：
   - 输出目录**必须**与现有文档目录不同，禁止将融合结果写入输入目录
   - 禁止覆盖或修改任何现有文档，融合结果必须写入独立的输出目录
   - 融合后的文档文件名与现有文档保持一致（使用现有文档的文件名）
2. 输出目录结构为：`{输出根目录}/{object_type}/{对象实例文档名称}.md`
3. **只保存发生变更的文档**：
   - 融合文档：使用现有文档的文件名，保存到对应 object_type 子目录
   - 全新对象文档：使用其 name 或合适命名，保存到对应 object_type 子目录
4. **未变更的现有文档不输出到融合目录**
5. 汇总报告：列出融合的文档和新增的文档

## 融合示例

### 输入

- 现有文档目录：`/path/to/existing/{object_type}/`
- 新增文档目录：`/path/to/new/{object_type}/`
- 输出目录：`/path/to/output/{object_type}/`

### 处理流程

1. 扫描两个目录下的所有文档
2. 发现新增文档"资料一"与现有文档"本体语义层.md"描述同一对象实例，进行融合
3. 发现新增文档"资料四"无匹配，作为新对象添加到输出

### 输出目录结构示例

```
输出根目录/
├── 植物/
│   ├── 百合.md
│   └── 月季.md
├── 动物/
│   └── 老虎.md
```

### 输出结果示例

| 类型 | object_type | 文档名称 | 说明 |
|------|-------------|----------|------|
| 融合 | 植物 | /path/to/output/植物/百合.md | 新增内容摘要 |
| 融合 | 动物 | /path/to/output/动物/老虎.md | 新增内容摘要 |
| 新增 | 植物 | /path/to/output/植物/月季.md | 对象摘要 |

## 注意事项

1. 融合时必须保留原有文档的核心信息和结构
2. 新增内容应自然融入现有文档，避免简单拼接
3. related_docs 列表需合并去重，确保引用关系准确
4. 如果多个新增文档对应同一个现有文档，需逐一融合所有相关内容
5. 未被更新的现有文档不要放入融合后目录
6. 判断同一对象实例时，要结合文档内容综合判断，不能仅依赖 name 字段
7. **输出目录禁止与输入目录相同，禁止覆盖任何现有文档**
