# 微信公众号技术文章生成器

把 GitHub 开源项目分析变成一篇开门见山、突出优势、带实测的微信公众号文章。

## 核心理念

1. **开门见山** — 第一屏就亮核心数据/成绩，不给铺垫废话
2. **只说优势** — 不写「需要注意的坑」「局限性」等负面内容，读者自己踩
3. **实测为王** — 能本地跑的一定跑，拿真实数据说话，不靠猜测
4. **手机友好** — 短段落、多表格、少代码块、有节奏感

## 工作流程

### Phase 1：仓库分析

1. **克隆仓库**到本地
   ```bash
   git clone <url> /tmp/repo-analysis-<name>
   ```

2. **静态分析**（按优先级执行）：
   - 读取 README.md、CLAUDE.md、CONTRIBUTING.md 等核心文档
   - 扫描目录结构（`find . -type f | head -200`）
   - 分析技术栈：语言分布（`cloc` 或 `find + wc`）、框架依赖（pom.xml/package.json/requirements.txt/pyproject.toml）
   - 检查基准测试数据（benchmark 目录、README 中的表格）
   - 检查 CI/CD 配置、测试覆盖

3. **提取关键信息**：
   - 项目定位（一句话说清楚干啥的）
   - 核心亮点（3-5 个，必须有数据支撑）
   - 基准测试/性能数据
   - 技术架构概览
   - 安装方式与使用方式

### Phase 2：本地实测

**这是文章的灵魂，必须尽力完成。**

1. **尝试安装工具**：
   ```bash
   pip install -U <package-name>
   # 或
   npm install -g <package-name>
   ```

2. **准备测试文件**：从仓库的 `samples/` 目录找，或下载一个经典 PDF/文档作为测试

3. **跑至少 5 个实测案例**，覆盖：
   - 最基本用法（如 `convert input.pdf -o output/`）
   - 多格式输出（Markdown + JSON 等）
   - 特色功能（脱敏、指定页面、内嵌图片等）
   - 性能计时（用 `time` 命令记录）
   - API 调用（Python/Node.js SDK）

4. **记录真实数据**：
   - 每次操作的耗时
   - 输出文件大小
   - 输出内容的关键片段（不要编造，从真实输出中截取）

### Phase 3：文章撰写

**结构模板**（严格按此顺序）：

```
# [炸裂标题：核心数据 + 项目名 + 一句话定位]

> 一行摘要：最核心的数据亮点

---

[1-2 句痛点引入，直接接成绩单]

## 🏆 成绩单/核心数据表格

[横评表格 or 性能数据表格]
[2-3 个加粗关键发现]

---

## 🤔 它到底干了什么？

[2-3 句话解释项目核心价值，不要超过 5 行]

---

## 🏗️ 怎么做到的？

[模式/机制/架构的精简说明，用表格+短文，不要堆砌]

---

## 🧪 实战演练

[实测案例，每个案例：命令 → 结果表格 → 输出片段]

### 安装
### 实测 1：[最常用功能]
### 实测 2：[多格式/特色功能]
### 实测 3-N：[更多亮点]
### 性能汇总表

---

## 🎯 谁该用？怎么选？

[场景 → 推荐方案表格]

---

## 总结

[2-3 句话收尾，有梗有态度]

---

**项目地址**：<url>
**许可证**：<license>

---

*觉得有用？点赞转发让更多人看到 💪*
```

### 写作规范

1. **标题**：必须包含核心数据 + 项目名，如「基准测试第一！OpenDataLoader PDF：PDF 解析界的"又快又好"选手」
2. **开头**：1-2 句痛点引入后直接甩数据表格，不做 3 层铺垫
3. **表格优先**：能用表格说清楚的不用段落，表格列数 4-7 列
4. **代码块**：集中在「实战演练」章节，其他章节尽量用表格/短文替代
5. **数据真实**：所有性能数据、输出片段必须来自实测，不能编造
6. **不写负面**：不写「坑」「局限」「注意」「风险」等内容
7. **段落长度**：每段不超过 4 行，手机阅读友好
8. **emoji 点缀**：章节标题加 emoji，但不过度使用
9. **语气**：口语化、像跟朋友聊天、有节奏感、适当转折

### 输出

- 文件保存到 `active/reports/<project-name>_wechat.md`
- 同时可保留完整分析报告到 `active/reports/<project-name>_analysis_report.md`

## 何时使用此技能

- 用户提供 GitHub URL + 要求写公众号/微信文章
- 用户说"帮我写篇文章介绍这个项目"
- 用户说"做个项目评测/安利/推荐文章"
- 用户想把项目分析结果发布到社交媒体

## 何时不使用此技能

- 用户只要技术分析报告，不要公众号文章
- 用户要写非技术类文章
- 用户要写论文/学术报告
