# Skill 在会话、平台与运行时中的生命周期

本契约依据用户明确的 ByClaw 生命周期约定，供创建、测试、发布、授权、安装和卸载流程共同使用。适用于 OpenClaw、DeepSeek harness 等运行时；不规定广播协议、消息字段名或运行时目录布局。

## 对象与作用域

| 对象 | 位置或归属 | 作用 |
|---|---|---|
| 开发产物 | 用户指定或当前运行时工作区中的独立技能目录 | 本次任务的开发、编辑和测试验证；由当前 Agent 直接编写文件 |
| 发布包 | 验证通过的技能目录生成的压缩包 | 向平台发布注册的交付内容；打包时保持引用与必要文件完整 |
| 平台技能资源 | 平台注册的资源及技能文件 | 承载正式技能身份、内容与管理状态 |
| 授权关系 | 平台技能授权管理 | 控制用户使用权限；不等同于绑定数字员工 |
| 员工绑定关系 | 平台技能与数字员工的关系 | 决定技能对目标员工的配置；绑定/解绑变化触发元数据广播 |
| 运行时加载内容 | 各用户自己的运行时目录 | 各运行时依据广播元数据，在平台授权与员工绑定范围内自动发现、获取和加载文件，生效后供 Agent 调用 |

开发工作区与运行时安装位置分别确定，具体路径及持久化由当前环境决定；本契约不假定会话结束立即删除文件，也不承诺跨会话永久保留。发布后运行时通过平台元数据取得技能，不依赖某次开发会话目录始终存在。

## 正向生命周期

```text
会话内创建/编辑 → 测试验证 → 用户验证通过
    → 打包压缩并发布注册到平台
    → 平台授权管理 → 绑定数字员工
    → 广播绑定元数据到各用户运行时
    → 各运行时自动发现并获取技能文件
    → 加载到各自运行时目录 → 生效调用
```

1. **创建与编辑：** 确定实际可写开发目录，直接编写完整技能文件。源码修改只改变会话产物，不自动更新平台注册内容或其他用户的运行时。
2. **测试与验证：** 在会话沙箱内验证技能行为，保存结果并修复失败。用户验证通过后，按用户要求进入发布；已有明确验收与发布指令可复用，不重复请求同一确认。文件校验通过不能自行替代用户验收。
3. **发布注册：** 将验证通过的内容打包压缩，发布注册为平台技能资源，取得真实资源身份。仅打包成功不代表已发布，平台已注册也不代表各运行时已经加载。
4. **授权与绑定：** 经平台技能授权管理，建立目标数字员工绑定。权限与绑定分别核实；已有合法权限可复用，不重复授权。
5. **广播与自动加载：** 绑定发生时，平台自动广播绑定元数据，各用户运行时据此自动发现、获取技能相关文件并加载到自己的运行时目录，使技能生效调用。管理 Agent 负责平台操作与结果核实，不手工逐个拷贝到各用户运行时，不自造广播消息或绕过权限分发文件。

平台业务动作可能由某个已部署接口合并执行。例如已有 uploadSkillZip 实现同时注册与绑定，调用前必须核实其副作用是否符合本次授权与目标顺序；不因接口名叫“上传”就当成仅保存文件。若用户只要求注册、禁止绑定，而现有接口不能满足，则核实平台支持的独立注册入口，不先调用再补救。生命周期定义不改变接口真实行为。

## 解绑、运行时卸载与注销

```text
注销/移除请求 → 核实绑定与影响 → 平台解绑
    → 广播解绑元数据到各用户运行时
    → 各运行时执行相应卸载
```

注销以解绑开始。解绑后，平台自动广播解绑元数据，各用户运行时执行卸载。不能用删除会话文件、直接删除运行时目录或先删除平台文件来代替这一链路。

单个技能卸载请求可能只移除一种绑定来源。若其他有效来源使员工绑定仍然存在，报告“绑定仍保留”及已核实的原因，不能报告“已解绑，等待运行时卸载”。仅实际解除的绑定进入对应的广播卸载链路，不强制清理其他有效来源。

“解绑”“运行时已卸载”和“平台资源记录已注销/删除”分别报告。用户要求注销时核实全部相关绑定和影响，先完成解绑链路；若还需删除资源记录或包，必须采用平台明确支持的注销契约，不编造 API、清理顺序或默认删除所有用户文件。

## 完成证据与中间状态

以下是报告用语，不是要求 API 实现这些枚举或字段：

| 可证明事实 | 可以报告 | 不能据此推断 |
|---|---|---|
| 会话文件和测试结果存在 | 已创建、测试通过/失败/未测 | 用户已验收或平台已发布 |
| 用户验收与实际注册结果可核实 | 已验证并注册，附资源 ID | 所有用户运行时可调用 |
| 平台权限与员工绑定可回读 | 已授权、已绑定 | 广播已被全部运行时接收 |
| 有目标运行时接收、获取和加载证据 | 该运行时已同步/已加载 | 未检查的其他运行时也完成 |
| 代表性调用成功 | 已在所测运行时生效 | 跨所有用户的全面可用性 |
| 平台解绑可回读 | 已解绑，运行时卸载待确认 | 文件已在各运行时卸载或平台资源已删除 |
| 目标运行时卸载证据可核实 | 该运行时已卸载 | 其他合法共享来源也应移除 |

自动广播不代表管理 API 返回时所有运行时都已处理完。优先使用平台或运行时已提供的状态、回执和脱敏日志；没有证据时报告“已绑定，运行时加载待确认”或“已解绑，运行时卸载待确认”。不假设固定延迟、所有运行时在线、广播可靠性或重试机制；具体协议和补偿行为以实际部署契约为准。

## 业务连接随执行上下文解析

开发产物发布、绑定与加载后，业务技能继续遵守 [凭据与连接发现](credentials-and-connections.md) 的动态解析契约：默认使用当前执行 Agent 的有效模型，资源认证与连接器使用当前用户的授权上下文。开发阶段只验证解析方式，不将开发者模型地址、密钥或会话身份封装进发布包。绑定到其他员工、安装目录变化或凭据更新后，通过对应运行时的受支持能力重新解析，不依赖原会话目录。

## 更新与失败恢复

技能改动回到会话内编辑与验证，通过后重新打包发布。源码修改、平台内容更新和运行时加载更新分别核实，不假定保存文件会自动广播。内容更新如何触发同步依平台实际契约确认；已明确的绑定/解绑广播不能代替对更新协议的核实。

平台操作成功但运行时同步失败时，从元数据接收、文件获取、加载/卸载分层定位。保留已完成的注册与绑定/解绑状态，不盲目重复发布或反复解绑重绑。仅通过平台提供的恢复机制补偿，不手工伪造广播或同步凭据。具体故障处理见 [错误与恢复](error-codes.md)。
