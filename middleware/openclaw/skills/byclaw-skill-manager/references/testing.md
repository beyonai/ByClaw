# 测试流程

编辑后先运行静态和必要的离线验证，再按业务需要验证真实连接与行为。联调须具备相应认证、明确的测试目标和已获准的操作范围；发布授权或隔离环境的存在本身不代表允许任意测试写入。不要把离线静态检查报告为平台联调成功。

## 1. 确定测试对象与预期

输入为目标技能目录、用户任务与预期产物；目录使用创建流程确定的实际路径，不要求固定前缀或 sessionId。先读取待测技能及其所需资源，选取代表性成功请求、边界输入和失败场景。测试的是该技能实际提供的能力，不能只检查本管理技能的流程表。

## 2. 静态与包验证

1. 按通用 Agent Skills 规范检查 YAML frontmatter：name 与目录一致，description 有明确触发范围；仅使用规范定义的字段及其允许的扩展机制，不产出 ByClaw 或 harness 专属的自定义字段。发现已有非标准字段时，在交付产物中移除或按规范迁移；对最终实际产物运行校验，不通过临时删除字段的副本代替最终产物验证。
2. 核对开发产物位于用户指定或运行时提供的工作区；确认实际路径未因符号链接越出已确定的授权范围。验证所有 skill 内 Markdown 相对链接可达；入口可直接找到各任务所需参考，不要求个人沙箱挂载开发仓库或个人机器路径。
3. 准备发布或涉及文件布局、引用、打包逻辑变化时，用真实打包脚本在源目录外临时目录生成 `<skill-name>.zip`，检查 `testzip()`、SKILL.md、所有被引用资源和脚本。检查无凭据、历史包、越界路径及意外链接内容。
4. 新增/修改可执行脚本要运行相应样例；文档中给出的只读采集片段可在隔离环境执行，确保不存在秘密值输出和隐式写操作。部署特有探测未运行时标为未测。

## 3. 运行与行为验证

通过当前 harness 支持的技能加载方式，在当前个人沙箱执行代表性请求，验证触发、引用加载、脚本行为与最终产物。无需假定 OpenClaw 或 DeepSeek harness 的专有工具；当前运行时无法加载时，分别验证能执行的脚本与文件并标明缺失的加载测试。

测试使用选定工作区中的独立临时输入/输出。纯静态或隔离测试使用合成数据；真实模型、业务 API 或仓库联调先按 [凭据与连接发现](credentials-and-connections.md) 取得当前执行身份下的有效依赖，在用户要求的业务范围内执行。真实发布、授权、安装、卸载、外部消息或其他写入不作为默认测试副作用；用 mock 或已获准的测试目标验证。测试证据放在技能源码目录外，避免日志和测试数据进入发布包。

失败时回到创建流程修改相应内容，再重测受影响场景。报告每个场景的预期、实际结果、通过/失败/未测及原因；仅静态验证通过不能写成运行验证通过。发布前读取这些结果，未解决的必要能力失败不得标记为可发布，未测项不得掩盖。

## 跨员工与运行位置变化验证

按目标技能实际依赖选择下列场景；不使用模型或外部资源的技能无需测试无关能力。需要模型时默认使用当前执行 Agent 的模型，不能绑定创建者环境。使用隔离的模拟上下文测试可观察行为；有获准的真实目标时再联调，否则将跨运行时实测标为未测。

| 场景 | 预期结果 |
|---|---|
| 平台已注册所需 API/MCP，但创建会话未加载 | 通过平台目录发现并核实元数据、权限和调用路径，生成资源引用，不误判资源不存在 |
| 资源可搜索但目标用户没有使用权限 | 分别报告可发现与不可调用，不能用开发者身份绕过 |
| 同一份技能先在 Agent A、再在 Agent B 下执行 | 每次解析当前执行 Agent 的模型协议、名称、endpoint 和认证来源；B 不沿用 A 的解析结果，两者可合法配置为同一服务 |
| 改变 cwd、会话目录或运行时安装目录 | 相对资源可达；模型、用户和连接通过当前上下文取得，无开发目录依赖 |
| B 的模型配置与共享沙箱启动 MODEL_* 不同 | 优先按 B 的有效 Agent 绑定解析，不静默使用启动默认模型 |
| B 的模型或凭据发生更新 | 根据实际刷新契约取得新配置；不复用 A 或过期的解析结果 |
| B 缺少模型解析能力或外部资源权限 | 明确所缺上下文/权限；不回退开发者 token，不将 mock 通过报告为真实联调成功 |
| 当前连接器提供认证，但没有预期 env key | 通过受支持连接器/helper 使用；不只因 env 缺失判无凭据 |

检查调用目标与认证是否匹配时用模拟标识或断言，不把真实 endpoint、认证 Header 和 token 写进测试报告。mock 迁移测试通过不证明所有 OpenClaw/DeepSeek harness 部署都已支持所需适配能力。

## 本管理技能的回归场景

仅在修改 byclaw-skill-manager 本身时，按改动范围选取下表场景；创建其他技能时跳过本节，根据其业务目标设计场景。


| 输入与环境 | 预期可观察行为 |
|---|---|
| “优化这个技能的说明”，没有 BEYOND_TOKEN | 完成沙箱内编辑和验证；不要求先登录、不调用 API |
| “想做个技能，但还没想清楚” | 推荐查看当前可见技能，说明查询范围，给出复用、优化或新建方向，不立即生成猜测的业务实现 |
| 用户要求查看全部技能，查询结果分页或仅限某员工 | 遍历可查询范围并说明覆盖边界，不把局部结果当全平台清单 |
| 业务想法模糊，但可发现模型、API/MCP 与连接器状态 | 按实际匹配结果提出少量业务方案，展示产物、资源与缺项，供用户选择，不读取或展示秘密 |
| 候选资源无使用权限或当前运行时不可调用 | 如实标注，提供可行替代或补齐路径，不将选择方案当作授权完成 |
| 用户已明确目标、资源并要求新建 | 仍先盘点相似技能与相关工具资源；无可复用候选时直接创建，不强制展示全量清单 |
| 查到名称不同但业务能力高度重合的技能 | 展示重合点并推荐复用或优化，用户选择后继续 |
| 所有技能发现来源均不可用 | 报查找未完成，继续准备；新建前由用户选择补齐查询或接受未查重继续 |
| 用户指定已有技能要求优化 | 读取并增量修改，不把新建前查找变为优化的额外前置条件 |
| “新建一个 ByClaw 报表技能” | 先盘点技能与相关业务资源，确定新建后使用文件工具在已确定的开发目录生成完整技能；不自动授权或发布 |
| 创建“查询自己当前运行的沙箱列表基本信息”的技能；目录中有 sandbox_manager 工具集及匹配动作 | 在自行编写业务探测前查询相关资源、读取动作并推荐复用；不以 hostname/cgroup 输出代替用户沙箱列表 |
| SKILL 查询为空，但 TOOLKIT 中存在可直接满足需求的动作 | 识别并推荐该工具集，不声称没有现成能力，不重复实现 |
| 工具集名称相近但动作不匹配，或资源未授权 | 说明差异或权限缺口；不因名称相近或能查到资源就宣称可完成业务 |
| 创建“汇总团队仓库待处理 PR”的技能，当前目录只是一份本地 checkout | 先定位团队与仓库范围及平台/GitHub 查询能力，不用 git status 代替 PR 列表 |
| 创建“查询订单当前状态”的技能，本地有历史导出文件 | 核对权威订单查询资源与数据时效；历史文件仅作为明确标注的快照，不能报告为实时状态 |
| 当前部署未发现 sandbox_manager | 不硬编码该工具存在，继续按业务动作寻找其他候选并说明查询范围 |
| 当前 cwd 是 harness 安装目录 | 从用户指定位置或运行时工作区确定开发目录，不默认写入安装目录 |
| 无 sessionId，但已提供可写工作区且没有其他创建技能 | 直接编写文件并测试，不要求补 sessionId 或安装其他技能 |
| 不同运行时提供不同工作区路径 | 使用各自实际目录，保持包内相对引用，不要求固定父路径 |
| 工作区已有同名技能或目录链接指向授权范围外 | 保留已有修改；越界链接不作为输出位置 |
| 用户提供其他位置的技能要求优化 | 在选定开发目录生成优化产物；未明确要求原地修改时保留原安装副本 |
| “发布这个 ZIP”，当前后端上传会注册 | 上传前查覆盖，上传后查询资源及绑定，不再次资源化 |
| “把这个工作区目录变为可分享技能” | 使用查询返回的 skillPath；先冲突预检，再目录资源化 |
| 未绑定目录列表为空，但完整列表有同名资源 | 识别潜在覆盖，不把局部空列表当作无冲突 |
| 覆盖范围已明确获准 | 按相同范围继续；仅新冲突或范围变化要求补充决定 |
| 上传超时 | 查询已发生状态，不盲目再次上传 |
| 安装已发布的单个技能 | 使用技能资源 ID 与目标员工 ID 增量绑定，回读实际关系 |
| 卸载后平台仍保留有效关联 | 报告关系仍保留，不强制删除或宣称已完全卸载 |
| 查询授权成员多页 | 自动分页到用户要求的范围；不每页请求继续许可 |
| OpenClaw 个人沙箱，工作区不在默认路径 | 从当前会话和加载器解析目录，完成相同文件任务，不套用镜像默认值 |
| DeepSeek harness 个人沙箱，没有 OPENCLAW_* 或 openclaw CLI | 使用其当前资源与执行能力，不报告缺少 OpenClaw、不要求安装它 |
| 未声明 harness，但已提供文件与执行工具 | 完成通用步骤；harness 标为 UNKNOWN，不强制识别品牌 |
| 技能由虚拟资源加载，shell 与文件工具作用域不同 | 通过加载器取得脚本文件路径，核实可访问性，不把资源 URI 当路径 |
| 只有文件工具，没有 Python 或 shell | 完成说明与引用编辑；明确打包/API 脚本未执行，不宣称全流程成功 |
| 使用远程浏览器工具，没有 DISPLAY 或浏览器 CLI | 根据远程工具和授权状态判断能力，不要求本机浏览器配置 |
| 获取沙箱环境时，执行工具明确指向另一环境 | 不把另一环境的版本/挂载结果作为当前用户沙箱事实 |
| Redis cluster、显式模式与 schema 配置不同 | 分别按真实读取规则核实，不把三者混成一个开关 |
| 已提供的诊断工具退出 0 但能力状态 unavailable | 依真实输出契约报告能力状态，不按退出码判健康 |
| 已绑定员工，但没有其他用户运行时的加载证据 | 报已绑定、运行时加载待确认，不宣称全部用户可调用 |
| 用户要求注销技能，平台仍有绑定 | 先核实并执行解绑，经元数据广播触发卸载，不先删除平台包 |
| 平台解绑成功但目标运行时尚无卸载证据 | 报已解绑、运行时卸载待确认，不盲目重复解绑 |
| “部署一个普通网站”，未涉及 ByClaw Skill | 不因“部署”泛词触发技能管理流程 |

可用 mock 响应演练分支，检查是否发起了正确种类/次数的调用及是否保留已完成状态，不以固定标题或措辞断言正确。每次只修正场景暴露的问题。

## 4. 用户验证与发布交接

向用户交付实际测试结果和可验证的产物，取得或复用用户验证通过的结论后再按要求发布。必要测试失败则继续修复，未测项明确披露；不能以结构校验通过替代用户验收。记录本次被验收的内容，验收后若发生影响行为的修改，应重新验证相应内容。

按 [生命周期契约](lifecycle.md)，会话内测试通过不等于平台运行时已分发。需要验证平台安装时，分别检查绑定、广播元数据接收、文件获取、加载和实际调用；解绑测试分别检查平台关系与运行时卸载，不用手工复制或删目录模拟广播链路。

## 5. 交付测试结果

报告检查种类、通过项、已知脚本限制、未运行的线上检查。记录实际可取得的平台与运行时版本；部署版本未知时如实说明，不要求读取平台开发仓库。
