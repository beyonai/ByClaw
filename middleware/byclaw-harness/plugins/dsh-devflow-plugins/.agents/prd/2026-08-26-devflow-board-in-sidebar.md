# PRD — devflow:看板迁入 better-sidebar 侧边栏页面

## Problem Statement

devflow 看板今天是一个**悬浮控件**:注册在会话头部的工具 slot 上,经 body portal 固定在对话区右上角(`top: 76px; right: 24px; z-index: 90`),收起态一颗胶囊、展开态一块 344px 的面板(详情态加宽到 460px)。这个形态是当初没有别的落点时的折中,它的代价现在很具体:

1. **尺寸是写死的,内容却在长大。** 需求书、七段流水线、产物清单、父子拆分、完整流转时间线,全都挤在 344/460px 宽、`min(480px, 60vh)` 高的盒子里。时间线一条条堆在这个高度里基本只能看最近三四条。
2. **它是弹层,不是工作台。** 点击外部或按 Esc 就消失,焦点归还触发元素;想"一边看卡片一边干活"做不到——它天生假设你看一眼就关。列表与详情还是**互斥两态**,看详情就看不见板子。
3. **它和内容抢位置。** 固定在右上角,浮在对话之上,遮挡正文;z-index 要小心避让 modal(1000)与 toast(1100)。
4. **每次转发事件都全量重取**,不管面板是开是关——没有"不可见时省掉"的位置。

同一时期,生态里的 [`dsh-better-sidebar`](https://github.com/omdsh-dev/DSH-better-sidebar) 已经把自己做成了一个**开放的侧边栏底座**:从 v0.4.0 起暴露 `ctx.betterSidebar` 服务,`registerTab` / `registerFileViewer` 两个扩展点对内置页面与三方插件**完全对等**(内置的 7 tab + 6 viewer 自己也走这套 API)。它提供的正是悬浮控件缺的东西:整列高度、用户可拖拽的宽度、按会话隔离的持久化状态、tab 角标、可见性信号、以及自动进 DSH 设置页的声明式设置。

## Solution

**装了侧边栏就进侧边栏,没装就还是今天的悬浮控件**——任一时刻只有一个入口。

- **注册**:client half 通过 `ctx.inject(['betterSidebar'], …)` 做**延迟可选注入**——服务出现时才回调,不存在时回调根本不执行。回调里 `ctx.effect(() => ctx.betterSidebar.registerTab({...}))` 注册 `dsh-devflow:board` 页面,disposer 由 fiber 在卸载/HMR 时收回。
- **零依赖**:不在 package.json 里引入 `dsh-better-sidebar`,不做任何 value import——在我们自己的 client half **本地重述最小服务契约**(只需要 `registerTab` 与能力探测两个字段)。生态里 `dsh-sentinel` 与 `ego-browser` 都是这么接的,后者正是"装了侧栏进侧栏、未装回退浮窗"的同款形态。
- **单面互斥**:侧边栏服务在场时,不再注册会话头部的 slot 控件;不在场时行为与今天逐字节一致。
- **页面重设计**(不是把 344px 面板原样塞进去):整列高度、随宽度自适应、统计头 + 阶段筛选 + 层级列表 + 分段可折叠的详情,活跃卡数移交 tab 角标。

数据面完全不动:仍走既有的 Remote `devflow` 命名空间(`list` / `detail`),浏览器仍只发会话 id,不新增任何 Remote 面或缝操作。

## User Stories

1. 作为开发者,我想在右侧边栏里常驻打开研发看板,以便一边看卡片一边在主对话里干活,而不是每次点开一个会自动消失的弹层。
2. 作为开发者,我想让看板占满侧栏整列高度并跟随我拖拽的宽度,以便时间线和需求书不再被塞进一个固定的小盒子。
3. 作为开发者,我想在 tab 图标上直接看到进行中的卡片数,以便不展开面板也知道有没有在跑的活。
4. 作为开发者,我想在页面顶部看到本工作区的卡片统计(进行中 / 已完成 / 受阻),以便一眼掌握全局。
5. 作为开发者,我想按阶段筛选卡片列表,以便只看"待开发"或"受阻"的那几张。
6. 作为开发者,我想让层级(父卡领头、子卡缩进、`k/n` 进度、折叠)在侧栏里保持与今天一致的语义,以便迁移不改变我已经熟悉的读法。
7. 作为开发者,我想在详情里把需求书、拆分关系、产物、时间线四段各自折叠或展开,以便按当下关心的东西调整信息密度。
8. 作为开发者,我想让看板页在被折叠或切到别的 tab 时暂停重取,以便它不在我看不见的时候持续消耗请求。
9. 作为开发者,我想让侧栏页始终显示**它自己那个会话**的工作区看板,以便定向打开另一个会话的侧栏时看到的是那个会话的卡片。
10. 作为开发者,我想在这个会话的工作区没有任何卡片时,让 `+` 菜单里的看板项显示为不可用而不是消失,以便我知道这个能力存在、只是此处没有数据。
11. 作为开发者,我想在 DSH 设置页的「侧边卡片」分区里看到研发看板卡片并能整体关掉它,以便不需要它的时候不占 tab 位。
12. 作为开发者,我想在面板足够宽时让列表与详情左右分栏、常驻并列,以便钻取子卡时不丢失板子上下文。
13. 作为未安装侧边栏的用户,我想让今天的悬浮看板行为完全不变,以便这次迁移对我零影响。
14. 作为开发者,我想让侧栏页与悬浮控件**任一时刻只出现一个**,以便不会同时存在两个入口两份状态。
15. 作为开发者,我想让侧栏页保持严格只读,以便流转决策继续只发生在聊天面、命令面与审批 composer。
16. 作为开发者,我想让侧边栏插件缺席、版本过旧或注册失败时插件照常加载,以便一个可选生态依赖永远不会拖垮 devflow 的其他能力。

## Implementation Decisions

- **接入形态是 B:侧栏优先、悬浮兜底,互斥。** 判定发生在 `ctx.inject(['betterSidebar'], …)` 的回调边界:回调执行 = 侧栏在场 = 注册 tab 并撤下 header slot 注册;回调不执行 = 维持今天。互斥必须由**同一处状态**决定,不允许两条注册路径各自判断。
- **本地重述契约,零 import。** 我们只写下自己用到的那部分类型(`registerTab(descriptor): () => void`、`version`、`features`),不引入 `dsh-better-sidebar` 包,也不做 type-only import——后者虽然被对方文档允许,但会在我们仓库引入一条对外部包的声明依赖,而 `verify-client-packages` 只认工作区包。运行时服务名不产生依赖边,门禁全清。
- **能力按 `features` 探测,不按版本号硬编码。** `badge` / `pluginSettings` 等 v0.12.0+ 能力先 `features.includes(...)` 再用;探测失败即降级(无角标、无设置行),页面主体照常。对方 `dsh.plugin.json` 已是 v0.17.0 而接入文档标称 v0.12.0,版本号不可信,能力清单才是。
- **注册必须包在 `ctx.effect` 里**(对方的硬要求):不包则 HMR / 禁用后注册残留,下次激活抛 `already registered`。
- **tab 描述符**:`id: 'dsh-devflow:board'`(带包前缀,不占用内置 7 个 id)、`single: true`(再次打开聚焦既有页)、`order` 取 60(排在内置 explorer/git/subagent/terminal/browser 之后)、`available` 在该会话工作区无卡片时返回 false(显示为禁用行而非隐藏,对应故事 10)、`badge` 返回进行中卡片数。
- **会话绑定改为 tab 自己的 `scope.sessionId`。** 今天的板子绑"当前选中会话",还有一段会话切换时关详情、重取的逻辑;侧栏页拿到的是自己那个 scope。store 因此按 sessionId 分桶,`watched` 那套切换逻辑退役。悬浮兜底路径继续用"当前选中会话"。
- **`visible` 做重取门。** 不可见时不发请求,恢复可见时补一次全量重取(而不是回放期间攒下的事件)。事件仍照常订阅,只是不触发网络。
- **页面版面(重设计)**,自上而下三段:
  - **统计头**:本工作区卡片总数与分布(进行中 / 受阻 / 已完成),下方一排阶段筛选(七个阶段 + `blocked`,单选,再次点击取消);
  - **卡片列表**:占满剩余高度并滚动,层级语义与今天一致(父卡领头、子卡缩进、`k/n`、受阻标记、每行折叠);
  - **详情**:选中卡片后在同一页推入(带返回),分为**需求书 / 拆分关系 / 阶段产物 / 流转时间线**四段,每段独立折叠,时间线默认展开——这是相对悬浮版最大的收益。
- **左右分栏是设置项,不是断点魔法。** 面板宽度由用户拖拽、跨会话共享,jsdom 里也测不出真实布局;因此分栏由 `settings.pluginToggles` 的一个开关控制(默认关),而不是靠 ResizeObserver 猜。窄面板下用户自己关掉即可。
- **活跃计数从胶囊移交 tab 角标**;页面内不再重复画胶囊。悬浮兜底路径的胶囊保持原样。
- **严格只读不变**:侧栏页不提供移动、编辑、勾选;流转仍走聊天工具与 `/devflow`,审批仍走审批 composer。
- **组件复用而非重写**:行渲染、层级分组(`groupByParent`)、阶段流水线、Markdown 正文、时间线等既有件全部复用;新增的只有页面外壳(统计头、筛选、分段折叠)与两条 props 适配路径。侧栏页拿不到 slot 合成的 props,`t` 由 `ctx.locale.bind('devflow')` 取(返回稳定标识),store 由组件内 `useSyncExternalStore` 直连。
- **注册失败不得影响插件其余部分**:`registerTab` 抛错(id 冲突等)只记 warn,插件照常完成其余注册。

## Testing Decisions

- **组合测用桩服务。** better-sidebar 不在本仓库工作区,e2e 台子起不来它;按测试策略「只 mock 外部服务」的允许,注册一个实现最小契约的桩到 `betterSidebar` 服务名下,用真实 Loader 组合断言:tab 描述符被注册、字段(id / order / single / available / badge)正确、header slot 在此路径下**不注册**、fiber 处置后注册被撤销(HMR 安全)、注册抛错只 warn 且不影响其余注册。
- **无侧栏路径回归**:同一套组合测在没有 `betterSidebar` 的上下文里断言 header slot 照常注册、悬浮控件行为不变。
- **组件层 jsdom**:统计头与筛选、层级列表(沿用既有断言)、详情四段折叠、`visible=false` 不重取、`available` / `badge` 的纯函数取值、只读断言(除折叠/筛选/返回/钻取外无可交互元素)。
- **既有真实浏览器 e2e 保持不变**:它跑的是悬浮兜底路径(台子里没有侧边栏插件),正好成为故事 13 的回归证据。
- **真机验证靠手测 + GIF**:侧栏形态的端到端只能在装了 better-sidebar 的真实 profile 上验证,按仓库 GUI 变更要求录制 GIF 附 PR。这是本 PRD 已知的自动化缺口,明确接受。
- 逐文件覆盖率、双语文案与 README、client catalog 门禁与 Agent Note 随各切片。

## Out of Scope

- **注册文件预览器**(`registerFileViewer`):卡片是目录不是文件类型,没有当前消费者;
- **侧栏页里的写操作**:移动、编辑、勾选验收项、面板内审批——沿用三面分工;
- **对方特有的容器行为**:底部面板、拖拽拆分/合并分栏、自由窗口、移动端抽屉——这些是底座的能力,我们的页面只需在其中正常渲染,不为它们做特化;
- **DSH 其他面板的迁移**:本 PRD 只搬 devflow 看板;
- **把 better-sidebar 变成必需依赖**或将其纳入本仓库的 e2e 台子;
- **父行"被打回"标记**:仍受限于列表不带历史(见 ui-devflow 的 Known Limitations),本次不解决;
- **跨工作区聚合视图**:维持前几份 PRD 的 out of scope。
