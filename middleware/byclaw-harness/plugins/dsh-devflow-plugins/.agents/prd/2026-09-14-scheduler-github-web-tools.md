# 定时调度与 GitHub 同步：Web 面板和 agent 工具

项目归属与页面结构以已确认的[项目自动化与独立 GitHub 订阅页](2026-09-14-project-automation-tabs.md)为准；本文保留最初功能范围。

状态：用户已确认独立自动化侧栏方案并授权实现；对应用户在本地安装完成后提出的 Web 面板与工具调用需求。实现基线为 `a4b15b7`，现有持久化服务继续负责业务状态。

## 用户目标

用户不用记忆斜杠命令和手写参数，通过自然语言创建或调整扫描任务，通过 Web 查看订阅、计划、运行及同步结果。工具返回能定位到具体对象的结果，不能将“已接收”描述为“同步完成”。

## 入口与操作

建议在 DSH 右侧栏注册独立“自动化”页面，使用已有页面注册和 docking 能力。页面包含三个视图：

1. **GitHub 订阅**：仓库、内容范围、启用状态、最后成功同步、关联计划；详情展示内容与版本、手动同步、修改范围、暂停/恢复。
2. **定时计划**：目标、周期或 Cron、时区、下次触发、启用状态、最近运行；提供创建、编辑、立即触发、暂停/恢复和删除入口。GitHub 扫描提供仓库与周期表单；自定义处理器暂不引入通用动态表单引擎。
3. **运行记录**：区分调度投递与实际同步；详情展示稳定运行 ID、来源计划/订阅、接收时间、开始/结束时间、页面和对象计数、重试等待、错误、取消及显式恢复。不能凭回执判定完成。

存储容量与阻断原因展示在订阅视图中；已有内容读取和消费回放在容量阻断时继续可用。消费游标的首版管理以工具为主，避免在运行列表里混入另一套消费状态。

外部 Issue/Discussion 正文按不可信文本安全渲染，保留来源链接，不解释为操作指令。凭证配置只接收已有环境变量引用，不把 token 放进工具参数、页面或返回结果。

## 工具入口

工具是公开服务的消费者，使用 Harness 已发布的 `defineTool`、注册、调用与结果展示机制；不拼接或执行 `/scheduler`、`/github-sync` 字符串。

功能分组（最终工具名按实现时的 schema 和可发现性细化）：

- 调度查询：列出计划、查看计划及其投递历史。
- 调度配置：创建与更新计划，校验固定间隔、Cron、时区和处理器参数。
- 调度管理：暂停、恢复、删除、立即触发与取消某次触发。
- 订阅查询与配置：列出/创建/更新订阅，查询同步内容和存储状态。
- 同步运行：手动发起、查询详情、取消、显式恢复原运行。
- 消费管理：注册消费者、读取、逐条确认与回放，沿用已有有序确认约束。

示例：“每两小时扫描 owner/repo 的 Issue 和讨论”“暂停这个仓库的自动扫描”“看看上次为什么失败”。agent 查询现有配置后调用相应工具，并返回仓库、计划/运行标识、可读状态和页面定位信息。

每个工具使用结构化 schema；actor 来自实际工具调用上下文，不能由模型传入任意身份。异步调用返回持久化运行引用与接收状态，后续查询返回实际进度。页面深链只在验证过宿主的资源导航协议后接入，不假设任意 URL 可以打开指定侧栏页。

## 技术边界

继续保持 `ctx.scheduler` 和 `ctx.githubSync` 为状态所有者。Web 请求和 agent 工具直接调用相同公开服务，复用取消墓碑、互斥、租约、分页检查点、容量阻断与恢复规则。入口各自记录真实来源，前端不写 SQLite，不维护额外业务状态机。

建议新增两个独立工具消费者包（scheduler-tool、github-sync-tool），以及自动化页面的 Web 接口和浏览器包（automation-web、automation-ui）。页面在某个能力未加载时清楚显示不可用；两个原始服务仍能独立加载。

Web 接口需沿用宿主的请求信任边界，验证输入和身份来源；不能因浏览器入口而绕开工具路径的业务约束。刷新只更新持久化状态的投影；请求失败时保留已显示数据并显式提示，恢复连接后重新读取。可见页面轮询或订阅通知，离开页面时释放监听与计时器。

## 验收

- 从自然语言经真实工具注册/调用创建订阅和计划，页面能读取相同结果。
- 页面与工具分别发起同步、暂停、取消和恢复，另一个入口能看到一致状态。
- 运行详情准确展示排队、运行、等待、成功、部分完成、失败与取消。
- 工具接收回执、HTTP 成功和通知均不能冒充同步完成。
- 页面有加载、空、不可用、错误与恢复状态；窄面板和全屏均可用，按钮和表单可通过键盘操作。
- 卸载后工具、Web 路由和页面注册释放；已接受的运行仍由原服务的生命周期处理。
- 使用真实 Loader、工具运行时、HTTP 接口、用户可见组件行为作为测试边界；仅替代外部 GitHub。
- 类型检查、lint、逐文件覆盖率、完整构建与打包通过后，安装到现有 `~/.dsh` web profile，并在真实浏览器验收。保留用户 profile 备份。

## 已确认的交互方式

- 独立“自动化”侧栏页面，参考 Devflow UI 的原生页面注册形式。
- 沿用已获同意的推荐方案：面板按钮直接调用公开管理接口，同时提供完整 agent 工具，共用业务服务。
