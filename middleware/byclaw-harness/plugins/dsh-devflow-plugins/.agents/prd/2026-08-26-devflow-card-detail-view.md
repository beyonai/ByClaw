# PRD — devflow:看板卡片详情视图与流转时间线

## Problem Statement

看板面板目前每张卡只有一行摘要(状态点、id、标题、阶段、七段进度条、revision),而系统里信息最密的两块内容在 Web 上完全不可见:

1. **需求正文看不到。** 聊天建卡沉淀的需求描述与验收标准写进了 `card.md` 的 Markdown 正文,`DevCard.body` 也已经在 Remote `read` 面上——但前端从未使用。要看"这张卡到底要做什么、验收标准是什么",只能回到聊天里问模型或去命令面敲 `/devflow show`。
2. **历史被折叠丢弃。** journal 是权威的完整历史——谁在何时把卡从哪移到哪、打回的原因、人工审批的签名、租约接管的记录——但读侧只折叠出当前状态,时间线在任何面上都展示不出来。"这张卡为什么被打回""上次是谁批的""现在谁拿着租约"这些看板最常被问的问题,今天都没有答案入口。

上一份 PRD 把"面板富视图"列为 out of scope;本 PRD 承接这个被推迟的方向,只做读侧的两层:详情视图(已上线数据)与流转时间线(journal 历史 + 租约持有者)。

## Solution

看板行变为可点击:点击一行,在会话区打开该卡的**只读详情抽屉**,分三段:

1. **需求书**:标题、id、放大的阶段流水线(七段进度条加阶段名标注,受阻卡标注受阻来源),`body` 的 Markdown 渲染(验收标准的 `- [ ]` 清单按只读清单呈现),已登记产物清单与卡片文件路径。数据来自**已存在**的 Remote `read` 面,零缝改动。
2. **流转时间线**:缝新增 journal 历史与租约持有者两个读操作,Remote 面以一次聚合调用取齐(卡 + 解码后的 journal 条目 + 当前持有者)。时间线逐条呈现 created/transition/artifact/claim-expired:执行者(human/agent 会话/command)、时间、边、打回 `reason`、审批签名 `gate.approvedBy`、接管的前任持有者;头部呈现当前租约持有者及其心跳新鲜度。每阶段停留时长、卡片总年龄、打回次数由客户端从条目派生,不进缝。
3. **会话反链**:时间线上 `kind: 'agent'` 的执行者按其 session id 渲染为可点击链接,点击切换到那次对话(客户端会话服务的既有打开能力);会话已不存在则退化为纯文本。

详情保持既有三面分工:**完全只读**,不提供任何移动、编辑或勾选;流转仍走聊天工具与 `/devflow`,审批仍走审批 composer。抽屉打开期间收到该卡的转发事件(`stage-changed`/`card-created`)即重取,详情与看板一样实时。

## User Stories

1. 作为开发者,我想点击看板行进入卡片详情,以便不离开 Web 就读到完整的需求正文与验收标准。
2. 作为开发者,我想让验收标准以清单形式渲染,以便一眼看出这张卡的完成定义。
3. 作为开发者,我想在详情里看到放大的阶段流水线与当前位置,以便比一行摘要更清楚地理解卡片进展。
4. 作为开发者,我想在受阻卡的详情里看到受阻来源阶段与最近一次受阻的原因,以便知道恢复后回到哪里、当初为什么停。
5. 作为开发者,我想看到完整的流转时间线——谁、何时、从哪个阶段到哪个阶段,以便追溯这张卡的全部历史。
6. 作为开发者,我想在时间线上看到每次打回的 reason,以便知道评审/验证阶段发现了什么问题。
7. 作为审计者,我想在时间线上看到人工审批的签名,以便确认哪些关键移动经过了人批。
8. 作为审计者,我想看到租约接管记录及被接管的前任持有者,以便理解卡片易手的经过。
9. 作为开发者,我想看到当前租约持有者与其心跳是否新鲜,以便知道"这张卡现在谁在干、是不是干着干着挂了"。
10. 作为开发者,我想看到每阶段停留时长与卡片总年龄,以便识别流程里的瓶颈阶段。
11. 作为开发者,我想从时间线上的 agent 执行者点击跳转到对应会话,以便回看那次移动前后的对话上下文。
12. 作为开发者,我想在详情里看到已登记的阶段产物清单,以便知道每个阶段交付了什么。
13. 作为开发者,我想让打开中的详情在卡片被移动时实时刷新,以便详情永远反映当前状态。
14. 作为开发者,我想用 Esc 或点击外部关闭详情回到列表,以便浏览多张卡时来回顺畅。
15. 作为浏览器用户,我不想让详情通道给前端任何传路径的能力,以便沿用既有的 Remote 安全边界。
16. 作为开发者,我想让详情严格只读,以便流转决策继续只发生在聊天面、命令面与审批 composer。
17. 作为开发者,我想让手写 journal 里不可解析的时间戳只是不显示时长而不是报错,以便脚本化建的卡同样能看详情。

## Implementation Decisions

- **第一层零缝改动。** 详情抽屉的需求书段完全使用既有 Remote `read(id, sessionId)`;点击行时拉取,不预取全量 body(列表保持轻)。
- **缝新增两个细粒度读操作,Remote 面聚合。** `DevflowStore` 增加 `history(id, root?)`(解码后的 `DevflowJournalEntry[]`,结构非法 fail-loud 同 read)与 `holder(id, root?)`(当前租约 `{ owner, heartbeatAt }`,无租约返回 undefined,损坏的 claim 文件 fail-loud);Remote 面新增一个聚合 `detail(id, sessionId)` 返回 `{ card, entries, holder }`,一次往返取齐抽屉全部数据。session→root 解析沿用上一切片的同一条 host 侧路径,浏览器仍只发 id。
- **派生指标在客户端。** 阶段时长、卡龄、打回次数由前端从 entries 计算;`at` 不可解析(手写 journal 的 `t1` 之类)则省略时长,渲染不失败。缝不新增任何统计接口。
- **Markdown 渲染复用。** 正文渲染复用客户端既有的 Markdown 渲染件;若 client 包纯度门禁不允许跨插件值引用,则按 ui-primitives 先例提取共享件,不在 ui-devflow 里重写渲染器。验收清单只读呈现,复选框不可交互。
- **抽屉形态与既有面板同构。** 与看板同一 body-portal 层,列表 ↔ 详情双态(详情内返回列表),Esc/外点关闭并归还焦点;344px 面板加宽为详情态或右侧抽屉,由实现按现有设计 token 定,不引入新 z-index 层。
- **实时性沿用整卡重取。** 打开中的详情在收到转发的 `devflow/stage-changed`/`devflow/card-created` 且命中当前卡时重取 `detail`;不做增量帧(与看板一致)。
- **会话反链用客户端既有打开能力**,不新增任何 Remote 面;目标会话不在列表中则渲染为纯文本 id。
- **不新增 Session 事件、不动写路径、不动工具与命令面**;`/devflow show` 保持现状,详情视图不是它的替代而是 Web 侧的对应物。

## Testing Decisions

- **缝**:`history`/`holder` 经 `DevflowStore` 公开面测——完整时间线解码回放、结构非法 journal fail-loud 指明文件与行号、无租约 undefined、损坏 claim fail-loud、多根下按 root 取历史。
- **Remote 聚合**:Definition 层沿用上一切片的测试姿势(真实 Remote 适配器 + 注入的 sessions/sessionPersistence 桩)覆盖 `detail` 的 session 解析、未知会话稳定拒绝与聚合结果拼装。
- **组件层 jsdom**:详情打开/返回/Esc 焦点归还、正文与清单渲染、时间线条目(含 reason、审批签名、接管)、持有者新鲜度、不可解析时间戳的降级、只读断言(除关闭与会话链接外无可交互元素)。
- **真实浏览器 e2e 增量**(沿用既有双工作区台子):点行开详情断言正文与时间线行;`/devflow move` 后打开中的详情实时出现新时间线条目;tripwire 无错误。
- 逐文件覆盖率、双语文档与 Agent Note 随各切片,遵循仓库既有门禁。

## Out of Scope

- 第三层整合:门禁预览(边上配置的 gate 命令与审批要求)、产物文件内容渲染、driver 实时执行状态、git 分支与变更统计;
- 任何写操作:勾选验收项、编辑正文、面板内移动或审批(沿用三面分工);
- 归档卡的详情与历史(`list` 不含归档卡,详情入口不存在);
- 时间线的增量推送(整卡重取已够);跨工作区聚合视图(维持前 PRD 的 out of scope)。

## Further Notes

- 切片建议:**012 详情抽屉**(点击行 → 抽屉,需求书段 + 产物清单,纯前端用现成 `read` 面,独立先行)→ **013 流转时间线**(缝 `history`/`holder` + Remote `detail` 聚合 + 时间线、持有者、会话反链、派生指标,依赖 012 的抽屉容器)。012 可先发布即有用户价值;013 不改 012 的需求书段。
- 兼容性:不触碰写路径与既有 Remote 面签名;`read` 面的既有消费者(`/devflow show`、工具)不受影响。
