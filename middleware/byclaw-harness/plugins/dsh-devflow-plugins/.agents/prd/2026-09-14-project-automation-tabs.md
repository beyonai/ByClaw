# 项目自动化与独立 GitHub 订阅页

状态：用户已确认并要求实现。基线：a5d0a6f。

## 问题

当前页面在会话侧栏中展示全主机计划和订阅，缺少项目归属。通用调度页同时承载 GitHub 内容，难以承接其他自动化能力，也无法可靠确定后续开发任务的项目。

## 目标

- 使用 Harness 工作区稳定 ID 表示项目归属，同项目不同会话共享计划与订阅。不同项目隔离；同 remote 的 worktree 不自动合并。
- 主机继续承担持久化调度与同步执行，关闭会话或页面不取消已接受的后台工作。
- 原生侧栏并列提供“自动化”和“GitHub 订阅”两个 Tab，保持“研发流程”不变。
- 工具、HTTP、命令、持久化服务统一项目边界，不允许只靠客户端过滤。

## 行为

自动化页展示当前项目的计划与投递记录，可创建、编辑、暂停、恢复、手动触发及取消。GitHub 订阅页展示当前项目的仓库订阅、同步内容和同步运行。订阅可跳转创建预填计划，计划可跳转关联订阅或同步运行；回执不表示同步完成。

浏览器只携带真实槽位会话 ID，服务端解析该会话工作区。工具从真实执行上下文解析项目，不接收模型自行指定的归属。无有效工作区时明确要求选择项目；不得退回全主机查询或写入。切换会话/项目后清空旧页面状态并终止旧读取，迟到响应不得覆盖新项目。

计划和订阅创建时持久化归属；查询、内容、历史、消费游标和更新/取消/恢复均检查项目。GitHub 调度计划与订阅必须属于同一项目，创建、修改和投递时均校验。基础服务可保留显式可信内部管理入口，但人类与工具入口必须使用项目范围。

旧记录保留为未归属，通过明确的认领操作绑定当前项目；不得自动关联。认领应处理已有历史关系并防止两个项目并发认领。未归属记录不得继续自动执行。跨两个数据库的关联认领可分步操作，绑定前不得执行，错误应可恢复。

底层磁盘容量仍为主机共享资源，界面和工具需明确标注范围，不能误称项目配额。

## 验收

1. A 项目两个会话共享记录；B 项目看不到 A 的计划、订阅、内容、运行或消费进度。
2. 猜测 A 的对象 ID 后，B 的工具及 HTTP 修改/取消/恢复/消费操作均被拒绝；创建跨项目关联也被拒绝。
3. 缺失或无效会话工作区不产生全局操作。
4. 真实原生侧栏出现两个独立 Tab；跨页跳转保持项目与对象上下文。
5. 旧库迁移保留数据，认领可审阅且并发安全；未认领自动工作停用。
6. 切项目、慢请求、错误重试和卸载均不泄漏旧状态。
7. Node 24、类型、lint、真实 Loader 组合测试、逐文件覆盖率、构建及 tarball 检查通过。
8. 隔离 profile 验证两个项目和 UI；备份后安装本地 profile，保留用户状态。
