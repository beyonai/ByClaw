# Agent Note: 通过现有门禁执行 Midscene Web 验收

Status: proposed

## 问题

Devflow 需要绑定源码、套件和运行构建的浏览器验收证据。仅有退出码不能证明检查了预期 UI。旧插件不能证明它兼容当前 Harness 契约。

## 提案

新增单独安装的 Midscene 技能和独立 CLI。Harness 管理 shell 作业；Devflow 管理产物和状态迁移。每次执行在 Git 工作区外记录源码标识、实测构建标记、有限用例结果、清理状态、可用用量及报告链接。完成门禁发起新执行。这扩展了 [testenv runbook 决策](../../implemented/feature/2026-09-11-testenv-retreats-to-runbook-skill.zh.md)，不取代原记录。

## 考虑过的替代方案

**先移植原生工具。** 这会在证明验收行为前扩大兼容范围。原生工具保留为 M2，以 M1 真实验收通过为前提。

**仅使用 MCP。** 调研中的 Midscene MCP 包已退役；初始集成需要明确的进程归属和持久证据。

**恢复 testenv 执行器。** 这会重复选定本地基线已经移除的生命周期职责。

## 验收标准

真实 SDK/Chromium 测试必须覆盖成功、失败、取消、输入变化和报告。真实 Loader/技能及 shell/工具/存储/门禁组合必须证明登记和重新执行。Tarball 必须包含 CLI、worker、共享代码块与技能资源。仓库检查必须通过。

M1 还需要在预期 Devflow UI/profile 上完成真实视觉模型验收，包括刻意失败和可达报告链接。受控模型响应不满足这一条件。M2 等待这些证据。参见 [PRD](../../../prd/2026-09-14-devflow-midscene.md)。

## 风险

报告可能包含应用数据，项目负责保留政策与托管。进程丢失时结果未知，不能静默恢复，因为重放可能重复副作用。Token 用量是测量，不是费用预算。实现与验证仍在进行，本记录保持 proposed。

## 认证部署修复

正式运行新增工作区外的私有 Playwright 登录快照和部署记录。记录把 commit、工作区指纹与本地 web/UI 产物计算的 buildId 绑定。运行时使用带认证的 POST JSON 探针，在用例前后校验实际提供的客户端字节；实例或输入变化不能通过。该 buildId 明确覆盖 web index 和客户端 bundle，完整部署包集仍另存哈希。

报告入口通过已发布 session 服务解析会话工作区，与管理员配置的输出目录及持久运行身份匹配，只提供明确登记的产物。拒绝符号链接、路径穿越和私有临时目录；HTML 在没有同源权限的 sandbox 中运行。重启后仍能读取证据，但历史报告不能替代新门禁执行。

Midscene 1.12.6 即使借用 Chrome 也会启动独立 CDP 代理。清理必须将私有 PID 记录与固定代理脚本、目标端点比对，停止该代理，再独立关闭自有 Chromium 或断开借用连接；用户 Chrome 进程不是清理目标。无法确认所有权或清理时不能产生通过证据。

显式崩溃恢复除代理/浏览器外，还记录原宿主与当前官方命令进程。原宿主存活时拒绝恢复，宿主退出后只停止命令身份匹配的遗留进程，登记 interrupted 证据而不重放操作。真实独立宿主在官方 CLI 模型请求期间被 SIGKILL 的测试证明恢复会停止遗留命令及浏览器。Bridge 无法证明资源所有权时仍保留 unknown。

## 官方 Skills 与托管执行

修复增加了固定版本官方浏览器 Skill/CLI 的薄适配（Midscene 1.12.6，Skill commit dec1d1c55252ecb1a90c4ecbcfd0d2cb3ce0ac7b）。五个工具根据真实会话解析工作区，复用 Harness 服务提供预检、探索、已批准套件执行、记录检查和中断清理。因此，早期将所有原生工具延后的提议不再适用于此次修复范围；仍不引入第二套工作流状态机。

每个托管子进程清除继承的 MIDSCENE 配置，重新解析凭证引用，并明确端点和视觉模型家族。正式套件必须与配置目标同源。必需具名 validator 不可用时拒绝，在 shell 检查之后执行，并在后续批准完成后复核输入与部署身份。历史成功不能批准新的完成请求。

真实宿主退出测试在官方 CLI 等待模型时终止独立宿主，再验证显式恢复只清理记录中的 CLI、代理与自有 Chromium。恢复不重放动作，也不将中断记录改为通过。

### 审批结束时的新鲜度补充

正式验收清单现在记录实际目标进程实例。下游审批结束后，以原始私有登录快照执行一次仅 HTTP 的认证探测，在业务转换提交前核对源码、suite、部署凭据、构建、实际提供的 UI 字节和目标实例。即使构建字节相同，目标进程重启也会使先前验收失效。复核必须使用原始内存中的运行结果，恢复的 JSON 证据不能替代。回归覆盖审批期间重启和探测期间取消。

源码指纹仅排除根目录 `.devflow` 运行状态，创建、认领和转换卡片无需重新构建应用；嵌套或名称相近的路径仍参与指纹。正式 suite 若实际解析到被排除的运行目录则拒绝，包括符号链接别名。真实 Git fixture 验证运行状态修改不影响源码身份，而应用和 suite 修改会使身份失效。

最终审阅修复两处实际缺口：模型和登录秘密统一使用同一脱敏函数，短本地 key 不再破坏 JSON 常量；最终审批在提交前同时检查原始报告是否仍可读取。真实认证 HTTP、Git 和文件系统回归证实，审批期间删除报告或重启目标都会使转移证据失效。
