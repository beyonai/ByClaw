# Agent Note: devflow — 侧边栏看板以阶段为中心

Status: implemented

[English](2026-08-31-devflow-stage-centric-kanban.md) | 中文

> 本记录于 2026-09-08 被[官方右侧栏接入方案](2026-09-08-devflow-official-right-sidebar.zh.md)部分取代。
> 下文的 Kanban 投影与响应式布局决策仍然有效；关于悬浮面、`dsh-better-sidebar`、
> 并列视图设置以及 Harness `0.1.2-alpha.x` 运行时验收的内容仅描述旧宿主。

## Problem

完整侧边栏页面以任务为行，并在每一行重复七段流程。这种表达能解释单张卡片走过的路径，却要求读者扫描每一行才能回答看板最主要的问题：每个阶段有多少工作。重复流程条也挤占了受阻状态和需求拆分的视觉空间。

子任务也不能直接平铺到各列。脱离父需求的子任务失去存在理由，而把父卡和子卡都渲染为普通任务会把同一份工作计算两次。

## Decision

完整侧边栏以七个 `DevStage` 作为 Kanban 列，并保留紧凑列表作为替代视图。浮动入口继续使用紧凑列表，因为受限浮层无法给七列提供可读宽度。

`blocked` 继续是旁路，不成为第八阶段。受阻卡片显示在 `blockedFrom` 对应列，带明确的警告标签，并计入该列数量。缺少来源阶段的异常持久化数据进入明确的兜底区域，卡片仍然可见。

有子卡的顶层卡成为可折叠泳道标题。子卡只在其当前阶段列出现一次，标题承载父卡阶段和子任务分布。独立顶层卡与找不到父卡的子卡进入独立任务泳道，因此不完整关系不会隐藏卡片。

浏览器保持只读。卡片继续打开现有需求、关系、产物、持有者和 journal 详情；流转仍由模型、命令和审批面负责。

窄屏优先进入有工作的“开发中”；该阶段为空时进入第一个非空阶段。没有当前阶段卡片的“独立任务”空壳会隐藏；父需求标题及其阶段分布继续显示，保证父子上下文不丢失。

宽屏网格继续显示全部七个阶段，但不再让空阶段与繁忙阶段等权占宽。全局为空的阶段收缩为带名称和计数的窄列；有任务的阶段共享剩余宽度，较宽的阶段单元使用自动适配子网格铺开卡片。卡片标题限制行数，长 ID 在卡片内省略，并通过原生悬停标题提供完整值。

## Alternatives considered

**只保留任务中心的进度列表。** 它保留现有紧凑度，却仍然难以阅读阶段负载和受阻集中位置，无法实现引入看板的目标。

**增加包含 `blocked` 的第八列。** 这种表达很直接，但会把临时旁路变成正式流程阶段，并让受阻工作脱离仍被它占用容量的来源阶段。

**把父卡和子卡平铺到同一组列。** 渲染更简单，但要么把父卡重复算成工作项，要么删除每张子卡的需求上下文。

**加入拖拽流转。** 这会越过浏览器只读边界，还需要在 UI 中处理 revision 冲突、Gate、审批和拒绝恢复；现有流转面已经拥有这些决策。

## Testing

- 纯投影测试固定阶段归位、受阻来源、异常兜底数据、独立卡与孤儿卡、父需求泳道、稳定排序和计数。
- React 测试固定七个列头、响应式阶段选择、父泳道折叠、子卡只出现一次、已完成展开、紧凑列表替代视图、空阶段自适应列宽、长文本边界和不变的详情导航。
- 浏览器绑定测试继续覆盖会话作用域、实时刷新、并列详情与两套面选择。首次读取失败提供重试；已有成功看板时后台刷新失败保留上一版数据。
- 打包后的 bundle 已通过 Harness `0.1.2-alpha.3` 当前的 `dsh-client-store`、`dsh-client-ui-renderer` 与 `dsh-api-session-controller` 边界启动。悬浮面与真实侧栏容器均已验收；后者使用面向 Harness `0.1.2-alpha.x` 的 `dsh-better-sidebar@0.18.0-alpha.0` alpha 通道。

## Consequences

七列需要横向空间，因此窄布局必须使用单阶段表达。列表响应不含阶段进入时间、持有者或 WIP 限额；看板省略这些值，不进行推断。Gate 历史仍是详情事实，不预测下一次流转是否通过。

因此列宽同时表达当前负载与阶段顺序：空阶段仍可找到，但会有意变窄。全局任务分布变化时列宽随之调整，而阶段顺序、名称、计数和卡片归位保持稳定。

以阶段为中心的页面只取代[侧栏面决策](2026-08-26-devflow-board-sidebar-surface.zh.md)与[需求拆分决策](2026-08-26-devflow-requirement-breakdown.zh.md)中的侧栏渲染方式。两者的面所有权、层级模型、只读边界和详情契约继续有效。悬浮面有意保留紧凑列表，因为受限浮层无法容纳七个可读列。
