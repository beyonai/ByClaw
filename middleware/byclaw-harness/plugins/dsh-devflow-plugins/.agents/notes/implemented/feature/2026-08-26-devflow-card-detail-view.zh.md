# Agent Note：devflow——看板行打开只读卡片详情

Status: implemented

[English](2026-08-26-devflow-card-detail-view.md) | 中文

## 问题

看板每卡只有一行摘要,而系统里信息最密的两块在 Web 上不可见:聊天建卡写进 `card.md` 的需求 Markdown(早已在 Remote `read` 面上、从未被消费),以及 journal 历史(下一个切片交付)。想知道"这张卡到底要做什么",只能离开 Web 去敲 `/devflow show` 或回聊天里问。

## 决策

点击看板行,在同一个 body-portal 面板内把列表切换为该卡的只读详情(面板加宽,头部带返回控件,Esc/外点/收起关闭整个浮层并连带收掉详情)。需求书渲染身份信息、标注全部阶段名的放大流水线、经 ui-primitives 共享 `MarkdownText` 渲染件呈现的 `body` Markdown——无需提取渲染器,该共享件本就存在且本包本就依赖 ui-primitives——GFM 任务清单的复选框天然禁用,外加产物清单与卡片文件路径。

插件在看板 source 旁再持有一个可观察 source(`detail`:关闭 / 加载中 / 已加载),slot inject 携带两个意图(`openCardDetail`、`closeCardDetail`),组件保持纯渲染。每次打开经既有 Remote `read(id, sessionId)` 拉取一次——缝与线上零改动;打开中的详情随每次看板刷新(转发的 devflow 事件)一同重取,过期的落定绝不覆盖更新的状态(以落定 id 与当前快照比对,守住打开/关闭/再打开的竞态),失败或 reject 的拉取关回列表,切换会话关闭详情(卡片属于旧工作区)。

流转时间线从缝侧扩展同一个抽屉:`DevflowStore` 新增两个细粒度读操作——`history`(完整的已解码 journal,流校验与读取完全一致,坏掉的 journal 在两个视图里同样 fail-loud)与 `holder`(租约事实,未认领为 `undefined`,损坏记录 fail-loud)——Remote 面把它们与读值聚合在一个 `detail(id, sessionId)` 调用后,经同一条 session→root 解析路径,抽屉因此只花一次往返、浏览器仍然只发 id。时间线从新到旧渲染每条记录的执行者(加载时客户端会话列表认识的 agent 会话经客户端会话服务自己的 `open` 成为反链;消失的会话保持纯文本)、打回原因、审批签名与接管记录;卡龄、逐条停留时长与打回次数由客户端从条目时间戳派生,手写时间戳不可解析时静默消失——缝没有长出任何统计 API。

## 曾考虑的替代方案

- **在 344px 列表里做手风琴展开** — 拒绝:需求 Markdown 与(下一切片的)时间线需要文档宽度;双态面板保持一个锚点一个层叠上下文。
- **随列表预取正文** — 拒绝:列表保持轻摘要;正文按打开拉取,加载态显式呈现。
- **dialog/modal 层** — 拒绝:面板已拥有 portal、关闭处理与 z-index 槽位;再开一层等于三者全部重复。
- **history/holder 各自单独的 Remote 线上调用** — 拒绝:抽屉永远同时需要三个值,聚合放在 Remote 适配器(一次往返),缝保留其他消费者可组合的细粒度操作。
- **缝侧统计面(时长、打回次数)** — 拒绝:所有指标都能从线上已携带的条目派生;呈现层数学留在客户端。

## 后果

Web 上不离页即可回答"这张卡是什么""谁在何时为何移动它""现在谁拿着它",且仍不发出任何变更——抽屉里唯一可操作的元素是返回控件与会话反链。行变成了按钮(原"无按钮"只读断言改为"每行恰好一个打开钮、无输入")。
