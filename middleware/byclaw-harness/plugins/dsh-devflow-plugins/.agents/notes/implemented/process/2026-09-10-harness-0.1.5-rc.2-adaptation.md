# Agent Note: Harness bump to `0.1.5-rc.2`, and the two breakages nothing marked

Status: implemented

## Problem

This line pinned every `@deepseek-ai/*` dependency to `0.1.3-alpha.2`, per
`AGENTS.md`'s "Harness version" rule. DeepSeek Harness published `0.1.5-rc.2`
(tag `dsh-v0.1.5-rc.2`), 846 commits later.

**Not one of those 846 commits carries a `!` breaking marker.** The previous
bump could read the four `!`-marked session commits and predict what would
break. This one could not: the commit log promised a clean bump, and the test
suite reported 152 failures across 23 suites. Where the last bump's research
step was reading commit subjects, this one's was running the suite against the
new version and reading the wreckage.

The type plane was clean at the same moment — `tsc -b --force` reported zero
errors while 152 tests failed. That combination is itself the diagnosis: what
moved was runtime exports and field names, not the type contracts the compiler
checks against `skipLibCheck`.

## Decision

Every `@deepseek-ai/dsh-*` dependency moves to `0.1.5-rc.2` — 226 entries
across the root manifest (18), all 19 `packages/*/package.json` (139), and the
`minimumReleaseAgeExclude` list in `pnpm-workspace.yaml` (69).

`0.1.5-rc.1` was the intermediate stop: every breakage below sits in the
`0.1.3-alpha.2` → `0.1.5-rc.1` window. `rc.1` → `rc.2` is four commits — a Web
UI backport touching `ui-chat`, `ui-deliverables`, `ui-message-feedback`,
`ui-primitives`'s `CodeFileIcon`, and the feedback packages. The `src` of every
package this line consumes (`ui-slots`, `ui-renderer`, `client-store`, `agent`,
`session`, `connection`, `ui-sidebar-right`) is byte-identical across that step,
and the bump needed no code change: every gate passed on the version move
alone.

`cordis` (`4.0.2`), `cordis-plugin-include` (`1.0.7`), `cordis-plugin-loader`
(`1.0.3`), and `schemastery` (`^3.18.1`) are unchanged.

`pnpm install` added one new transitive package to `minimumReleaseAgeExclude`:
`dsh-chunked-list@0.1.5-rc.2`, pulled in by a pinned package rather than
depended on here.

## The three version lists, and the phantom errors

The bump is written in **three** places, not one:

1. `packages/*/package.json`
2. `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`
3. the root `package.json` devDependencies

Changing only the first two left 18 `0.1.3-alpha.2` copies installed under the
root. TypeScript then resolved declaration merging against those copies and
reported six errors of the form "slot does not exist" and "namespace does not
exist" — errors naming the new surface, produced entirely by the old. All six
vanished on aligning the third list; none named a real change.

`node_modules` and `pnpm-lock.yaml` must be deleted before reinstalling.
An incremental install keeps the stale copies alive and the probe keeps lying.

A related dead end is worth naming so it is not retried: while the third list
was still stale, `dsh-settings@>=0.1.5 <0.2.0-0` failed to resolve, which looked
like a peer-resolution problem. Turning off `auto-install-peers` "fixed" it and
broke the runtime instead, by dropping `dsh-http-proxy` and other genuine peers.
The root cause was the same stale third list; with all three aligned, **default**
pnpm settings install cleanly and no pnpm configuration changes.

This rule is now in `AGENTS.md`'s "Harness version" section.

## What the bump broke, and what replaced it

Two breakages, both in tests, neither marked upstream.

| Removed / changed | Replacement used here | Sites |
|---|---|---|
| `Inbox` is no longer a runtime export, only a type | `emptyInbox()` in `tests/agent-double.ts` | 17 suites |
| `surfaceOp` replace fields `start` / `end` renamed `startSeq` / `endSeq` | the new names | 1 (`devflow-iron-rules`) |

**`Inbox`** accounted for 148 of the 152 failures — 97%, all reading
`Inbox is not a constructor`. `@deepseek-ai/dsh-agent` now declares it as an
interface (`packages/core/agent/src/runtime-types.ts`, reached over
`1101422362 refactor(agent): keep concrete inbox loop-internal` and two
neighbours) and exports no factory. The harness owns construction; a plugin
composing against published surface has no way to make one.

Nothing in any `src/` referenced `Inbox`. Only test agent stubs did, each
building an `Agent` object to give a command, tool, or gate a caller. The
replacement is one shared double in `tests/agent-double.ts`, restating the
`Inbox` interface with empty queues and methods that **throw**. Returning
plausible values would let a suite silently depend on stub behavior; throwing
means the first suite that actually drives agent input fails and says so.

**`surfaceOp`** was renamed by `657e68186a fix(session): canonicalize V3
envelopes through adjacent migration`. The harness validates the field set by
exact key match, so the old names produce a runtime rejection, not a type error.
One test carried a literal.

## The client transitive dependencies

Three published harness client packages import npm packages their tarballs do
not declare: `dsh-client-store` imports `zustand`, and the renderer chain
reaches `clsx` and `anser`. Under pnpm's strict layout the importing package
cannot resolve them, and the suites fail at import time.

The fix is local and stays local: `devflow-ui` declares `zustand`, `clsx`,
`anser`, and the markdown/highlight chain the renderer bundle expects. This is
compensation for an upstream packaging gap, not a devflow requirement, and it
should be withdrawn when those tarballs declare their own dependencies.

## The sidebar restatement stays a restatement

`packages/devflow-ui/src/client/sidebar-right.ts` restates the right-Sidebar
contract. Its stated reason — the harness package is unpublished — is no longer
true: `@deepseek-ai/dsh-client-ui-sidebar-right` is published at `0.1.5-rc.2`,
and `AGENTS.md` ranks a real dependency above a restatement. The switch was
attempted and measured, and it does not work.

The tarball declares no dependency beyond `@deepseek-ai/cordis`, while its
`.d.ts` imports `dsh-client-ui-dockkit` and `dsh-client-ui-layout/client`. Those
reach `dsh-brand`, `dsh-client-store`, `dsh-client-ui-slots`, and
`dsh-client-ui-theme`; the last reaches `dsh-client-ui-settings` and the **host**
package `dsh-host-webserver`. Consuming the real contract means pinning that
whole graph inside an independently published browser plugin, and pulling a host
webserver package into a client type graph.

The failure mode if it is pinned incompletely is worse than the work: under
`skipLibCheck: true` — which this repository sets — an unresolvable import
inside a `.d.ts` produces **no diagnostic**, and every type from it silently
becomes `any`. A partial pin therefore compiles green while `TabRecord`,
`PaneId`, and `TabHookContext` are all `any`.

So the restatement stays, and what changes is its honesty:

- the module doc now states the real reason and the `skipLibCheck` consequence;
- every place the copy is narrower than the original says so at its
  declaration — `SidebarRightTabDefinition` omits `patterns` / `priority` /
  `canOpen`, `SidebarRightTabInfo` omits `panel` and the dockkit `TabRecord`
  members, `hookContext` is left `unknown` because the board registers a body
  and never a hook factory;
- `SidebarRightGuideEntry.description` becomes optional, matching the original.

Two package READMEs carried the "not yet published" claim in prose and in a
Known Limitations entry; both now describe the dependency-declaration gap
instead.

## Alternatives considered

**Depend on `dsh-client-ui-sidebar-right` and pin its graph.** Rejected on the
measurement above: seven-plus packages including a host package, in a plugin
whose whole premise is depending only on published surface. Reconsider when the
tarball declares the dependencies its types require.

**Keep the restatement and say nothing.** Rejected: a restatement whose stated
reason is false is worse than no comment, because the next reader acts on it.

**Vendor a real `Inbox` implementation for tests.** Rejected. The suites never
drive agent input, so an implementation would be untested code that exists to
make an object look real. The throwing double is smaller and fails louder.

**Turn off `auto-install-peers` to resolve `dsh-settings`.** Rejected — it
treated a symptom of the stale third list and broke genuine peers. Recorded
above so it is not retried.

## Consequences

- Consumers composing at `0.1.3-alpha.2` cannot take this release: the
  `peerDependencies` move with everything else.
- `devflow-ui` carries npm dependencies that exist only because harness client
  tarballs under-declare theirs. Each is a candidate for removal, not a
  permanent part of this plugin's dependency set.
- No local boot regression was run against a real `0.1.5-rc.2` Web profile. The
  READMEs say so rather than inheriting the previous version's claim. Note that
  `rc.2`'s only substantive change is Web UI, which is exactly the surface a
  boot regression would exercise.
- The `rc.2` tarballs still under-declare: `dsh-client-ui-sidebar-right` names
  only `@deepseek-ai/cordis`, and `dsh-client-store` names nothing at all. Both
  compensations below therefore stay.
