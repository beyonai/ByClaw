# Agent Note: Harness bump to `0.1.2-alpha.3`, and the `dsh-client-runtime` split

Status: implemented

English | [中文](2026-08-31-harness-0.1.2-alpha.3-adaptation.zh.md)

## Problem

This line pins every `@deepseek-ai/*` and `cordis*` dependency to one exact
prerelease (`0.1.1-rc.2` / `cordis@4.0.1`), per `AGENTS.md`'s "Harness
version" rule. DeepSeek Harness's `master` moved 1430 commits ahead of that
pin (to `dd6322d604`, tag `dsh-v0.1.2-alpha.3`), and `npm view <pkg>
versions --json` showed every dependency this line uses had a published
`0.1.2-alpha.3` — except `@deepseek-ai/dsh-client-runtime`, which has no
`0.1.2-*` release because the harness removed it
(`be531688f3 refactor(client): migrate consumers and remove Runtime`,
`3a23185edb chore(client): align split package graph`). Held at
`0.1.1-rc.2`, this line would depend on a package that will never publish
its target version again — the "Bad" case
`.trellis/spec/dsh-devflow-plugins/versioning.md` already named.

## Decision

Every `@deepseek-ai/*` and `cordis*` dependency across every
`packages/*/package.json` (not just the root manifest and `devflow-ui`,
which is as far as the originating design doc enumerated) now pins
`0.1.2-alpha.3` (`cordis` `4.0.2`, `cordis-plugin-include` `1.0.7`,
`cordis-plugin-loader` `1.0.3`). This repo's own package versions are set to
`0.1.2-alpha.3` to match, via `pnpm run set-version 0.1.2-alpha.3`.

`@deepseek-ai/dsh-client-runtime` is dropped. This repo's actual usage of its
surface (found by `grep -rl 'dsh-client-runtime' packages`, then confirmed
against the harness's last pre-removal source at
`packages/client/runtime/src/client/index.ts`) split three ways:

| Old symbol (from `dsh-client-runtime/client`) | New source | Kind |
|---|---|---|
| `ClientContext` | `import type { Context as ClientContext } from '@deepseek-ai/cordis'` | type-only |
| `SlotRegistry` | `@deepseek-ai/dsh-client-ui-renderer/client` | value (class) |
| `createSnapshotStore`, `SnapshotStore` | `@deepseek-ai/dsh-client-store` (root entry — this package ships no `./client` subpath) | value + type |
| `SettingsScope`, `SettingsScopeSnapshot` | `@deepseek-ai/dsh-client-ui-settings/client` | type-only |

`packages/devflow-ui`'s six call sites (`src/client/{binding,index,board}.ts`,
`tests/{harness-doubles.ts,browser-plugin.client.spec.tsx}`, and its own
`package.json`) now import from these successors instead.

**`packages/devflow-ui/package.json`'s `dsh.client.inject` array carried a
third, unenumerated reference to `dsh-client-runtime`** (the design doc's
grep-based call-site list found only the `devDependencies` and
`peerDependencies` entries). This array is the harness loader's mount-order
declaration — the packages whose `ctx` services must exist before this
plugin's `apply()` runs — not an import list, so it cannot be inferred from
`tsc`. `devflow-ui`'s plugin body declares `inject = ['sessions', 'slots',
'locale']`; `dsh-client-runtime` used to provide both `sessions`
(`SessionRuntime`) and `slots` (`SlotRegistry`) at once. Diffing
`3a23185edb` across several harness packages that migrated the same
`inject` array (`ui-commands`, `ui-goal`, `locale`, `ui-brand-official`, …)
showed the consistent successor mapping: `slots` now comes from
`@deepseek-ai/dsh-client-ui-renderer`, and `sessions` comes from
`@deepseek-ai/dsh-api-session-controller` (confirmed by grep for
`rootCtx.reflect.provide('sessions', ...)` in the harness source, which now
lives in `packages/api/session-controller/src/client/sessions/service.ts`,
not in a runtime-adjacent package). `devflow-ui` now declares both as
`peerDependencies`/`devDependencies` and lists both (plus the
already-present `dsh-client-locale`, `dsh-client-ui-conversation`,
`dsh-client-ui-primitives`) in `dsh.client.inject`.
`@deepseek-ai/dsh-client-store` needs no loader-ordering entry — its
published shape is a plain node/ESM library (`main`/`exports['.']` only, no
`dsh.client` key), not a `dsh.client` plugin, so it is only a regular
dependency plus a browser-bundle module-table entry.
`@deepseek-ai/dsh-client-ui-settings` stayed a `devDependencies`-only
entry: every usage found (`SettingsScope`, `SettingsScopeSnapshot` in
`tests/harness-doubles.ts`) is `import type`, confined to tests, never
shipped in `devflow-ui`'s own type surface.

The browser-bundle module table (`tsdown.client.ts`'s `MODULE_TABLE`,
`tests/loader-factory.ts`'s `STATIC_TABLE`, and `vitest.config.ts`'s
`CLIENT_BUNDLES`) now serves `@deepseek-ai/dsh-client-store` (plain import,
not `/client`) and `@deepseek-ai/dsh-client-ui-renderer/client` in place of
`dsh-client-runtime/client`. `tests/loader-factory.ts` needed the plain
`dsh-client-store` addition for an unrelated-looking reason: once loaded,
`@deepseek-ai/dsh-client-locale/client`'s own published bundle internally
`require()`s `@deepseek-ai/dsh-client-store` (the harness's own `locale`
package picked up the same successor during its `3a23185edb` migration), so
the recursive module-table resolver threw until this repo's own table could
answer that request too — this is exactly the "a bundle requiring something
the table does not serve throws here" case `tests/loader-factory.ts`'s own
doc comment names, not a defect in this repo's usage.

## Other breakage the bump surfaced (not in the design doc)

Two unrelated upstream changes landed inside the same `0.1.1-rc.2 →
0.1.2-alpha.3` window and broke `typecheck`/`test` independently of the
`dsh-client-runtime` split; both were confirmed by pickaxing
`/workspace/deepseek-harness` rather than patched blind:

- **`@deepseek-ai/dsh-llm`'s `CallId` was renamed to `ToolCallId`**
  (`a789637db6 refactor(llm): rename CallId to ToolCallId`, a pure rename,
  same semantics). Two test files constructed a `SubagentStartRequest` by
  hand and called the old name: `packages/devflow-tool/tests/loader-composition.spec.ts`
  and `packages/devflow-fs-guard/tests/guard.spec.ts`.
- **`@deepseek-ai/dsh-client-ui-primitives`'s `MarkdownText` gained a
  required `labels: MarkdownLabels` prop** (`3c10f5d2d3 fix(client): route
  UI copy through locale`), replacing a narrower `codeLabels` prop.
  `packages/devflow-ui/src/client/board-view.tsx` now builds the label set
  with a local `markdownLabels(t)` helper mirroring the harness's own
  `packages/client/ui-chat/src/client/markdown-labels.ts` adapter: `t('copy')`,
  `t('copied')`, and `t('markdown.footnotes')` resolve through this
  package's own namespace-bound `t`, which already falls back to the
  harness's shared `common` locale namespace (`LocaleKeysOf<N> =
  (LocaleNamespaceMap[N] & string) | CommonKeyOf`) — no new dictionary
  entries were needed, `@deepseek-ai/dsh-client-locale` ships `copy`,
  `copied`, and `markdown.footnotes` in its `common` dictionary already.
- **`@deepseek-ai/dsh-subagent`'s `SubagentCapabilities` gained a required
  `agentOptions: boolean` field**, and its service now rejects a
  `SubagentStartRequest.agentOptions` sent to a provider that does not
  declare the capability. `devflow-agent-gate`'s checker dispatch
  (`packages/devflow-agent-gate/src/index.ts`) always sent `agentOptions`
  (the deployment's default model/provider route) unconditionally; it now
  gates that the same way it already gated the tool filter
  (`checkerAgentOptions`, mirroring the existing `checkerToolFilter`): a
  provider without the capability dispatches with whatever provider/model
  it defaults to on its own, rather than faulting the whole check. The test
  double in `packages/devflow-agent-gate/tests/checker-provider.ts` now
  declares `agentOptions: true` by default (parameterizable, like
  `toolFilter`), because every existing spec in this package assumes model
  routing reaches the checker; the two inline provider literals in
  `fail-closed.spec.ts` and `fault.spec.ts` declare `agentOptions: false`
  since those fault-injection specs never assert on it.

`.trellis/spec/dsh-devflow-plugins/versioning.md`'s Good/Wrong/Correct
examples described the split as `dsh-client-store` + `dsh-client-connection`
+ `dsh-client-modules` + `dsh-client-hmr` — the harness's full split, not
this repo's actual dependency surface. That file's examples are corrected in
the same change as this note, per its own "Source of truth" instruction.

## Alternatives considered

**Scope the dependency bump to only the two files the design doc
enumerated (`package.json`, `packages/devflow-ui/package.json`).**
Rejected: `AGENTS.md`'s own "Harness version" rule and this PRD's
acceptance criteria require every `@deepseek-ai/*`/`cordis*` pin across the
workspace to move together, and `pnpm`'s per-package dependency resolution
means a package left at `0.1.1-rc.2` would silently keep resolving the old
harness surface for its own build, not the new one — the exact
"drift" `pnpm run preflight` is built to refuse.

**Hold `checkerAgentOptions` at "always require the capability" and fail
closed when a provider lacks it.** Rejected: the existing `toolFilter`
capability already treats absence as "dispatch unrestricted, not a fault,"
and a checker fault parks the card `blocked` — a much larger cost than
routing to whatever provider/model default the provider itself picks.

## Consequences

`pnpm run verify` (typecheck + lint + test) and `pnpm run preflight:tarballs`
both pass at the new pins. The dev-channel publish (`<version>.dev.<sha>`)
and the release publish are separate, still-unconfirmed steps per the
versioning spec — this change only prepares the pinned dependency graph and
this repo's own version, it does not publish either channel.

The `sessions`/`slots` ambient `Context` merges `devflow-ui`'s
`src/client/index.ts` relies on now arrive through explicit type-only
imports (`import type {} from '@deepseek-ai/dsh-client-ui-renderer/client'`,
already-present `dsh-client-locale/client`, and transitively through
`dsh-client-ui-conversation/client` for `sessions`) rather than through one
package that happened to declare all three. A future harness package that
stops re-exporting one of these ambient merges would surface as a `tsc`
error on the matching `ctx.<service>` access, the same way this bump's
`Context.slots` regression did.
