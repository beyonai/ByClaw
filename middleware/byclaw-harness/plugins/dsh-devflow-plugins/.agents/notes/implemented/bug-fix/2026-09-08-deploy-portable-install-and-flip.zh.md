# Agent Note: deploy 默认惰性安装，并在 GNU 与 BSD 主机上原子切换

Status: implemented

[English](2026-09-08-deploy-portable-install-and-flip.md) | 中文

## 问题

安装 `@zhchxiao123/dsh-devflow-deploy` 会加入一条已启用但没有配置的 Loader 行。插件正确地
要求 `host` 与完整的驱动布局，因此 Cordis 会在 profile 启动前拒绝该行。bundle patch
把这种状态称为惰性，但从唯一重要的结果看它并不惰性：一次未配置安装会阻止 Harness 启动。

静态驱动的原子符号链接切换还使用了 GNU 专属的 `mv -T`。真实远端命令测试会在本机执行
该命令，所以 macOS 上的每个部署场景都会在到达待测行为前失败。只改成 BSD 专属形式，
不过是把不兼容挪到 Linux。

## 决定

随包安装的 `deploy` 行默认禁用。profile 只有在同时提供完整服务器与驱动配置时，才启用
同一行。这样安装过程可撤销、可启动，也不需要编造危险的地址默认值；直接用代码组合时，
配置不完整仍然响亮失败。

静态切换仍然先暂存一个新符号链接，再用一次重命名覆盖在线链接。它先尝试 GNU
`mv -fT`；该选项形式不可用时，改用 BSD/macOS `mv -fh`。两种形式都会阻止把指向目录的
目标符号链接当作目录跟随，因此在两类受支持的 Unix 系统上仍保持原子重命名。Windows
远端主机依然不受支持。

## 考虑过的替代方案

**给部署路径提供默认值。** 否决：猜测的主机或服务目录可能把内容发布到错误位置。缺失
部署知识意味着能力应保持禁用，而不是把知识编造出来。

**先删除在线符号链接，再移动暂存链接。** 否决：这很便携，却会制造一个访问者看到目标
不存在的时间窗，破坏静态驱动声明的原子回滚等级。

**只用普通 `mv -f`。** 否决：GNU `mv` 在未提供 `-T` 时，可能把指向目录的目标符号链接
当成目录处理。仅在 macOS 通过不够，同一命令不能在 Linux 上变义。

## 后果

单独安装本包不再破坏无关 profile；运维者必须显式激活部署能力。profile patch 由此成为
授权部署目的地的审计点。

静态部署与回滚会在 GNU 和 macOS 两种命令语义下真实执行切换，同时保持原有 release
布局与原子回滚承诺。fallback 刻意只覆盖 Unix 工具；支持 Windows 服务器需要另一套远端
协议，而不是再加一个 flag 分支。
