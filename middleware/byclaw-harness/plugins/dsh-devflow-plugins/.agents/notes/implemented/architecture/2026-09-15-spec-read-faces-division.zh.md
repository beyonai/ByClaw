# Agent Note: spec 的几个读取面是一次分工，不是一个缺失的工具

Status: implemented

[English](2026-09-15-spec-read-faces-division.md) | 中文

## Problem

`devflow_read_spec` 需要一个 id，而 spec 缝上没有任何东西接受一个 scope。spec-tool 的 README 把这条记作名为「No index tool」的已知限制，而一次针对多模块仓库的真实运行恰好问出了它预言的那个问题：`customers-service` 都覆盖了什么？

那条限制条目错在最要紧的地方。它只给出一条替代路径——单卡结果上的 `specRefs` 索引——而那条路需要一张卡、一次 `spec-refs` 登记，因而需要 `dsh-devflow-artifact-gate`，而这一行在默认组合里是**禁用**的。真正默认开着、且已经回答了这个问题大半的那个面——`dsh-devflow-spec-sentinel` 的 `devflow-spec-map` pre-step 索引——一个字没提。照字面读，这条条目教的是：默认组合下模型无从得知一个 scope 覆盖了什么。事实相反：它在每一步之前被告知，不必发问。

## Decision

**不做按 scope 列举的工具，两个 plane 都不做。** 四个读取面作为一次分工写进了 [spec-tool 的 README](../../../../packages/devflow-spec-tool/README.zh.md)，限制条目改为陈述真正缺失的东西，而不是陈述「某样东西不是一个工具」：

- `devflow-spec-map` pre-step 索引——这次会话触达过的文件被哪些文档主张，以及这些包还有哪些文档。模型面，推送，默认开，不花工具调用。一个 scope 只能靠会话真正发生过的第一方 `read`/`write` 进入它；每层 64 条触达记录；渲染按字节封顶，且**先丢 scope 层**并声明丢弃。
- 单卡结果上的 `specRefs`——这张卡声明的前缀下有哪些文档。模型面，默认关，受四道门约束。
- `/devflow spec` 普查——全集健康，加上每个期望 scope 的三态裁决与可锚文件计数。人面，不接参数。
- `devflow_read_spec`——一篇文档的正文。模型面，按需应答。

### 触发本次评估的那个问题是一个 coverage 问题

那次运行问的是 `customers-service` 覆盖了什么。同一份证据记录着：该 scope 当时**一份文档都没有**——八个模块里只有两个有。按 scope 列举会回答一个空清单。「这个 scope 够不够」是 coverage，由[覆盖普查](2026-09-14-spec-coverage-verdicts.md)在人面持有，并且已经被写进 bootstrap 技能作为它的完成判据。

### 「全集普查与索引不给正文的纪律相反」的两种读法

`docs/devflow.md` 把这句话作为普查不做成模型面工具的理由，而这是全仓对该理由的唯一一处陈述。它是压缩表述，两种读法对普查都成立：病在**未被收窄**（模型面拿到的索引必须由相关性收窄——由卡片自己的前缀，或由会话触达的文件），或者病在**它根本不是索引**（索引行指向可读的正文，而普查的 `no document` 一行不指向任何东西；计数、三态与密度是判断面，不是指针面）。

按 scope 列举在两种读法下都会一分为二，而且断在同一处：

- **返回索引行，两种读法都落不进去。** 收窄来自调用者给的 scope，走的是 `specRefs` 已经在用的同一次 `store.list(prefix)`，而每一行都指向一次 `devflow_read_spec`。
- **区分「空 scope」与「没人期望的 scope」，两种读法都落进去。** 只有期望集能回答它，而期望集是普查的。
- **报告豁免落得最深。** 豁免由住在**另一个** scope 下的文档声明，因此要回答就必须列出全集再扫 `waives`——从机制上说就是一次全集普查，而不是「像」一次。

于是这样一个工具本应承担的内容纪律，恰好是该跟着普查走的那一半；而不跟着走的那一半，已经被推送索引与 `specRefs` 服务了两遍。中间不剩下什么值得建的东西。

### 它本会花多少，以及一条关于成本的错误论证

满足那份纪律的工具，紧凑 schema 约 1366 字符，约 340–380 token，**在插件挂载期间每一次请求都常驻**——约为本包现有两个工具字面量的一半再多。pre-step 索引没有可比的常驻成本：`contextMaxBytes` 是上限而非下限，无话可说时它渲染为空并离开 prompt，且 harness 只在它变化时重发。

**「全集 `list()` 太贵所以不能上模型面」是假的，此后任何论证都不得靠在它上面。** pre-step 索引在每一个 model step 之前都做一次无参 `list()`，由 store 按 stat 键的解析缓存撑住。普查独有的昂贵动作是可锚文件的目录树遍历，而那次遍历早已被限定在人面命令上。**普查留在人面的理由是纪律，不是算力。**

## Alternatives considered

**一个 `devflow_list_spec({ scope })` 模型工具。** 否决，卡在「Require a current owner and need」。现有各面唯一漏掉的场景，是去问一个本会话未触达、也没有卡片声明过的 scope，而这件事没有当前调用者：bootstrap 路线按定义工作在没有文档的 scope 上，增量开发者按定义已经读过该 scope 的文件。代价那边是每请求常驻的 token，以及 spec-tool 对哨兵的 workspace 服务新增一条可选依赖——它需要那个期望集。

**让 `devflow_read_spec` 接受前缀。** 否决。一个工具时而返回正文时而返回清单，读者得先判形状才知道拿到了什么；而 `read(id)` 对不存在的 id 是抛错，列举却必须回答「空」——一个工具两种含义，而两个工具更省读。

**把当前 scope 的文档挂到每一条单卡结果上。** 否决。它让每一次卡片操作多付一次 `list()` 与一次全量 freshness 重算——`specRefs` 索引已知的成本就是这条——换来一个多数调用用不上的字段，而且「当前 scope」从一张卡推不出来。

**人面的 `/devflow spec <scope>`。** 否决，但若本决定被重审，它是第一个该被重开的候选——它不花模型预算，机器也都现成：`spec` 分支接一个可选 scope，`coverageExpectation()` 回答「期望之内但为空」与「不在期望之内」，豁免 map 回答豁免态，`documented` 分支把今天只计数的那些 id 打出来。它输在自己能补的缺口太小。一个人今天已经拿得到：每一份非 fresh 文档的 id 与失效锚、每一份豁免文档的 id、每个 scope 的文档计数与密度，以及 `ls .devflow/spec/<scope>/` 给出的 id 本身——一篇文档的权威就是文件加 git。它唯一新增的事实是「按 scope 分组的 fresh 文档 id」，这抵不上一处命令解析改动、一处普查渲染改动、四个测试用例、一对双语 README 和一份 note。

**每个 scope 手写一份 `index.md`。** 在本次评估之前就已否决：纯目录文档没有可锚的东西，会被 `no-anchors` 拒绝；而 `list()` 已经从 frontmatter 算出的索引再抄一份，必然与它漂移。

## Consequences

**除散文之外什么都没有落地。** 没有任何包增加表面，因此覆盖率与组合不受影响；spec-tool 的 README 双语对及其一致性记录就是这次改动的全部。

**下一次提议面对的是一道门槛，而不是一条要重走的路。** 点名一个必须去问「本会话未触达、也没有卡片声明过的 scope」的调用者，才重开这件事；重复那个触发问题不算，因为那个问题由 `/devflow spec` 回答。

**`docs/devflow.md` 里那句压缩表述保持压缩。** 它的两种读法都支持本决定，因此替作者消歧等于代他做判断，本次改动不做。若出现与两种读法都相悖的第三种读法，本决定重新可议。
