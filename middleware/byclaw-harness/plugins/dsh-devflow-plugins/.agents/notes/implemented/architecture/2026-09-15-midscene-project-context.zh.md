# Agent Note: Midscene 项目上下文与模型调用

Status: implemented

## 问题

将工作区路径和模型凭证放在宿主级验收 profile 中，会让项目切换容易出错。页面检查成功也可能没有关联任务证据或必需的完成策略。

## 决策

发起请求的会话提供规范化工作目录。可选选择与已评审用例保存在 `.devflow/midscene`，私有回执与输出保存在源码树外。静态探索返回带来源的候选项。Harness Agent 使用已有 shell/jobs 准备服务并确定实际地址，不仅凭监听端口判断应用身份。

经过认证、按运行隔离的本机桥接将固定版本 Midscene 协议转换为 DSH 已发布的 LLM 与附件调用，凭证由 DSH 管理。模型选择固定，每个请求单独取得适配器调用绑定。不支持的协议字段和被缩放的截图明确失败。公开 LLM 接口不能在整个多请求运行期间固定同一个适配器版本。

绑定工具校验任务、源码、用例和已有部署回执，对变化的绑定请求审批，并在审批后检查新鲜度。它先持久化必需验收策略，再发布项目设置。门禁引擎独立于 Midscene 提供者读取策略，因此卸载提供者会阻止完成。任务存储提交日志前，最终检查再次验证证据与策略。

项目报告通过可选服务确定输出目录，沿用现有 Web 鉴权与产物检查。普通运行通过任务存储关联生成的 Markdown；门禁运行不重入任务产物串行写入。

## 考虑过的替代方案

**原样迁移全局 profile 到其他文件。** 仍会保留重复路径和模型凭证，也无法解析发起请求的任务与模型。

**提取 Provider 的 API Key 和地址。** 已发布 LLM 适配器拥有自己的传输行为；复制内部配置会绕过 Provider 行为与凭证生命周期。

**将应用可访问视为部署证据。** 响应的服务可能运行另一份源码，因此正式验收保留部署回执和运行时探针。

**只注册内存中的项目要求。** 卸载提供者可能同时移除义务，独立读取的项目策略能够保留该义务。

## 后果

普通探索不需要全局 profile 或重复模型密钥。持久化选择通过受校验工具和有界原子写入维护。独占修改锁避免更新丢失；宿主崩溃后可能需要确认锁的 owner 已退出再移除。可移植 Node 文件系统检查不能提供对抗同用户恶意替换上级目录的内核事务。

首次正式绑定仍需真实部署证据。探索是静态的；服务启动和认证登录使用 Agent 已有项目流程。可控适配器测试证明协议、浏览器和存储组合，不能证明某个付费模型的视觉效果。真实部署验收仍单独验证。
