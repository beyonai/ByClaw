# Agent Note:devflow —— 卡片可以停下,而留下来的是那个理由

Status: implemented

[English](2026-08-31-devflow-reasoned-abandonment.md) | 中文

## Problem

`done`是唯一的终态,而`archiveDone`只收`done`卡,于是"这个不做了"、"已经过时"、"和 0007 重复"、"被取代了"都没有一个如实的落点。现有的两个答案都是谎言:把卡停在`blocked`,让一个意思是*有人在等某件事*的列慢慢堆满没人在等的东西;或者标成`done`,污染`done`所承载的那唯一一个信号。

## Decision

除`done`外任意位置的卡片都可以**被放弃**,并且必须附带理由。journal 记录这件事,卡片离开活跃看板。

**不加新阶段。** `DEV_STAGES`保持封闭,所以看板的列、持久化的阶段枚举、两处工具 schema、以及客户端的那份镜像都不动。而"被放弃的卡离开看板而不是占住一列",在语义上也更诚实:没人在做它,以后也不会有。

**理由是必填的**,而 transition 的理由是可选的。transition 之后卡片仍然可见、仍能从它所在的位置被解释;而放弃把它从看板上移走,理由就是这个决策留下的全部。空白理由在任何写入发生之前就被拒绝。

**`done`卡被拒绝。** 已交付的结果由`archiveDone`了结,而不该被一个"决定不交付"覆盖掉。

## 提交点与崩溃窗口

journal 追加是提交点;把目录移进归档发生在其后,正如投影重写发生在已提交的 transition 之后。因此两者之间的崩溃会留下一张仍在`tasks/`下的已放弃卡片。

`list` 依据**折叠状态**排除已放弃的卡,而不是依据它的目录在哪。这让看板在那个窗口内依然正确,也让目录移动成为清理动作,而不是承载语义的那一步。

`foldJournal` 把该条目视为终态:其后的任何条目都会让回放失败,正如`created`只能出现在首位。这正是"不能靠往 journal 里追加来悄悄复活一张卡"的保证。

## 归属

放弃是一个决策而非执行,所以它落在`/devflow`——确定性的人工干预平面——并且没有对应的模型侧工具。Harness agent 推进工作,但无权决定工作停止。

## Alternatives considered

**加一个`dropped`阶段:不做。** `DEV_STAGES`在持久化 journal 校验、`DevCard` schema、两处工具 schema、以及客户端包里一份手工维护的镜像中都是承重的。付出这些代价换来的,是给一批再也不会有人碰的卡片留一列——而那正是这份 note 要消灭的假 WIP。

**复用`blocked`:不做。** 它已经表示*被打断、将会恢复*——它的恢复规则就是 blocked 卡必须回到它离开的那个确切阶段。让它同时表示*永久停止*,会导致两个意思都读不出来。

**恢复一张被放弃的卡:不做。** [归档按设计就是只写不读的](2026-08-27-devflow-stage-model-rigidity.zh.md);没有任何操作能列出或恢复一张归档卡。推翻一个"停止"的决定是新工作,也就是一张新卡。

## Consequences

**前向兼容是刻意放弃的。** `decodeJournalEntry`遇到未知`type`会抛错,所以带有放弃条目的 journal 对早于本次改动的版本不可读。暴露面很窄,因为该条目只存在于已归档的目录里,而没有任何东西会去读它——唯一的窗口就是上面描述的崩溃。这一点在同一发布线内被接受,并记录在此,而不是留给别人去发现。

`archiveDone`未变,包括它的父子月份归桶。被放弃的卡按自己最后一条条目的月份归档;它不是 done 卡,也不加入家族桶。

**已知缺口:父卡在子卡仍存活时被放弃。** parent gate 管的是完成,不是放弃,所以没有东西阻止它。每张子卡仍可按自己的方式被读取和归档。要管住它,就得先回答"放弃一个需求是否等于放弃它的所有切片",而这是本次改动没有回答的产品问题。
