# Agent Note:devflow —— 卡片的服务类别决定它走哪条流水线,跳过边由此站得住脚

Status: implemented

[English](2026-08-31-devflow-service-class.md) | 中文

## Problem

每张卡都要走满七个阶段。改一行文案的卡要经过 `designing` 与 `ready`,一起生产事故也一样。门禁一直是配置,但**遍历本身**不是,于是唯一的提速手段是 `/devflow move` —— 人工干预平面。这才是值得点名的失败:**当流程表达不了紧急,逃生口就落在被记录的流程之外**,而被丢掉的恰恰是最需要它的那一刻的审计线索。

[刚性 note](2026-08-27-devflow-stage-model-rigidity.zh.md) 审视过这一条,给出的答案是**"跳过边:不加"**,理由是统一流水线就是产品本身,而跳过边一旦存在就会变成默认路径。本 note 取代它的**这一条**备选答案。那份 note 的另外两个答案 —— 它落地的返工修复,以及拒绝重开 `done` —— 继续有效。

## Decision

卡片携带一个**服务类别**,创建时固定,决定它可以走哪些边。共三个,词表封闭:

| 类别 | 新增 | 放弃 |
| --- | --- | --- |
| `standard`(缺省) | 无 | 无 |
| `express` | `draft->developing`、`reviewing->done` | 设计、就绪、独立验证 |
| `emergency` | `draft->developing`、`developing->done` | 以上,外加评审 |

`express` 刻意保留同行评审:在这里可用的控制手段里,它是唯一对得起自己成本的那个,所以廉价工作省掉的是设计轮次,而不是有人把代码读一遍。`emergency` 连它一起放弃,代价用一张普通的后续卡来还 —— 而不是在状态机里编码一条义务,那不过是套着字段名的第二个编排器。

### 为什么原来的反对意见不再成立

反对意见是:跳过边会变成默认路径。回答它的是两条结构性质,而不是自觉:

- **词表封闭。** 部署方无法自造更短的类别。这三个名字由 Definition 拥有,理由和 `DEV_STAGES` 一样:看板、两份语言文档、agent 的工具描述都在引用它们,而部署方自定义的类别会让上述每一处引用都变成局部的。让部署方自行定义,**正是**原反对意见所担心的那种漂移。
- **类别创建后固定。** 工作开始后,卡片无法被降级进快车道,所以"这事太慢了"永远不能靠重新分类来解决。升级意味着新开一张 `emergency` 卡,而原卡留在看板上,如实说明自己是什么。

原答案给出的退路 —— "真心想要更短流水线的部署,可以让中间阶段不设门禁" —— 在成本上是对的,在语义上是错的。不设门禁的阶段照样让看板对着一张没人在设计的卡片说 `designing`,而这正是那份 note 在返工问题上拒绝接受的同一种错报。

## 边模型

`FLOW` 未变。第二张表只存每个类别**新增**了什么([`stages.ts`](../../../../packages/devflow/src/stages.ts)),于是"每个类别都是 `standard` 的超集"成为代码的性质而非约定:类别无法删除任何一条边,因此也就无法让今天能回放的 journal 停止回放。`isLegalTransition` 收下移动中卡片自身的上下文,两个生产调用点都把卡片整个传进去。

没有任何捷径是返工边 —— 它们都向前跳 —— 所以 `isReworkEdge` 及其 `reason-required` 契约一个字都不用改。

## 持久化格式

`serviceClass` 完全照抄 `parent`:写进 `created` 条目、折叠进读侧状态、投影进卡片文件的 frontmatter、永不改指。它**在盘上可选、在内存里必填**:条目字段与 frontmatter key 只在类别不是 `standard` 时写入,而未声明类别的条目折叠为 `standard`。

于是:classes 出现之前写下的 journal 原样回放;`standard` 卡的首条 journal 行与卡片文件与不知道 classes 的旧代码写出的**逐字节相同**;读侧没有任何消费者需要判缺失。取值非法则在持久化边界大声失败,而不是降级处理。

## Alternatives considered

**类别配置化:不做。** 那是把问题搬家而不是解决它 —— 部署方自定义的类别集就是"跳过边变成默认路径"这个失败再加一层,而且会让看板和 agent 提示引用某种局部的东西。

**允许改现有卡的类别:不做。** 升级确实真实存在,但可变类别会把审计线索变成一句关于现状的断言,而不是一份关于"当时决定了什么"的记录。新开一张卡的代价是一次创建,而两个事实都留下来了。

**给 `emergency` 加事后复审义务:不做。** 把"你欠一次评审"编码进状态机,会让插件变成编排器。真实的事故实践本来就把复盘当作独立工作项,而现成的父子关系已经能承载它。

## Consequences

每条类别新增边都是普通的 `from->to` 键,所以 `'draft->developing'` 和 `'developing->done'` 可以像任何其他边一样承载产物契约、agent 检查或门禁命令。一个类别跳过的阶段**不是**被绕过的门禁:卡片根本不经过那条边,也就没有契约可逃。

`devflow_list` 保持紧凑 —— 类别只在非 `standard` 时报告,所以普通行原样不变,走短流水线的行被标为 `<express>` / `<emergency>`。看板遵循同一条规则,这意味着一个既有部署在自己创建出第一张短流水线卡片之前,看不到任何新的视觉噪声。

回滚就是回退代码:`express` 与 `emergency` 卡此后读作 `standard`,这低报了它们的意图,但每一份 journal 仍可回放。正是这种不对称,决定了字段只在携带信息时才落盘。

看板的浏览器包现在在既有的 `DEV_STAGES` 与 `isReworkEdge` 副本之外,又复述了一份 `DEFAULT_SERVICE_CLASS`,适用同一条规则:与原件的分歧就是副本的缺陷。
