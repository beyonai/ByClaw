# Agent Note：项目自动化页面与工具消费者

状态：已实现

[English](2026-09-14-automation-sidebar-tools.md) | 中文

## 问题

全主机管理视图无法确定订阅归属或后续开发任务所在项目。通用调度页同时展示 GitHub 内容，也使导航依赖单一处理器。

## 决策

计划和 GitHub 订阅归属于已有 Harness 工作区的稳定 ID。会话提供项目操作入口，主机负责执行。关闭页面或会话不取消已接受的后台工作。不同工作区身份的 worktree 保持独立，即使 Git remote 相同。

共享的 automation-project 解析器使用真实会话的 cwd 和已发布的工作区注册服务。HTTP 接收会话 ID，不接受文件路径或客户端自行指定的项目归属。工具与命令从调用上下文解析项目。上下文缺失时明确失败，不退回全主机操作。持久化服务按项目过滤读取并检查操作归属，包含消费游标与运行恢复。GitHub 计划在配置和投递时验证订阅属于同一项目。创建、修改和认领计划要求处理器当前可用；已有计划可等待卸载的处理器恢复。工具在异步解析工作区后、修改状态前再次检查取消信号。

原生右侧栏注册两个并列页面。“自动化”管理计划和投递历史；“GitHub 订阅”管理订阅、纯文本内容与同步运行。原生导航携带关联订阅或运行，不改变项目归属。现有研发流程看板保持并列。页面状态属于对应的会话与 Tab，迟到的读取不能替换另一项目的状态。

旧记录保持未归属，直到显式认领。每个服务在自身数据库中原子完成认领，保留历史并保持自动执行暂停；恢复需显式操作。两个数据库中的关联记录可分别认领，但归属一致前计划不能执行。存储容量仍是主机共享资源，并明确标注。

## 考虑过的替代方案

**只在 UI 筛选。** 工具、猜测的对象 ID 和排队工作仍可能跨项目操作。

**用 Git remote 或会话 ID 表示归属。** 一个远程仓库可以服务多个项目，一个项目也可以包含多个会话。两者都不能表示需要的持久化范围。

**每个会话独立数据库。** 会重复保存状态，使后台工作与对话耦合，并违背项目内共享的要求。

## 影响

调度与同步继续保持独立的服务定义、实现和消费者。人类及工具入口读取相同的持久化结果。投递已接受和同步已完成仍是不同事实。查看未归属记录属于显式迁移动作；普通项目查询不包含未归属或其他项目记录。删除工作区注册不会把记录重新分配给获得新 ID 的替代工作区。

## 验证

Node 24.18.0 / pnpm 11.24.0：134 个测试文件、1,687 项测试通过。全仓库逐文件语句、分支、函数和行覆盖率均为 100%。TypeScript、清理后构建及 30 个包的 tarball 预检通过；lint 无错误，有三条既有的未使用 disable 警告。

真实 Loader 组合使用已发布的工作区注册服务、文件系统领域存储与会话持久化，验证同项目多会话、跨项目读写、消费访问及恢复。回归测试拒绝处理器缺失时配置、校验期间卸载处理器，以及工作区解析期间取消后写入。

隔离的打包 profile 暴露 19 个真实工具和两个原生侧栏页面。浏览器验证在项目 A 创建订阅、跳转自动化预填计划、触发并通过完成记录返回 GitHub 同步运行，再切换项目 B 验证空列表。最终 tarball 也通过真实 HTTP 拒绝跨项目同步和计划关联。GitHub 响应使用本地回环 fixture；未进行真实模型请求或远程 GitHub 账号操作。
