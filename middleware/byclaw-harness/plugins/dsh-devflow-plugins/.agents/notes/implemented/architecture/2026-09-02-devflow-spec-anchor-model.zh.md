# Agent Note: 把架构文档系在它所描述的代码上

Status: implemented

## Problem

devflow 有卡片、产物与门禁，却没有地方安放寿命超过一张卡的知识。「域拒绝 resolve、基础设施失败 throw」这样的规则属于某个包，不属于恰好确立它的那张卡。没有归宿，每张卡要么重述一遍，要么依赖 `AGENTS.md` 那种一刀切的注入。

显而易见的做法——每个包一个 Markdown 目录——有一个比它所填补的空缺更糟的失效模式。一篇已经与代码脱节的架构文档不只是没用：agent 读了它、信了它，然后照着一条早已不成立的规则写代码。引用 `types.ts:195-197` 的散文看起来很严谨，其实不是；没有任何东西检查那些行号是否还有意义。**过期的 spec 比没有 spec 更危险，因为它自信地错着。**

## Decision

`ctx.devflowSpec` 是与 `ctx.devflow` 平级的能力缝，不是它的一部分。文档存放在 `.devflow/spec/<id>.md`，frontmatter 加正文，每条实质论断都落在一个声明过的 **anchor** 上，store 在每次读取时对其求值。

三类 anchor，取舍标准是：把一条论断系在**足以证伪它的最窄的那个东西**上。

- `symbol` —— 该名字必须仍被声明。抓改名与删除，而这正是大多数词汇与结构类论断的失效原因。
- `content-hash` —— 该符号经解析器规范化后的体，其摘要必须不变。抓「名字没动但实现变了」。
- `churn` —— 该文件不得在文档之后被提交。给没有解析器读得懂的文件用的粗粒度 anchor。

规范化会去掉注释**与语句分号**并折叠空白。注释经 TypeScript 扫描器剥离而非正则，因为正则分不清字符串字面量里的 `//` 和真注释。分号被去掉，是因为它是各工具最常有分歧的那个格式维度——如果一次格式化加上分号就把全仓 anchor 打成过期，结果只会是教会所有人忽略这个信号。

**`AnchorVerdict` 是三值的。** `unevaluable` 如实呈现，绝不折叠进 `fresh`：不在 git 工作树内时 churn anchor 判不了，没有解析器读得懂的文件也挂不了 symbol anchor。**一个再也跑不动的校验不是一个通过了的校验。** `worstFreshness` 汇总时 `stale` 压过 `unevaluable`，因为一个确定的失败盖得住任意多个未知。

**省略的 `content-hash` 摘要由 store 补齐。** 本线之外没有调用方算得出「对解析器规范化后的体取摘要」这个值——模型当然更算不出——因此强制要求它，等于让最强的一类 anchor 通过模型平面根本用不了。补齐发生在 Provider 的 `write` 里，与其它实现方默认值并列，而不在工具里：跨包协作走缝，绝不走值导入。找不到的符号会让摘要留空，写入以 `anchor-unresolvable` 被拒。

**写入时每个 anchor 都必须求值为 `fresh`。** 一篇文档不得一出生就是过期的。正是这一条规则让此后的新鲜度报告可信：一个 `stale` 裁决永远意味着代码动了，而不是这篇文档从一开始就是错的。

### 结构契约止步于机制的边界

写入路径机械校验 id 合法性、`## Source of truth` 小节、至少一个 anchor，以及**双向的**引用关系——每个声明的 anchor 都被引用，每个引用都有声明。只查一个方向，就会让文档要么攒下无人依赖的 anchor，要么让论断落在从未声明过的 anchor 上。

它刻意**不**校验「每条实质论断都挂了 anchor」。那是自然语言判断，属于流转边上的 LLM 准入门禁，不属于结构校验；把查不了的规则塞进机械层，只会产出一个假装严格的校验。

## Alternatives considered

**把 spec 文档做成一种 artifact kind。** 否决。artifact 登记不可变、恰好属于一张卡、随卡归档。而 spec 文档可变、属于一个包、寿命长过每一张碰过它的卡——与 artifact 契约的三条核心承诺全都不匹配。而说明「这张卡触及哪些文档」的**引用清单**是另一个对象，它确实契合 artifact 的形状，两者因此被拆开。

**把 spec 状态放进卡片 journal。** 否决。journal 的权威来自它可回放；文档的权威是文件本身加 git。混在一起会让回放去回答它无权回答的问题，也会让引入或移除本缝改变已提交卡片的回放结果。**spec 不进 journal，正是本缝回滚零代价的原因。**

**行区间 anchor。** 否决——那正是要修的失效模式，不是修法。行号会随其上方的任何编辑漂移。

**照 `dsh-iron-rules` 用路径存在性做腐化检测。** 因不足而否决。那个包自己的文档把限制写得很直白：一条规则的 grep 全部不再匹配、而被监视路径都还在时，它完全看不见。它同时指出两条真正的出路——把 git churn 与规则自身的修改时间对比，以及要求每条规则附一个已知违规样本。本设计取第一条作为 `churn` 类型，第二种失效模式改用 `content-hash` 覆盖，因为参考型文档没有「违规样本」这回事。

**为将来的语言预留可插拔求值器接口。** 依据「Require a current owner and need」否决。今天没有第二种语言的消费者，那个抽象就是要长期维护、却无人读取的表面。**这是一笔明知的技术债**：第二种语言到来时，要拆到接口后面的是 `anchor-eval.ts` 与 `normalize.ts` 两个模块，而需要按语言分派的只有 `symbol` 与 `content-hash` 两类——`churn` 本来就与语言无关。这笔债后来正是在这道缝上还清的：[多语言 anchor 求值 Agent Note](../feature/2026-09-13-spec-anchor-multilang.md) 记录了这次拆分及其背后的 Python 与 Go 求值器，[Rust 与 Java](../feature/2026-09-14-spec-anchor-rust-java.md) 随后经同一道接口跟上。

## Consequences

本缝的**代价**是 Provider 对 `typescript` 的硬依赖，以及一条明说的限制：`symbol` 与 `content-hash` 当时只在 TS/JS 上工作，其余一律只能用 `churn`——这条限制后来收窄到没有求值器的语言，Python、Go、Rust 与 Java 已经通过上文那条备选预留的缝加入。它还带来一条天真设计不会有的拒绝路径——anchor 解析不通的文档根本写不进去。

它**换来**了整个想法赖以成立的那个性质：**一篇会报告自身腐坏的文档**。`packages/devflow-spec-tool/tests/loader-composition.spec.ts` 用真实 Loader 组合端到端证明了它——写一篇文档、改掉被锚定的符号、把同一篇读回来得到 `stale`。

把根放进 `.devflow/` 之内，白得了第二重保证：`dsh-devflow-fs-guard` 已经按目录名匹配拒绝文件工具写入该子树，因此「store 是唯一写路径」是被强制的而非仅仅本意如此，且无需任何额外配置。守卫的拒绝消息现在按目标分支，写 spec 的人会被指向 `devflow_write_spec`，而不是指向写不了他那个文件的卡片工具。

**没有求值缓存。** 每次读取都重新解析被引文件。形态已设计好并记在 Provider 的 README 里，但目前还没有任何消费者的规模需要它。
