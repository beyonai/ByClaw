# Agent Note: Midscene CI portability and lint project discovery

Status: implemented

## 问题

带类型检查的 lint 无法解析被最近的 TypeScript 项目排除的测试和脚本。即使源码构建通过，缺失类型信息也会产生数千条 `error` 类型诊断。真实进程测试还涉及 Windows 路径、权限、文件系统错误和进程树语义，本地 macOS 通过不能证明这些行为。

## 决策

每个包的测试都有可发现且禁止输出文件的 `tests/tsconfig.json`。新增项目继承 `tsconfig.tests.json`；根目录脚本和辅助代码通过本地配置继承 `tsconfig.tools.json`。生产构建引用和 lint 规则保持不变，删除因类型信息缺失而添加的过时抑制注释。

夹具使用原生路径操作，ESM 导入使用 `file:` URL。权限测试遵循读取器现有合约：Unix 检查 POSIX 权限位，Windows ACL 策略由宿主管理。报告渲染测试的外层预算覆盖验收及第二个浏览器，不改变验收截止时间。恢复夹具暴露子进程进度和结果，保留真实模型请求、杀死宿主及进程退出断言。

Worker 单元测试传入测试专属的生命周期及 IPC 宿主；生产使用独立 worker 进程。测试不替换测试运行器的进程监听器、发送函数或连接状态。共享 Vitest 的 IPC 通道可能意外取消 worker，使未消费的模拟响应污染下一个测试。测试间重置模拟状态，断言监听器隔离和移除，并要求重启检测完成两次构建探测。真实进程测试仍使用真实 IPC 和进程终止。

自有浏览器通过 Playwright 准备持久上下文页面，在导航前应用登录状态，等待页面加载及成功截图，再将已渲染页面交给官方 CLI。CLI 在 `domcontentloaded` 后立即截图，可能在托管 macOS 上因渲染尚未就绪而失败。浏览器启动、CDP 连接、导航及截图共用剩余操作预算；取消或过期会阻止下一步。借用浏览器保留原有连接路径。清理失败会在结果中保留脱敏后的原因，而非仅报告未知清理状态。

Windows 清理先终止已记录的浏览器进程树，再终止其父进程树，避免重叠的 `taskkill /T` 竞争。两个根进程共享截止时间，首个命令为第二个预留时间。若调度已耗尽预算，剩余尝试使用正数 1ms 超时；零会禁用子进程超时。代理元数据缺失时还须检查父路径，因为 Windows 在父路径是文件时也可能返回 `ENOENT`。临时目录不存在仍是正常状态；元数据不可访问则拒绝确认清理。

恢复记录为命令、代理和浏览器阶段保存固定诊断原因；恢复没有模型凭证上下文，因此不发布任意异常消息。Windows 所有权查询成功但结果为空时，仅在确认 PID 已退出后接受该状态；仍存活且身份不匹配的进程绝不会被终止。

## 考虑过的替代方案

**关闭不安全类型 lint 规则。** 这会同时隐藏类型解析失败和真实的不安全操作。可发现的项目为现有规则提供所需输入。

**跳过 Windows 浏览器测试。** 这会让已支持的清理和所有权行为缺少验证。按平台调整夹具断言可以保留相同的可观察保证。

**重试无诊断的恢复失败。** 子进程诊断是区分基础设施故障和清理缺陷所必需的。本地通过不足以证明托管 CI 行为。

## 影响

lint 可以解析包测试，无需将测试加入生产声明构建。根目录 typecheck 命令仍检查生产和工具项目，不代表对每个包测试独立检查。仍须运行完整跨平台 CI；一台机器的测试和覆盖率通过不能证明托管 Windows 或 macOS 的行为。
