baiying-enhance Hub Skill 同步与动态加载方案

本文说明 baiying-enhance 如何支持百应数字员工 relSkills 的新对象格式， 如何自动发现 ByaiService、按版本下载 hub skill，以及 OpenClaw 如何基于 agents.list[].skills 做 skill 动态加载过滤。

目标

兼容新旧 relSkills 旧格式字符串数组继续可用；新格式对象可以表达内置 skill 与 hub 下载 skill。
按版本自动更新 每次托管 agent 全量同步时请求 versionUrl，仅在版本变化或本地缺失时下载。
动态加载过滤 只把 agent 需要的 skillCode 写入 agents.list[].skills， OpenClaw 按该列表过滤加载。

方案边界很明确：relSkills 负责声明数字员工要使用哪些 skill； hub 同步模块负责把 hub skill 安装到全局 skill 搜索目录； OpenClaw 运行时负责在构建 agent 上下文时按 skills 列表选择实际加载哪些 skill。

relSkills 数据格式

支持三类输入，最终都归一化为 OpenClaw 的 skill 名称列表。

1. 旧格式字符串

{
  "relSkills": ["dws", "clawhub"]
}

2. OpenClaw 内置 skill

{
  "skillCode": "dws",
  "skillType": "inner"
}

内置 skill 不下载，只把 skillCode 写入 agents.list[].skills。 前提是该 skill 已经存在于 OpenClaw 或全局 skill 搜索路径中。

3. ByClawHub 下载 skill

{
  "skillCode": "guizang-ppt-skill-main",
  "skillType": "hub",
  "skillUrl": "/byaiService/tool/downloadSkillZip?skillId=10026639",
  "versionUrl": "/byaiService/tool/getSkillVersion?skillId=10026639"
}

hub skill 同样把 skillCode 写入 agents.list[].skills。 额外的 skillUrl 与 versionUrl 会保存到适配后的 hubSkills 元数据中，供同步模块下载与更新本地文件。

如果 relSkills 不存在或为空，插件仍会回退读取旧的根级 skills 字段。 这保证旧数字员工 JSON 与旧配置不需要迁移即可继续运行。

整体执行流程

1 读取 Redis 数字员工

从授权列表和 DIG_EMPLOYEE_* JSON 中加载可见 agent。

2 适配 agent 配置

将 relSkills 转为 agents.list[].skills 和 hubSkills。

3 同步 hub skill

发现 ByaiService，检查版本，必要时下载并原子替换。

4 写入 OpenClaw 配置

更新托管 agent、模型、工具与 skill 过滤列表。

5 触发快照刷新

hub 文件变化时写内部 reload marker，让 OpenClaw 重建 skill 快照。

同步发生在 agent-watchdog 的全量 Redis flush 中，并且在配置变更检测完成前执行。 这样 OpenClaw 看到新的 agents.list[].skills 时，对应 hub skill 文件已经就绪。

关键模块职责

模块 职责 关键点
src/agent-adapter.ts 把百应数字员工 JSON 适配成 OpenClaw agent。 relSkills 字符串或对象都归一化为 skills； skillType=hub 的对象额外输出 hubSkills。
src/hub-skill-sync.ts 执行 hub skill 发现、鉴权、版本检查、下载和安装。 安装目录为 ${OPENCLAW_STATE_DIR}/skills/<skillCode>； 元数据写入 .baiying-hub-skill.json。
src/agent-watchdog.ts 把 hub 同步接入 Redis 全量同步流程。 当 hub 文件变化但 agent JSON 未变化时，更新 skills.entries.__baiying_enhance_reload 触发快照刷新。
src/types.ts / openclaw.plugin.json 暴露插件配置。 hubSkillAutoSync 默认开启，可显式关闭。

版本自动更新机制

安装目录与元数据

hub skill 统一安装在 OpenClaw 全局状态目录下：

${OPENCLAW_STATE_DIR}/skills/<skillCode>/
  SKILL.md
  .baiying-hub-skill.json
  ...skill files

.baiying-hub-skill.json 记录下载来源与本地版本：

{
  "skillCode": "guizang-ppt-skill-main",
  "version": "v0.1",
  "skillUrl": "http://byai-service/byaiService/tool/downloadSkillZip?skillId=10026639",
  "versionUrl": "http://byai-service/byaiService/tool/getSkillVersion?skillId=10026639",
  "downloadedAt": "2026-06-18T08:01:43.000Z"
}

更新判定

  1. 收集所有托管 agent 的 hubSkills，按 skillCode 去重。
  2. 从 Redis 服务注册表 byai_gateway:sd:instances:ByaiService 发现 ByaiService 基础地址。
  3. 将相对 versionUrl 解析为完整 URL，并发起 GET 请求。
  4. 读取返回体 data.version，如果存在 data.skillUrl，优先使用它作为下载地址。
  5. 比较本地 .baiying-hub-skill.json 的 version 与远端版本。
  6. 如果本地 metadata 缺失、本地 SKILL.md 缺失或版本不同，则下载 zip 并覆盖本地目录。
  7. 如果版本相同且 SKILL.md 存在，则跳过下载。
for each hubSkillRef:
  version = GET resolve(versionUrl)
  local = read skills/<skillCode>/.baiying-hub-skill.json

  if local.version == version.data.version and SKILL.md exists:
    skip
  else:
    zip = GET resolve(version.data.skillUrl || relSkills.skillUrl)
    validate zip entries
    extract zip
    locate one skill root containing SKILL.md
    atomically replace skills/<skillCode>
    write .baiying-hub-skill.json

鉴权来源与安全边界

请求 hub API 时只透传 allowlist 内的 header，避免把无关登录态或敏感字段扩散出去。

来源 用途 优先级说明
baiying-session.json 复用本地登录态。 作为基础鉴权来源。
环境变量覆盖 允许测试或部署环境注入 token。 覆盖本地会话中同名 header。
Redis 登录 auth hash 读取当前用户实时登录态。 可覆盖过期本地 session，避免 Beyond-Token 过期导致 hub sync 失败。

允许透传的 header 名称：

Beyond-Token
Sso-Token
Authorization
X-User-Id

下载包校验与原子替换

  • 下载前不删除本地旧版本。版本请求或下载失败时，只记录 warning，保留已有 skill。
  • 用 unzip -Z -1 枚举 zip entries，拒绝绝对路径、Windows 盘符路径和 .. 路径穿越。
  • zip 可以是根目录直接包含 SKILL.md，也可以是单个顶层 skill 目录。
  • 解压到临时目录后，先复制到 swap 目录，再 rename 替换目标目录；替换失败时回滚旧目录。
这个策略保证“版本检查总是发生，下载只在必要时发生”，同时保证下载失败不会破坏已有可用 skill。

Skill 动态加载过滤

OpenClaw 的 skill 加载过滤入口是 agent 配置里的 agents.list[].skills。 baiying-enhance 不把 hub metadata 写进 OpenClaw agent 配置，只写最终 skill 名称，避免运行时关心百应下载协议。

适配前

{
  "id": 10026037,
  "name": "杜甫的知识开发助手",
  "relSkills": [
    { "skillCode": "weread-skills", "skillType": "hub", "skillUrl": "...", "versionUrl": "..." },
    { "skillCode": "guizang-ppt-skill-main", "skillType": "hub", "skillUrl": "...", "versionUrl": "..." },
    { "skillCode": "dws", "skillType": "inner" }
  ]
}

适配后

{
  "id": "baiying-agent-10026037",
  "name": "杜甫的知识开发助手",
  "skills": ["weread-skills", "guizang-ppt-skill-main", "dws"],
  "tools": { "alsoAllow": ["baiying_call"] }
}

运行时效果是：该 agent 构建上下文时，只加载上面三个 skill。 其他全局 skill 即使存在于 ${OPENCLAW_STATE_DIR}/skills，也不会进入该 agent 的 skill 上下文。

hub 文件变化但 skills 列表不变

一个常见情况是 hub skill 的 zip 内容更新了，但 agents.list[].skills 仍然是同一个 skillCode。如果只比较 agent JSON，OpenClaw 可能不会重建 skill 快照。 因此同步模块下载新版本后，watchdog 会写入一个禁用的内部 marker： 

skills.entries.__baiying_enhance_reload = {
  "enabled": false,
  "config": {
    "reason": "hub-skill-sync",
    "managedSnapshotSignature": "..."
  }
}

这个 marker 不代表一个可用 skill，只用于改变配置快照，让 OpenClaw 感知 skill 文件已经变化， 从而刷新 skill snapshot。

workspace 上传的 skill 扫描逻辑与 hub skill 同步保持分离。 workspaceSkillAutoEnable 仍只处理工作区里的 skills/<dir>/SKILL.md， 不参与 hub 下载目录管理。

配置项

配置 默认值 说明
hubSkillAutoSync true 是否启用 hub skill 自动版本检查与下载。关闭后仍会写入 agents.list[].skills，但不会自动准备本地文件。
workspaceSkillAutoEnable true 是否把工作区上传的 skill 合并到托管 agent 的 skills 列表；与 hub 下载逻辑互不替代。 
{
  "plugins": {
    "entries": {
      "baiying-enhance": {
        "enabled": true,
        "config": {
          "hubSkillAutoSync": true,
          "workspaceSkillAutoEnable": true
        }
      }
    }
  }
}

本地运行验证

  1. 把插件目录复制到 ~/.openclaw/extensions/baiying-enhance。
  2. 确保 OpenClaw 配置加载该插件，并配置 Redis 连接环境变量。
  3. 启动 gateway 后观察日志，应该出现 hub skill sync checked=...。
  4. 检查 ~/.openclaw/skills/<skillCode>/SKILL.md 和 .baiying-hub-skill.json。
  5. 通过 byai-channel Redis Stream 入站消息测试目标 agent，确认返回内容能识别已配置 skill。

Redis Stream 验证点

控制流:

结果流:
byai_gateway:session:<sessionId>:data_stream

目标 agent:
extra_payload.agent_id = "10026037"

故障处理

现象 可能原因 处理建议
日志出现 version request failed HTTP 401 本地会话 token 过期，或 Redis 登录 auth hash 缺失。 确认 USER_CODE 能映射到用户 ID，并检查 user:<userId>:login:auth。
hub skill 未下载 relSkills 对象缺少 skillCode、skillUrl 或 versionUrl。 修正数字员工 JSON；对象字段完整后会在下次全量同步时检查。
zip 下载成功但安装失败 zip 内没有唯一 SKILL.md 根目录，或路径包含不安全 entry。 重新打包 skill，保证根目录或单个顶层目录中存在 SKILL.md。
文件已更新但 agent 仍用旧 skill OpenClaw skill snapshot 未刷新。 确认同步后写入了 __baiying_enhance_reload marker；必要时触发一次 Redis full flush。
agent 看不到某个 skill agents.list[].skills 过滤列表不包含该 skillCode。 检查数字员工 relSkills 是否包含对应 skillCode，以及适配后 OpenClaw 配置是否写入。

实现原则

  • 兼容优先：旧 relSkills: string[] 与旧 skills 行为不改变。
  • 职责分离：agent adapter 只做配置归一化；hub sync 只做文件准备；OpenClaw 只按 skills 过滤加载。
  • 失败保守：远端 version 或 download 失败时保留本地已有 skill，不从 agent 配置中删除 skillCode。
  • 最小下载：每次都请求版本，但只有版本不一致或本地缺失时才下载 zip。
  • 安全安装：下载包必须经过路径校验，安装采用临时目录和原子替换。
