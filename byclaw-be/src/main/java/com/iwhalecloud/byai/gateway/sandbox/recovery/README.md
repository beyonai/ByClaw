# 沙箱恢复任务管理

管理入口：`/manager/systemParams/sandbox` → **恢复任务**。接口位于 `/sandbox/recovery`，前端入口和每个接口仅允许账号为 `adminvip` 且明确配置 `BYAI_BRAND_VERSION=openSource` 时访问。商业版本的平台管理/运维角色不再单独授予权限；版本未知时不开放。

## 查看

- 分批 SCAN 当前网关 Redis 的沙箱控制队列，同时读取控制面唤醒、投递暂存和死信记录。集群逐节点扫描主节点。需要继续扫描时页面明确提示，不能把单批结果当全量。
- 对消费组分别展示“已领取待确认”和“未领取”，消息每批 50 条，可继续加载。读取使用 XINFO/XPENDING/XRANGE，不 XREADGROUP/XCLAIM，因此查看页面不会领取或重放任务。
- `pending` 不等于失败：在线 Worker 可能正常执行长任务。离线租约也不证明进程已死。展示用户、目标员工/组、会话/命令、内容、当前运行沙箱、在线状态、入队/最后领取时间、未确认时长和领取次数。
- 任务字段来自原消息白名单，不返回认证头、metadata 或 extra_payload。内容最多 12000 字符并隐藏常见凭证形式；管理员仍需按敏感业务数据管理内容。
- Redis 不记录容器实际停止时间，明确显示未知，不能把 PEL idle 当成停止时间或 OOM 证据。消息被裁剪时保留待确认条目，但禁用操作。
- 无消费组的投递暂存/死信属于记录，不能仅凭记录仍存在就断言尚未完成。当前版本只读展示，不自动重发这些记录。

## 操作

必须填写原因并确认，服务端再次验证消息状态。按目标沙箱加五分钟互斥锁；启动请求复用现有带锁、按目标类型路由的沙箱生命周期接口。不可从浏览器提交任意 Redis 命令、目标用户或任务内容。

1. **唤醒沙箱**：仅针对目标用户明确、Worker 离线、领取超过一分钟、未结束的共享员工任务或受支持的唤醒请求。保留原消息，不复制/重发用户请求，不假定启动后任务已完成。旧 Worker 专属队列不能由新 Worker 自动接回，不能以唤醒操作伪装成恢复。
2. **确认已唤醒**：仅对目标 Worker 已在线且超过一分钟的唤醒 pending 确认，不能确认业务任务完成。
3. **移出待确认**：仅针对 Worker 离线、用户目标明确、超过一分钟的员工 pending。单键 Lua 比较消费者、领取代次和最小 idle 后 XACK，若期间发生 reclaim 则拒绝；不 XDEL 原消息。它停止此消费组后续恢复，不是取消任务，也不会修复历史会话的 loading。确认前必须人工核对会话结果。租约离线不能保证网络分区中的旧执行进程已经停止，不能用本操作代替业务取消协议。

失败仍保留原消息。唤醒请求成功只标记 `WAKE_REQUESTED`，需人工刷新核对任务结果。自动唤醒异常也记录失败类型和消息 ID，历史错误无法从 Redis 追溯的仍需查日志。

## 操作记录与部署

操作前先写审计，记录失败则不执行。结果包含操作者、时间、原因、用户/会话、动作和结果，不保存原始认证信息。单消息最近记录保留 30 天；全局操作流保留最近约 10000 条，页面显示最近 100 条，包含自动唤醒失败记录。Redis 清空/过期后不可作为永久审计凭证；操作结果亦写入服务日志。

不新增数据库结构，不修改已有任务状态或消费组策略。查询反映 BE 当前连接的 Redis；若平台执行侧与业务 BE 配置了不同 Redis，应在连接执行侧 Redis 的管理实例使用，不能将另一 Redis 的空列表理解为系统没有积压。

后端需重新启动才能加载新接口，前端需更新构建。无需重建 Harness 镜像。

验证：`mvn -B -f byclaw-be/pom.xml verify`；前端 RecoveryPanel 交互测试；隔离 Redis 可使用 `-Dtest=SandboxRecoveryRedisTest -Drecovery.test.redis.port=<专用端口> test` 验证真实 reclaim/ACK 竞争。不要把该测试端口指向业务 Redis。

Redis 连接管理：单机模式每次命令执行后（包括异常）归还借出的 Jedis；集群模式不关闭共享客户端，节点扫描单独归还节点连接。避免刷新列表耗尽框架连接池、阻塞沙箱列表与恢复操作。

### 自动恢复历史

定时对账确认远端沙箱异常并取得记录更新权后，追加发现异常、重建成功/失败历史。DSH 共享命令队列中的待确认任务会保存脱敏摘要（每组最多 500 条），每 15 秒检查新消费者及执行状态。只有执行记录明确结束才标记结束；仅 ACK 或裁剪无法证明成功，显示结果未知。发现时间不等于停止时间，不推断 OOM。记录失败只记告警，不中断恢复。

页面默认展示最近 10 条历史，完整抽屉显示最近 100 条；沿用 Redis 历史 Stream 约 10000 条上限，不是永久审计。观察器跨 BE 加锁，每批最多 200 个追踪，超过 1 小时仍不确定的任务标记结果未知。此记录从部署后开始，不补造过去 OOM 历史；未经过定时对账的重建暂不包含此链路记录。
